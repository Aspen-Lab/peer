## Design decisions beyond the guide's exact text

- **"Logical call" granularity for keyword channels**: guide's Finding C4 table counts S2/OA
  keyword calls per TOPIC (2 for battery's 2 topics), not per adapter invocation. Adapters
  fan out internally per topic already. Runner calls `semanticScholar.fetch`/`openalex.fetch`
  ONCE PER TOPIC STRING (not batched), so each call = 1 logical call = 1 real HTTP request,
  matching the guide's count table and giving the stop-on-429 rule a clean per-call unit to
  attribute. Per-topic results merged (deduped) into one ChannelRun per input.
- **Seed resolution "both lookups must succeed"**: guide's Finding C3 text ("on either lookup
  failing... drop that one seed") read as: attempt OpenAlex-by-DOI and S2-by-DOI independently
  (2 tracked calls, matching the "2 lookups x 3 seeds = 6" budget line), each wrapped
  separately in `trackedCall` for correct per-provider 429 attribution; a pure
  `combineSeedLookups` function (no network) then requires BOTH to have succeeded for the seed
  to feed roles 5/6/7 — partial resolution drops the whole seed, reason names which side(s)
  failed.
- **`mulberry32` reuse (Finding C7 item 5 says reuse, not reimplement)**: it exists in
  `web/src/lib/evaluation/metrics.ts` but is NOT exported. Adding `export` to that one function
  is the smallest change that satisfies "reused, not reimplemented" — metrics.ts is not in
  SPEND-CAP C's lane, so this is in scope. No other change to that file.
- **nDCG skip (§1w P5)**: `blinded-sheet.ts`'s metrics wiring imports only `precisionAtK` and
  `recallInJudgedSet` from metrics.ts, never `ndcgAtK`/`perProjectBreakdown` (the latter bundles
  nDCG) — structurally guarantees nDCG is never computed, not just "unused in practice."
  Skip #1: blinded sheet has no venue/title/doi of its own —
  `WorkEntry` (channel-comparison.ts) carries only key/channels/contributions. `blinded-sheet.ts`
  takes `WorkEntry[]` plus an injected `ReadonlyMap<string, WorkDetails>` (title/year/venue/doi)
  the runner builds from the original RawItems it already has, keyed by the same id-form/title
  keys `compareChannels` itself matches on (reusing `idFormKeys`/`titleFormOf`) — so a `WorkEntry`
  representative key always has a details entry.
- **compareChannels called once PER INPUT**, not pooled across all 7 inputs — pooling would
  compare a battery-materials paper against a quantum-computing paper under the same
  "overlap"/"exclusive" numbers, which is meaningless. The blinded label sheet, by contrast,
  DOES pool works across all inputs' results (stratified sampling needs the full candidate pool).

any input id present in the resolved file. To run every input (the fresh A's job, not C's): set
`PEER_LIVE_CHANNELS_FULL_RUN=1`.
