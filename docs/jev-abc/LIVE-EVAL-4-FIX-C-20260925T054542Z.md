## Plan

**Fix 1 (`call-budget.ts`, `runner.ts`):**
- Split the old single `StopReason` (which conflated "stop everything" with
  "S2 is rate-limited") into two independent, differently-scoped states on
  `CallBudget`: `stopped` (OpenAlex 429 only — still blocks EVERY provider,
  unchanged meaning) and a new `s2Blocked` (set only after a COOL-OFF RETRY
  also 429s — blocks only further `semantic_scholar` calls; `openalex` calls
  are unaffected).
- `trackedCall` gets provider-aware retry logic: on a 429, OpenAlex behaves
  exactly as before (stop everything). S2 gets one 60s cool-off + one retry
  of the SAME call; only a 429 on that retry sets `s2Blocked`.
- New `waitForS2Slot()` on `CallBudget`, called before every S2 attempt

  until ≥3s have passed since the last S2 call this budget recorded.
- `sleep`/`now` are injected into `CallBudget` (defaults: real `setTimeout`/
  `Date.now`), so tests never actually wait 3s or 60s.
- Rewrite the ONE existing test whose contract changed (a single S2 429 used

  no-silent-deletion rule. All other existing call-budget tests are

  `RunLiveChannelsEvalOptions` (defaults preserved, so the real run is

## Fix 1 — implementation, RED then GREEN

Edited only `call-budget.ts` and `call-budget.test.ts` for the core logic;
`runner.ts` for the plumbing (new `s2RateLimited` result field, `sleep`/`now`
passthrough). Did NOT touch `web/src/lib/sources/semantic-scholar-client.ts`
(the production S2 client) anywhere.

**Design.** `CallBudget` now tracks two INDEPENDENT states instead of one
conflated `stopped`:
- `stopped` (`StopReason`, kind `"openalex-429"` only now) — an OpenAlex 429
  still blocks EVERY provider for the rest of the run, unchanged.
- `s2Blocked` (new `S2BlockReason`, kind `"s2-rate-limited"`, reason literally
  `"s2_rate_limited"`) — set ONLY when a post-cool-off S2 retry ALSO 429s.
  Blocks only further `semantic_scholar` calls; `openalex` calls are
  untouched and the run keeps going.

`trackedCall`'s new flow for a 429: OpenAlex — unchanged (`recordOpenAlexStop`,
return the failed outcome). S2 — check `blockReason` again first (covers the
edge case where the first attempt itself exhausted the ceiling — never pay a
60s wait for a retry the budget can't afford); if still allowed, sleep 60s
(`coolOffAfterS2RateLimit`), re-pace (`waitForS2Slot`, a real-time no-op right
after a 60s sleep), retry the SAME `fn` once. Retry ok → return ok (S2 stays
unblocked). Retry 429 again → `recordS2RateLimit()`, return the retry's own
failed outcome (so THIS call is honestly reported `status: "failed"` with the
real 429 message — never hidden); every S2 call attempted after it gets
`status: "not_run", reason: "s2_rate_limited"` from `blockReason` without
`fn` ever being invoked. Retry fails non-429 → returned as `"failed"`, S2 stays
unblocked (symmetric with the existing "non-429 never stops anything" rule).

Runner-side pacing (`waitForS2Slot`) is on `CallBudget` itself (not each
call site) since it's already the one shared, per-run instance every S2 call
goes through via `trackedCall` — so it applies uniformly across every
channel/seed/topic call site with no changes needed anywhere else. Tracks
only the START time of the last S2 call THIS budget issued; waits the
remainder of 3s if less has passed; no-ops before the very first S2 call.

Both `sleep` and `now` are constructor-injectable on `CallBudget` (default:
real `setTimeout`/`Date.now`), and both are threaded through as optional
fields on `runLiveChannelsEval`'s own options — production/the real run is
unaffected (defaults kick in), tests supply a "virtual clock" (`sleep(ms)`
advances the same counter `now()` reads, so pacing/cool-off math is exercised
exactly as it would be live, with zero real waiting).

**Existing-test impact.** Of the 7 original `call-budget.test.ts` tests, 6
needed NO change (ceiling ×2, non-429 ×1, network-error ×1, failed-call-counts
×1, openalex-429-stops ×1 — all still pass unmodified, verified below). Only
ONE test's contract changed — "stops the run after an S2 429..." — because a
single S2 429 no longer stops anything. Per the "never delete, rewrite and
comment" rule: rewrote that one test in place, retitled to start with
`LIVE-EVAL-4-FIX:` and state the new contract explicitly (single 429 → 60s
cool-off → retry succeeds → NOT stopped), same file position.

**New tests added** (7, all in a new `describe("CallBudget S2 429
cool-off/retry (LIVE-EVAL-4-FIX)", ...)` block), covering every item in this
item's own test list:
1. Second 429 (on the retry) → this call `failed` with the real error, every
   LATER S2 call `not_run("s2_rate_limited")`, OpenAlex completely unaffected.
2. OpenAlex 429 still blocks a LATER `semantic_scholar` call too (the
   cross-provider "whole run stops" behavior — the old test only ever
   re-called with `"openalex"`, never checked the other provider was also
   blocked).
3. S2 calls paced ≥3s apart (no wait before the first; exactly 3000ms waited
   before each subsequent one when no time has passed).
4. OpenAlex calls are never paced, even back-to-back.
5. No extra wait when ≥3s has already elapsed between two S2 calls.
6. Ceiling counts a retried call TWICE, exhausting a ceiling of 2 after ONE
   logical (429-then-ok) call.
7. Boundary case: ceiling exhausted by the first attempt itself → no cool-off
   paid, no retry attempted, `s2Blocked` stays null (a second 429 was never
   confirmed).

## Fix 2 — implementation, RED then GREEN

Edited only `blinded-sheet.ts` (added a `buildDoiUrl` helper, reused
`normalizeDoi` from `@/lib/utils/canonical-identity` — the SAME helper
`inputs.ts` in this directory already reuses for seed DOI validation, not
reimplemented) and `blinded-sheet.test.ts`. Root cause (confirmed by reading
`utils/openalex.ts` and `sources/semantic-scholar.ts`, matching A's finding
exactly): OpenAlex's adapter passes its provider's raw `doi` field (already a
full `https://doi.org/...` URL) straight into `metadata.doi` unchanged; S2's
passes a bare DOI. The row builder assumed the bare form unconditionally.

`normalizeDoi` strips any of `https://doi.org/`, `http://doi.org/`,
`https://dx.doi.org/`, `http://dx.doi.org/` case-insensitively (its own
regex has the `i` flag), lowercases, and validates the CrossRef DOI shape —
exactly the normalization this fix needs, already trusted elsewhere in this
same codebase for DOI identity (`canonicalPaperKey`) and in this same
directory (`inputs.ts`'s seed DOI parsing).

**New tests added** (5, new `describe("buildBlindedSheet doiUrl
normalization (LIVE-EVAL-4-FIX)", ...)` block, using realistic DOI shapes —
the existing fixture DOIs like `"10.1/s2-only-0"` are deliberately too short
to be valid CrossRef shapes, since they only ever needed to be unique keys,
not exercise normalization):
1. OpenAlex-shaped full-URL DOI → stripped, not double-prefixed.
2. Bare DOI (S2's own shape) → unchanged, single prefix.
3. `http://dx.doi.org/` DOI → stripped.
4. Mixed-case `HTTPS://DOI.ORG/` prefix → stripped (case-insensitive, called
   out explicitly in this item's own Fix 2 text, not just the 4-item test
   list).
5. No DOI → no link (`doiUrl` undefined).

RED (pre-fix source): `npx vitest run
src/lib/evaluation/live-channels/blinded-sheet.test.ts` → **3 failed, 12
passed** — the 3 that involve an actual prefix to strip reproduced the exact
double-prefix bug (e.g. received
`"https://doi.org/https://doi.org/10.1038/s41586-020-2649-2"`); the bare-DOI
and no-DOI cases already worked pre-fix, as expected (only the OpenAlex-shaped
inputs were ever broken).

GREEN (after implementing `blinded-sheet.ts`): same command → **15/15
passed**.

it's blocked outright (S2 already rate-limited from an earlier input),
`fanOutCalls` reports `"not_run"` with reason `"s2_rate_limited"` verbatim —
both already flow into each input's own `channelCalls` array with no changes
needed. The new top-level `s2RateLimited` field on the run summary adds the
same signal at a glance across the whole run, without having to scan every
input.
