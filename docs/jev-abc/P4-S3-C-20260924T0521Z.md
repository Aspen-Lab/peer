DESIGN CHOICES:
1. **Local-date source**: `localCalendarDate(now)` from `@/lib/opportunities/pool-cache` — the exact function `pipeline.ts` itself uses for the pool cache key. `route.ts` computes ONE `now = new Date()` per request (in both POST and GET) and passes the SAME instant both into the ledger date computation and into every `runFeedPipeline` call's `{ now }` option, so the pool cache's notion of "today" and the ledger's notion of "today" can never disagree within one request.
2. **`served_items` shape**: `DashboardBatch.servedItems?: readonly unknown[]` in the ledger — kept as an opaque, caller-typed payload. The ledger module deliberately never imports a feed-specific item shape (matching its existing "never imports canonical-identity" convention, stated in its own top-of-file comment) — `route.ts` is the only place that casts it back to `ScoredItem[]`. `prepareBatch` gained a 5th, trailing, OPTIONAL parameter (not an options object) so every existing 3-arg/4-arg call site — including in `delivery-ledger.supabase.test.ts`, which this slice never edited — keeps compiling and behaving unchanged. The Supabase insert row only carries `served_items` when a caller actually supplied one (checked via `!== undefined`, not truthiness, so an explicit empty array `[]` is still stored and distinguished from "not provided") — this is what keeps the reviewer's exact `toEqual` assertion on the pre-existing insert-row shape passing byte-for-byte.
3. **Legacy fallback**: if a served/acknowledged (or just-promoted-from-prepared) batch has no stored `servedItems` — only possible for a batch minted before this slice, since every batch `runLedgerAwareFeed` mints always stores them — `route.ts` re-derives today's ranked pool via one extra `runFeedPipeline` call with `excludeIds` AND `ledgerExclusions` both deliberately omitted (this is a REPLAY of already-decided papers, not a re-decision of membership; applying the current ledger exclusion set here would be self-defeating for an ACKNOWLEDGED batch, since its own papers are by definition already in that set), matches candidates back to the batch's stored identities by canonical key, in the batch's own frozen order, and sets `meta.batchReconstructed: true`. An identity with no match today is simply omitted — never padded. This path is not reachable by anything this slice itself produces; it exists purely for the Design-mandated legacy case, and is proven by one dedicated test that manually constructs a "legacy" batch (via a real `prepareBatch` call with the 5th argument omitted) rather than asserting it only by code reading.
4. **Race safety**: after `ledger.prepareBatch(...)` returns, the response is always built from the RETURNED batch's own stored items — never from this call's own local `result.items` directly. On a race, `prepareBatch` may hand back a different, already-existing winner (per its own documented idempotent contract), and that winner's `servedItems` already correctly reflect what should be served. Proven by a dedicated `Promise.all`-based concurrency test using a REAL `MemoryDashboardDeliveryLedger` (not two independently-scripted mocks), so the actual synchronous-body idempotency the class provides is what the test exercises, not an assumption about it.
