## PLAN (recorded before editing, unchanged from execution)

Root cause per §1p.G / `docs/jev-abc/P2-S1-A-20260924T0438Z.md`: `dedup.ts` composed many pairwise `sameCanonicalWork` checks through plain union-find, so a third bridging record with no ID-form key transitively merged two items that directly conflict. Fix: separate strong links (pass 1, logic unchanged: union on shared ID-form key) from weak links (pass 2, rebuilt: evaluated BETWEEN pass-1 clusters, not raw items). Weak-linked clusters form connected components; a component collapses to one group only if no two clusters anywhere in it conflict (share an id TYPE, e.g. both have a DOI — necessarily different *values*, since equal values would already have been unified by pass 1). Any conflict anywhere in the component blocks the whole component — every pass-1 cluster in it stays separate. Survivor tie-break becomes a total order (source priority, then more of the item's own id-form keys, then lexicographically smallest item id) so it is input-order-independent. Survivor gains `metadata.mergedAliases` (union of every member's own id-form keys/aliases) and a conditional DOI backfill (only when the cluster carries exactly one distinct DOI). New `paper-identity.ts` exports `identityForRawItem`, folding `metadata.mergedAliases` into `canonicalPaperKey`'s output; `dedup.ts` uses it instead of calling `canonicalPaperKey` inline. Hand-traced all 9 pre-existing `dedup.test.ts` cases against the new algorithm before writing any code; empirically reconfirmed after (EVIDENCE #3) — all 9 pass unchanged, so no existing assertion needed the `// P2-S1-FIX (Round 3): ...` rewrite comment. `canonical-identity.ts` needed NO edit: `mergedAliases` lives on `RawItem.metadata` (`sources/types.ts`) and is folded in by `paper-identity.ts` AFTER calling `canonicalPaperKey`, not inside it — so `CanonicalPaperInput` never changed shape.
