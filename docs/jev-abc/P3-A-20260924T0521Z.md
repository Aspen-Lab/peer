CURRENT TIER-2 BASELINE (for later paired evaluation against Jev):
- **Candidates and reasons:** `applyTier2Rerank` (`tier2-rerank.ts:60-138`) takes the top 50 Tier-1-ranked items (`items.slice(0, 50)`, L70) and asks one LLM call to return a full best-to-worst `orderedIds` for all 50 plus text `reasons` for only the top 20 (`REASON_LIMIT = 20`, L74).
- **Provider/model:** resolved by `resolveProvider(llmOverride)` (`registry.ts:97-104`): a user's own BYOK override first, else local-`next dev`-only server credentials (`canUseLocalServerProvider()` = `isLocalDevRuntime()`, never true in production/preview/Vercel), else `null`. When `null` or `generateJsonText` is unavailable, `applyTier2Rerank` returns the items unchanged (silently degrades to Tier 1) — `tier2-rerank.ts:66-68`. Model id itself comes from the provider's own `tier: "small"` mapping (`provider-models.ts`, e.g. `gemini-3.1-flash-lite`), not a Jev-style pinned decision-model version.
- **Caching:** the LLM's output (`aiOrder`, `aiReasons`) is stored as part of the whole daily `CachedPaperPool` (`pool-cache.ts:38-45`), written once at pool-build time. For signed-in users this pool lives in the owner-scoped Supabase `private_paper_pools` table (`private-paper-cache.ts:126-173`, keyed by `owner_id`+`scope_key`); for unauthenticated requests it is never durably cached (`ephemeralPaperPoolCache`, no-op `set()`). The outer cache key (`derivePoolCacheKey`, `pool-cache.ts:155-172`) embeds the calendar date, so the whole pool — including the AI rerank — rebuilds at most once per local day, but *always* rebuilds on a new day even with unchanged inputs (see F-A-P3-03).
- **Read-time replay:** every page load of a cached pool calls `applyRerankOrder` (`tier2-rerank.ts:30-58`, `pipeline.ts:394-397`), which is pure/local/free — it re-applies the stored order and reasons to freshly re-scored items with no network call. This is the one respect in which today's design already matches the *spirit* (not the letter — no decision-level identity exists) of "cache-hit page opening triggers no AI call."
- **Validation:** `orderedIds` from the model are filtered to strings present in the known item-id set (`tier2-rerank.ts:123-126`); `reasons` is used as-is with no shape/length validation. The model never returns numeric scores — the actual score used (`aiBoost = max(0, 0.12 - index*0.002)`, `tier2-rerank.ts:42`) is computed locally from array position, so there is no NaN-from-model risk today, but also no schema validator (zod/ajv) — just ad hoc field checks.
- **Fault fallback:** a single `try/catch` around the whole provider call (`tier2-rerank.ts:109-137`) catches network errors, non-2xx-shaped failures the provider throws for, and JSON-parse failures (`parseRerankResponse` returns `{}` on all-candidate parse failure, L140-158, which then fails the `Array.isArray` check) — all degrade uniformly to `{ items, orderedIds: [], reasons: {} }`, i.e. Tier-1 order. There is no differentiated handling for timeout vs. 429 vs. 5xx vs. bad JSON; it is one blanket catch.
- **Untrusted-data hygiene:** `title`/`abstract` are embedded directly into the JSON prompt (`tier2-rerank.ts:94-102`) with no `cleanDisplayText`-style sanitization (contrast `providers/types.ts`'s `buildUserPrompt`, which does sanitize for the digest path), and the system prompt (L75-82) carries no explicit "treat paper content as data, not instructions" framing.
- **Cost/usage logging:** every `generateJsonText` call, including this one, is logged by the provider adapter (e.g. `gemini.ts:264`) via `logLlmUsage` with a hardcoded generic `path: "json"` tag shared by all `generateJsonText` callers system-wide — Tier-2 rerank's own token/latency cost cannot be isolated from other JSON-generation call sites by `path` alone. Logging never includes keys or prompt/response text (`usage-log.ts:9-10`). No dollar-cost computation exists anywhere in this path.
- **Report route (`api/papers/report/route.ts`) for comparison:** already separates an abstract-only report from a full-text "deep" report via `deepReport?: boolean` (L33) / `aiMode = body.deepReport ? "tier2" : "tier1"` (L323), gated by `protectAiRequest("paper-report", 20)` (L507, 20/hour). No `CompanySpendCapability` usage — same BYOK/local-dev-only resolution as the feed path.
