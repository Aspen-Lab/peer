DESIGN CHOICES (to be finalized in code, recorded here before writing so intent is auditable):
1. rrf.ts stays decoupled from RawItem: mirrors channel-comparison.ts's established shape (candidates carry raw identity fields OR a precomputed CanonicalIdentity; resolved via canonicalPaperKey). Cross-channel grouping uses the SAME shared `clusterCanonicalWorks` (paper-identity.ts) dedupe/channel-comparison already use, not a private key-equality fold — this closes a rare edge case plain-key grouping would miss (two channels' copies of the same paper carrying different, non-overlapping id-form types) and keeps every P2-phase module agreeing on what "the same paper" means.
2. Stage 1 (fold within channel) = for each canonical-identity cluster, the MINIMUM within-channel rank across every query/occurrence from that channel. Stage 2 = sum 1/(k+rank) over each channel's folded rank for that cluster, k default 60. Deterministic tie-break = ascending sort on the cluster's own smallest id-form/title key.
3. Per-channel cap = after folding, only that channel's best-`cap` clusters (by folded rank) actually vote from that channel; <=0 or unset = no cap (neutral). Exploration slots = per channel, its N worst-still-voting clusters (worst folded rank first, channel input order) are relocated to the FRONT of the returned order, guaranteeing survival through any downstream top-K cut; 0 = neutral (pure fused-score order). Both parameters are wired into pipeline.ts with their neutral defaults only in this slice, per RULING point 4 ("no cap, 0 slots... no source gives numbers") — pipeline.ts never sets a non-default value.
