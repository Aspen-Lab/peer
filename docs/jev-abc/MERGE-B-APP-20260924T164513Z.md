## PRODUCT TRADE-OFFS

1. **Does "nothing set up yet" show main's sample/starter feed, or Jev's "set your Research focus" prompt?**

   Plain-language: main just shipped a feature where a brand-new visitor with nothing set up sees a *real sample of today's papers* with a small setup strip on top, instead of an empty page pushing them to a form. Jev separately built a rule that says: if there's truly nothing to build a briefing from (no project, no challenge, no topics, nothing at all), show a plain "set your Research focus" message instead of guessing.

   Right now these two rules would partly overlap in a confusing way. Main's "should I show the sample?" check only looks at one old-style field (research topics). Jev's check looks at the whole, newer picture (topics AND project AND challenge). So someone who typed in a project but left topics blank would currently get main's sample-feed treatment even though Jev's system already knows exactly what to build for them — they'd see a generic sample instead of their own project-driven briefing.

   Recommended default (already reflected in this guide's exact instructions for item 8): keep both messages, but make main's "should I show the sample?" question ask Jev's broader question instead of the narrow one — show the sample only when Jev's system also says nothing usable is set (i.e. gate `isStarterFeed` on `intentRequired`/`!feedAutoLoadKey` rather than on `researchTopics.length === 0` alone). This needs a one-line sign-off from the user/manager because it changes exactly when a first-time visitor sees the sample feed versus their own briefing, and it touches a file (`starter-topics.ts`) outside this guide's 12-file scope. If the user prefers main's narrower behavior unchanged, the fallback is to leave `isStarterFeed` as-is and accept that a project-only, no-topics visitor sees the sample feed on their first visit even though Jev's intent system already has enough to build their real briefing.
