## DESIGN CHOICES

1. **Reused `sources/search-failure.ts`'s `searchHttpFailure(provider, res)`** for the non-2xx path in all 5 adapters rather than inventing a parallel helper — already the repo-wide convention for this exact problem (used by `web-search.ts`, and via it by `events/sources/eventweb.ts` and `jobs/sources/jobweb.ts`). Its message format is provider-name-agnostic and accurate for an academic API.
2. **Did NOT reuse `search-failure.ts`'s `WebSearchProviderError`/`collectSearchResults`.** `WebSearchProviderError`'s message is hardcoded `"${provider} web search failed for every query: ..."` — accurate for Tavily/Brave/Gemini-grounding, misleading for OpenAlex/S2/arXiv/DBLP/PubMed (not web search). `search-failure.ts` is outside this slice's allowed files, so it could not be generalized. Each adapter's `fetchImpl` instead inlines the identical "all failed → rethrow the first reason, else keep whatever fulfilled" rule (4 lines, no timing/pacing — not a second limiter) with accurate wording. `pipeline.ts`'s pre-existing `errors[sourceId] = String(result.reason)` needs no specific error class to work correctly, so no shared class was required.
3. **`semantic-scholar-client.ts` and `affiliation/openalex.ts` left untouched** — see prior checkpoint note preserved below; reasoning unchanged.
4. **`getOrBuildCachedPool` gained an optional `shouldPersist` parameter (Option A) rather than a cache-wrapping closure (Option B, considered and rejected).** A wrapper `PoolCache` that no-ops `.set()` for a fully-failed pool would ALSO have worked without touching the shared function's signature at all, but it introduces an object-identity subtlety: `getOrBuildCachedPool`'s own in-process single-flight coalescing (`inFlightByCache`, a `WeakMap<PoolCache, ...>`) is keyed by the exact `cache` reference passed in, and `ephemeralPaperPoolCache` is a module-level singleton whose IDENTITY matters for that coalescing across concurrent anonymous requests. A wrapper would have needed its own `WeakMap<PoolCache, PoolCache>` memoization to preserve that identity correctly — a real but non-obvious correctness trap for a fresh reviewer to have to re-verify. The optional-parameter approach has no such trap: omitted, `getOrBuildCachedPool` is provably byte-identical to before (one added `if`, unconditionally true when the parameter is absent), which is what makes it safe to touch a function shared with events/jobs at all.
5. **Deliberately did NOT bump `PAPER_CACHE_KEY_VERSION` (currently 6).** `sourceStatus` is a new OPTIONAL field — absent on every pre-existing cached row, treated as unknown/assume-ok by every reader (build always sets it fresh; retry only reads it when present; `errorsFromSourceStatus`/`everySourceFailed` both treat `undefined` as "no information," never as "failed"). A version bump is unnecessary for a purely additive optional field, and more importantly `private-paper-cache.ts`'s `PrivatePaperPoolCache.get`/`.set` gate on the LITERAL string prefix `"peer-pool-v6-papers-"` — bumping the version would silently make every private-scope read/write a no-op until that prefix check were also updated, and `private-paper-cache.ts` is explicitly READ-ONLY for this slice. Recorded here as the rationale requested by the task brief's "decide and record."
6. **Retry scoped to the five academic paper sources only ("web"/"hn" excluded from auto-retry).** `"web"` carries its own connector-resolution (`webSearchOptions`) and per-source timeout override (`needsVertexSourceTimeout`/`GEMINI_SOURCE_TIMEOUT_MS`) wiring in `buildPaperPool`; replicating that safely inside `retryFailedSources` risked exactly the "second limiter" the STOP conditions warn against. `"web"`/`"hn"` still get honest `sourceStatus`/`meta.errors` from a build if they are ever included and fail — they are just never auto-retried by this slice. Recorded rather than guessed, per the STOP-condition instruction.
7. **Retry bookkeeping shape:** `SourceStatusEntry = { status: "ok"|"empty"|"failed"; lastAttemptAt: string; retryCount: number; lastErrorMessage?: string }`, one entry per attempted `SourceId`, stored inside `CachedPaperPool.sourceStatus`. `lastAttemptAt` covers BOTH the original build and any retry (one timestamp, not two), so `isEligibleForRetry`'s "30 minutes since last attempt" reads from a single field. `retryCount` starts at 0 on the build (not itself a retry) and is capped at 3 by the same eligibility check — daily reset is automatic because `derivePoolCacheKey` already folds the local date into the cache key, so a new day is unconditionally a new pool. `lastErrorMessage` exists so a cache-hit response's `meta.errors` can show the SAME real cause a build response would, not just the word "failed".
8. **Retry runs synchronously, in-request, on a degraded cache hit — not fire-and-forget.** The task's own Design section describes "re-fetch only that source... merge... write back" without mandating background execution, this codebase's API routes have no evidenced reliable post-response background-work primitive, and the existing test harness (`await runFeedPipeline(...)` then inspect) only exercises a synchronous contract. The added latency is bounded (one source's existing 8s timeout, at most once per 30 minutes per source, at most 3 times/day) — a rare, capped cost, not a retry storm.
9. **Retry re-scores the WHOLE merged candidate set (old + new) via the SAME neutral (`includePreferenceLedger: false`) `scorePaperCandidates` a build uses, rather than hand-preserving old items' existing score fields and only scoring the delta.** `ScoredItem extends RawItem`, so a merge-then-full-rescore is simple and can never leave a stored pool with a mix of old-scored and new-unscored objects (which type-checking alone would not have caught, since `ScoredItem`'s extra fields are structurally optional-looking from a `RawItem`'s perspective when spread). The extra recompute cost is pure local computation — the same cost class read time ALREADY pays on every cache hit, degraded or not.
10. **`meta.fetched`/`beforeDedup`/`afterDedup` were deliberately left alone on a cache-hit response** (still `{}` / pool-size fallbacks) — only `errors` was made truthful. The pre-existing code comment ("A cache hit reports the pool's size rather than inventing source counts it never saw — the same choice `buildDailyJobPool` makes") documents that choice as intentional for `fetched`, and neither the binding ruling nor the guide's finding asks for `fetched` to change — only `meta.errors`. Narrower diff, no unrequested behavior change.
