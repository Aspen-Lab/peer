Ruling (ABC-JEV-INTEGRATION.md §4, 2026-09-24T15:40:42Z entry): fix now.
Tri-state `get()` (hit / miss / unavailable). Resolver skips all live legs
on unavailable with the existing distinct error text
(`"<leg>: channel candidate cache unavailable"`, Policy 8: distinct from a
real adapter failure). Day-pool cache's identical swallow-to-null behaviour
(`private-paper-cache.ts`, `pool-cache.ts`) is pre-existing and OUT OF SCOPE
— record only, never touch.

## PLAN

1. `channel-candidate-cache.ts`: change `ChannelCandidateCache.get()` return
   type from `Promise<CachedChannelCandidates | null>` to a tri-state
   `Promise<ChannelCacheGetResult>` = `{status:"hit", value} | {status:"miss"} | {status:"unavailable"}`.
   - `MemoryChannelCandidateCache.get`: hit/miss only (never unavailable —
     no I/O to fail).
   - `PrivateChannelCandidateCache.get`: classify —
     - owner/key-prefix guard mismatch (call not meant for this instance) → MISS (routing guard, not a storage failure).
     - no configured Supabase client on an otherwise-valid call → UNAVAILABLE (per task spec: "an unconfigured cache for a trusted scope should be unavailable, never a silent live path").
     - Supabase `error` field set → UNAVAILABLE.
     - thrown/rejected exception → UNAVAILABLE.
     - no row found (`data` null/undefined, no error) → MISS.
     - row found but payload fails `isValidPayload` → MISS (self-healing: a
       shape problem, not a storage-read failure; treating it as unavailable
       could wedge a channel closed forever behind one bad row).
   - `set()` unchanged (stays fail-soft void).
2. `pipeline.ts` (`resolveChannelCandidates` only): consume the tri-state —
   `unavailable` (or a `get()` that still throws, kept as belt-and-suspenders)
   → skip every enabled leg, synthetic per-leg error, zero live calls;
   `miss` → existing fetch-live-and-persist path; `hit` → existing
   cached/retry path. No other function in this file touched.
3. Tests, RED first:
   - `channel-candidate-cache.test.ts`: rewrite assertions for the
     unconfigured-client and query-error/exception cases to the new
     `{status:"unavailable"}` contract (P2-S4d-FIX comment, tests kept, not
     deleted); add a Supabase-error-object case and a corrupt-payload case;
     confirm prefix/owner guards still resolve `{status:"miss"}`.
   - `channels.test.ts`: keep the existing spy-reject test (still exercises
     the defensive catch of a hypothetically-throwing implementation); add a
     NEW test driving a REAL `PrivateChannelCandidateCache` through a fake
     Supabase client that returns an error object (not a JS throw) via
     `runFeedPipeline`, proving zero adapter calls + the distinct
     "cache unavailable" text (never the adapter's own HTTP-failure text).
     Confirm a genuine miss still fetches once and a hit still makes zero
     calls (existing tests already cover this through the tri-state; rerun
     to confirm still green).

   must fail; restore → pass.
