### Why the digit sticks (the mechanism, confirmed by execution)

`canonicalize()` turns punctuation into spaces but leaves `NMC811` as one unbroken word (letters and digits both count as "word characters" — `\p{L}\p{N}\p{M}`). `termMatches`'s word-boundary check (`(?<!wordchar)nmc(?!wordchar)`) then refuses to match "nmc" against the *start* of a longer word like "nmc811" — the character right after "nmc" is "8", a word character, so the boundary fails, by construction, on purpose (this is the same rule that correctly keeps "cat" from matching inside "category"). T4 (the similarity fallback) does not rescue this either: `tokenize()` (used for T4's TF-IDF) has the identical letters-and-digits-together rule, so the document token is `nmc811`, never `nmc` — there is no shared word for the cosine to score, so T4's `simTopic` is 0 for a document whose *only* occurrence of the family name is glued to digits. Executed directly: `scoreItems([item], {topics:["NMC"], seedTexts:[PROJECT_TEXT]})` on a title-only "NMC811 cathode degradation study" item returns an **empty pool** (0 items) — confirmed, not assumed.

### What this means for Q2

Two separate, independently-confirmed gaps sit underneath the hyponym question the brief asks about:
1. **The hyponym gap** (the brief's subject): "NMC" has no member forms at all, so it can never match a paper that only ever writes a specific stoichiometry with a separator (`NMC 811`, `NMC-811`) — wait, it CAN today, via plain T1, because "NMC 811" already contains the bare word "nmc". The real hyponym gap is narrower than it first looks: **today's "NMC" tag already matches every SEPARATED spelling of every stoichiometry**, because a separated spelling always contains the bare family word "nmc" as its own token. The gap is only the **no-separator** spellings (`NMC811`, `NCM622`, …) — very common in real papers (measured in Q3b).
2. **The family-alias gap** (adjacent, same root cause, same fix shape): "NCM" is simply not linked to "NMC" at all, at any stoichiometry, separated or not. This is not a hyponym problem — it is the same synonym relationship LCO-FORMULA already shipped for LCO/LFP (two spellings of one name), just never added for NMC's own bare acronym.

Both are folded into the Q2 design below, since a member-shape pattern has to close the no-separator gap for both "nmc" and "ncm" to be worth shipping.

## Q2 — design

### Family set — evidence, not guesses

**NMC and NCM belong together; nothing else does.**

- NMC and NCM name the *same* compound class (LiNixMnyCozO2, x+y+z=1) with the metals in a different letter order — not a hyponym relationship, a plain synonym, the same shape LCO-FORMULA already shipped for `LiCoO2`/`LCO`. Evidence, executed: Q3's own fresh OpenAlex sample caught a paper writing `LiNi0.6Co0.2Mn0.2O2 (NCM622)` — the identical formula LCO-FORMULA-B and this item's own background text both call "NMC622" — literally in the same sentence as "LCO" (`openalex:W7213392907`). 90 sampled real papers (Q3b) split almost evenly between NMC-prefixed and NCM-prefixed spellings for the *same* stoichiometries.
- **NCA does not belong.** `ABBREVIATION_GROUPS` has no "nca" entry at all today (confirmed by reading `term-expand.ts` in full). NCA substitutes *aluminum* for manganese (LiNiCoAlO2) — a chemically distinct sibling family, not a spelling variant of NMC/NCM. One of Q3b's own sampled titles lists them as separate things side by side: *"Chemical versus Electrochemical Electrolyte Oxidation on NMC111, NMC622, NMC811, **LNMO**, and Conductive Carbon"* — the field itself treats a different cathode family (there, the spinel LNMO) as a peer, not a member. The brief's own background text never names NCA either. Recommendation: leave it out; a separate, smaller follow-up if real recall evidence for NCA-specific stoichiometries ever surfaces (this item measured none).
- LNMO (`LiNi0.5Mn1.5O4`, a spinel, not a layered oxide) — same reasoning, excluded, evidence above.

### Member SHAPE — a pattern, not a list

Q1 already found the real boundary by execution: a **separated** stoichiometry spelling (`NMC 811`, `NMC-811`, `NMC(811)`) already matches a bare "NMC" tag *today*, because `canonicalize()` turns the separator into a space and the bare word "nmc" ends up standing alone — plain T1 already has it. The only real gap is the **glued** spelling (`NMC811`, no separator), which is also the *more common* real-world spelling (Q3b: glued forms dominate every sampled term). So the new mechanism only has to add one shape:

```
family prefix ("nmc" | "ncm") immediately followed by 3–4 digits, no separator
```

— tested with the same manually-anchored word-boundary style `termVariantMatches` already uses (`(?<![\p{L}\p{N}\p{M}])(nmc|ncm)\d{3,4}(?![\p{L}\p{N}\p{M}])` against the already-canonicalized haystack), so "category" -style false containment stays impossible by the same construction as every existing check. Measured 3-digit forms only (811/622/532/111 — the brief's own named examples, and everything Q3b's live sample returned); 4-digit is included because the brief specifies it as a closed superset, not because this investigation found positive 4-digit evidence — flagged in POLICY, not asserted as measured.

This is a **new, small, additional check — not a change to `ABBREVIATION_GROUPS`/`expandTerm`.** It must NOT live in the symmetric mechanism: `expandTerm` is a bidirectional closure by construction (every member of a group expands to every other member, unconditionally), so *any* shape rule added there would either have to be symmetric too (recreating exactly the widening the brief prohibits) or would need deep structural surgery to `expandTerm` itself. It belongs as a new, small function alongside T2/T3 in `keyword.ts` — call it `matchesFamilyMember` in this guide (not claiming a `T5` name; REQUIRED-GATE's own B guide already reserved that letter for a different, unshipped idea, §1ao.4) — gated behind the *same* `opts.extendedRequiredMatch` flag T2/T3 already use, so it only ever runs for the Required-gate's literal-topics call in `combine.ts`, never softTopics/events/jobs (identical scoping reasoning as T2/T3's own doc comments).

**Structural, by-construction proof of the one-way property** (not just tested, *provable from where the check lives*): `matchesFamilyMember` only ever fires when the *Required tag itself* canonicalizes to a bare family form (`"nmc"`/`"ncm"`, or any of the family group's own aliases, e.g. the long name) — it is a function of `(haystack, tag)` called from the tag's own admission path, never invoked in reverse. A member tag like `"NMC811"` never reaches this function as its own topic string, and `expandTerm("nmc811")` is completely untouched by it (still just itself + the spurious plural, unless the sibling rule below is also added — see next). So a member tag structurally cannot ever reach the bare family form through this mechanism, regardless of what any paper says. Confirmed empirically too (Q1, Q3d): tag `"NMC811"` does not match a paper that says only `"NMC"` — today, and unchanged by this design since neither new piece touches that direction.

**Cross-member independence** (not explicitly asked, but load-bearing and cheap to state): tag `"NMC811"` must never match a paper that only says `"NMC622"` — a reader tagging the Ni-rich 811 chemistry specifically does not want the 622 composition. Holds structurally today (`expandTerm("nmc811")` has never contained `"nmc622"`) and is untouched by every piece of this design — worth a named test (Q4) precisely because it is easy to get wrong if a future edit tries to be "clever" about stoichiometry proximity.

### Member self-synonymy (NMC811 ↔ NCM811 ↔ the formula)

**Yes for the prefix swap, symmetric — it is the same compound, not a family relationship.** A reader who types `"NMC811"` should also match a paper that only ever writes `"NCM811"` — Q1 measured this does **not** happen today (0/6 checked). This is safe to make symmetric, *and* still closed-shape rather than an open list: a small, derived rule inside `expandTerm` — "if the canonical term matches `/^nmc(\d{3,4})$/`, also queue `ncm$1`; if it matches `/^ncm(\d{3,4})$/`, also queue `nmc$1`" — swaps only the 3-letter prefix at the *same* digit suffix. It can never produce the bare family form (no digits means the pattern doesn't match at all), so it cannot reopen the widening the brief prohibits; it is additive to `expandTerm`'s existing queue-based closure algorithm (`term-expand.ts` lines ~232-251), not a rewrite of it.

**The formula (`LiNi0.8Mn0.1Co0.1O2`) — not recommended now, POLICY item.** Unlike LCO-FORMULA's single-compound formulas, a stoichiometry-suffixed formula needs the digits *parsed* into a fractional composition and matched against several plausible decimal notations — real, but materially more work, and Q3a/Q3b found **zero** real papers where the formula was the *only* spelling present (every real sample that used a fractional formula also used the family or member acronym somewhere in the same title/abstract — the identical finding LCO-FORMULA-B already made for NMC's generic formula, §3: "papers using it overwhelmingly already say NMC too"). A small, curated map for exactly the 4 brief-named stoichiometries (mirroring LCO-FORMULA's own curated-formula approach) is possible later if wanted; not proposed as part of this item's core deliverable.

### Where each piece lives

| Piece | Lives in | Shape |
|---|---|---|
| "ncm" as a synonym of "nmc" (bare acronym) | `term-expand.ts`, `ABBREVIATION_GROUPS`'s existing "nmc" entry | One literal string appended: `["nmc", "ncm", "nickel manganese cobalt oxide"]` — zero new mechanism, existing symmetric machinery, safe because it's a true synonym |
| Family → member glued-digit check | `keyword.ts`, a new function parallel to T2/T3, gated behind `extendedRequiredMatch` | Pattern match, one-way by construction (see above) |
| Member self-synonymy (NMC811↔NCM811) | `term-expand.ts`, inside `expandTerm` | Derived rule on the SAME digit suffix, symmetric-but-scoped |
| SENSE-CONTEXT skip for a glued-member match | `keyword.ts`, extending (or reusing, parameterized) `matchesFullNameOrFormula`'s skip precedent | See next section |

### Should a family→member match skip SENSE-CONTEXT?

**Recommend yes**, the same exemption LCO's own `matchesFullNameOrFormula` already gets for a full-name/formula match (§1bg point 3): a stoichiometry-suffixed acronym (`NMC811`) is *more* specific, unambiguous evidence than the bare family word, not less — exactly the reasoning that already exempts a full spelled-out name. Measured support: **zero** of the 140 real papers sampled in Q3 (90 in Q3b + 50 in Q3c's raw "NMC"/"NCM" searches) produced a digit-glued collision in any non-battery sense found (meteorology, nursing, "New Media Consortium," Chinese health insurance, or the one crystallographic space-group collision) — every real collision found was the *bare* acronym only, which is exactly the shape SENSE-CONTEXT already exists to catch and which this design leaves completely alone. The bare-acronym path (T1 literal "nmc"/"ncm" as a standalone word) keeps going through SENSE-CONTEXT exactly as today, unchanged — confirmed by execution in Q3c (a constructed real-shaped nursing-council paragraph containing bare "NMC" is demoted 0.25×, not dropped, against a real battery-researcher's declared context; the same holds for the found crystallography "P42/ncm" collision).

### Card sentence when a member matches a family tag

**Unchanged.** `reason.ts`'s `generateReason` always renders `matched` — the *reader's own tag string* — never the paper's matched spelling (confirmed by reading the file: `matched.push(topic)` in `keyword.ts` pushes the canonical tag, not the variant that matched). A reader with Required tag "NMC" whose feed admits a paper that only says "NMC811" sees exactly the same sentence every other admission produces: **"Matches your interest in NMC."** — true (the paper genuinely is about NMC), and identical in shape to every T2/T3/T4 admission already shipped (LCO-FORMULA verified this same non-effect for its own formula fix). A friendlier sentence naming the specific member ("...in NMC, as NMC811") is a real, separate UX nicety — flagged in POLICY, not required for this item, since `matched`'s shape is a product-wide convention touching every tag, not something to special-case for one family here.

### A parallel, out-of-scope residual (noted, not fixed)

`termSpecificity("NMC811")` computes **0.5** today (not in `KNOWN_SHORT_FORMS`, and 6 characters is below the `>= 8` long-token threshold) — the *same* low-specificity bucket as an ordinary vague word, despite "NMC811" being about as specific as a Required tag can get. This is the identical asymmetry LCO-FORMULA-B already flagged and declined to fix for a reader who types a formula as their own tag (its POLICY 5) — noted here for the same reason (so it isn't later "discovered" as unexplained), not proposed as in-scope work.
