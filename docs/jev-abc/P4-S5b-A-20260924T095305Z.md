NEW FINDINGS (re-delivery and privacy first):
1. **[RE-DELIVERY RISK, FAIL] Judgement (a): the savedIds carve-out is applied to the whole excludeIds union, letting a delivered-then-saved paper re-enter the candidate pool.** This contradicts ABC-JEV-INTEGRATION.md's own compound acceptance-16 wording (line 296: "No delivered item re-enters future batches" is listed as a separate, unconditional clause from "saved history preserved") and disagrees with the server-side permanent ledger (`delivery-ledger.ts`/`pipeline.ts`'s `ledgerExclusions`), which has no saved-id exception at all. **Minimal fix direction:** stop filtering `deliveredBeforeTodayIds` by `savedIds`; keep the existing carve-out (whatever its own merits) scoped to `dismissedPaperIds`/`recentlyShownAndDisplayed` only, e.g.:
   ```
   const paperExcludeIds = Array.from(new Set([
     ...dismissedPaperIds.filter((id) => !savedIds.has(id)),
     ...deliveredBeforeTodayIds,                              // no savedIds carve-out — mirrors the ledger
     ...recentlyShownAndDisplayed.filter((id) => !savedIds.has(id)),
   ])).slice(0, DELIVERED_EXCLUDE_SEND_CAP);
   ```
   (Exact placement of the two `.filter()`s vs. one final filter is an implementation detail; the essential fix is that `deliveredBeforeTodayIds` must survive the savedIds carve-out unconditionally.) This is a small, localized change with a direct, already-partially-written regression test shape available (the existing "orders excludeIds..." test already exercises a mixed dismissed/delivered/recently-shown case and just needs a saved-and-delivered id added to it).
2. **[PRIVACY / CORRECTNESS, FAIL] Judgement (b): `deliveredLocal` is one unnamespaced, account-agnostic map that survives sign-out, so a shared device leaks and misapplies delivery history across accounts.** On a shared browser: User A (any auth state) builds up `deliveredLocal`; signs out; User B (a different signed-in account, or anonymous) loads the feed; `loadFeed` reads the SAME `deliveredLocal` unconditionally and sends User A's delivered ids as User B's `excludeIds` — User B is wrongly denied papers they have never seen, and User A's reading/delivery history is functionally exposed to and used on behalf of a different identity with no consent boundary at the account-switch point. **Minimal fix direction:** scope `deliveredLocal` (and its persistence) per owner — e.g. key the stored map/localStorage entry by `"anonymous"` or the signed-in user's id, so switching accounts on one device naturally lands in a different bucket instead of requiring a clear-on-transition step. (Clearing on sign-out alone is insufficient — it defeats the memory's whole purpose for a person who signs out/in repeatedly on their own device, which C's own checkpoint already argues against; clearing on sign-in alone still lets an anonymous-then-signed-in same-person transition leak into a later DIFFERENT account. Per-owner namespacing is the one fix that avoids both failure modes without sacrificing the intended benefit for a single returning user.) This is a larger change than (a) — it touches the persisted shape, not just one filter — so it is reasonable to scope as its own follow-up slice item rather than a one-line fix.
