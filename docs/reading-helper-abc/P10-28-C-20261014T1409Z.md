- **Rule 3.** `StructureStep` / `StructureLog` with `newStructureLog`, `recordStructure`, `stepStructure` (exported, pure): a split (Enter) or a join (Backspace, Delete) is one step holding the run of blocks before and after, whole (text, type, anchor, checked, indent), and where the caret goes on undo and redo. `stepStructure` returns null when there is no step, when the blocks are no longer as the step left them (typed in since), or when the caret is in none of them. Ctrl/⌘ Z steps the block's own history first (`stepHistory` now returns whether it stepped) and, when that is spent, `stepBlocks` undoes the last split or join; Ctrl/⌘ Y and Shift Z redo; a new step drops what was ahead. Enter at the very start of a block (an empty block inserted above) is not logged.

`web/src/lib/notes/inline.ts`, `wysiwyg.ts`
- **Rule 4.** The dialect has one escape now: a backslash before `*`, `_` or `=` is that character (a text token whose `text` is one character and `[from, to)` two, flagged `esc`). The mark expressions count an escape as one unit of content (so `**a\*b**` is bold "a*b"); `\\*` is a backslash and a star (a backslash that escapes nothing is unchanged: `a\b`, `\n`, a trailing `\`). `serializeTree` writes a `*` inside bold or star italic, an `_` inside underline or underscore italic, an `=` inside highlight escaped; a character after a literal backslash is escaped too (`\*` typed as two characters must not read as an escape); a character that was escaped when read stays escaped through splitting, joining and splicing (`esc` nodes are never merged into text). `sourceOfPlain` / `plainOfSourceOffset` treat an escape as an atom (the caret is never between the two characters). Where a mark could not hold its words (a star in bold, `__` in underline, `=` in highlight) it was **dropped**, so the words lost their mark; now it is kept and the character shows. Italic keeps its old preference (a star where the dialect can read it, else an underscore) and escapes only when both spellings meet their own character. Markdown (`.md`) keeps `\*` (Markdown reads it as the character), `.txt` / Copy / `.doc` / the read view show the character.

## Unsettled / for the manager

- A literal star, underscore or equals **outside** any mark that is stored escaped (`a \*b\* c`, from another tool) is kept escaped through every tree-level edit (split, join, splice, a mark laid over it) but the editing surface cannot tell an escaped character from a typed one (a text node has no flag): the next keystroke in that block reads the characters as typed, so a pair such as `\*b\*` becomes italic. Characters typed outside a mark were always read that way; text stored with `\*` did not exist before this change. A `<span data-esc>` in the surface would close it.
- A literal backslash at the very end of a text followed directly by a mark that opens with `*`, `_` or `=` (`a\` then bold) is written `a\**b**`, which reads `\*` as an escape; the serializer cannot escape a backslash (the dialect has no `\\`). The surface then redraws from the source.
- In the read view (`inline-text.tsx`, not mine) a mark whose whole content is one escape (`**\***`) is drawn from the raw text (`\*`): its `kids` shortcut takes a one-token content as text. Rare; a one-line follow-up there.
- Legacy sources that held a single `_` in underline (`__snake_case__`) are rewritten `__snake\_case__` the first time that block is edited (same words; the brief asked for the escape inside underline). A source that is only read is not rewritten.
- The toolbar's hold is set on the DOM from the editor (see above); `NoteToolbarView` taking a `typesHeld` prop is the clean version.
- Rule 3 does not log Enter at a block's very start (an empty block above) or a join by `Backspace` that merely deletes an empty block after a non-text block.
