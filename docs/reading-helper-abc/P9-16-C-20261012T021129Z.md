2. **The entity table stays as it was (it could not be made clean).** The brief allowed `minus` → `−` only if the default output stayed unchanged. It does not: the entity decodes *before* `normalizeLatex`, which strips an `_`/`^` group that begins with a hyphen-minus, so with `minus: "−"` the default turned `x_&minus;1` from `x-1` into `x_−1` and `y^&minus;2` from `y(-2)` into `y^−2` (probed on the first commit, base against it). The PDF text layer does not carry HTML entities, so the paper path loses nothing.
3. **The opt-in is a second export, `cleanPaperText(text)`, not an option of the first.** `cleanDisplayText` is passed point-free to `.map` at 10 call sites in the sources (`.map(cleanDisplayText)`), where a second parameter would receive the array index (an options object there would be handed a number). `cleanPaperText` is the same pipeline (`cleanText(text, keepDashes)`) with the dash step narrowed: U+2010 and U+2011 → `-`, U+2012 → `–`, U+2015 → `—`; **U+2212 `−`, U+2013 `–` and U+2014 `—` stay**. Anything else the pipeline does is the same for both.
4. **The paper's display path is `papers/pdf-text.ts` `normalize()`**, all seven calls: the sections' heading and text, the captions' label and caption, the equations, the title (import switched too). No other caller on the body's display path re-cleans with the default: `reading-map.ts`, `reading.ts`, `upload-concepts.ts` do not call the cleaner (`Grep` for `cleanDisplayText|text/clean` over `src`, non-test: 23 files, none of them those three; the e2e below confirms no other caller changes the body). **Left on the default, as ruled:** `evidence.ts` (the matcher folds anyway, and `normalizeForMatch` goes through the default), `plain.ts`, `report.ts`, `explain.ts`, `paragraph-guide.ts`, `html-text.ts`, `enrich.ts`, and every feed / source caller.
