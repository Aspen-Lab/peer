## The rules as built

1. **The selection buttons (B3).** `web/src/components/reader/selection-toolbar.tsx`: `SelectionToolbar({ target, onExplain, onTakeNote })`. One pill, fixed, label face, two buttons `Explain this` and `Take notes`, `bounds.top − height − 6` above the selection's first line, left-aligned with `bounds.left`, clamped into the window (8 px) and clear of the masthead; where the masthead leaves no room above it stands 6 px under the selection's last line instead (never over the words); measured again on scroll and resize through `target.measure()`; not drawn under 768 px (`toolbarPlace` returns null); null for a selection scrolled out of view; `mousedown` is prevented so the selection stays. Mounted by `page.tsx` next to the box (`<SelectionToolbar target={explainTarget} onExplain={openExplain} onTakeNote={takeNote} />`). "Take notes" on a phone is deferred (the thumb bar's cell stays the explain control, §1h.66). The "no drag" clause is moot: no window of this toolbar's is dragged this round.
2. **A sticky (B7).** `sticky-note.tsx`: `takeStickyNote` (what "Take notes" does: `ensureReadingNote` → `addSticky` → `useWindows.open`), `useTakeNote` (the page's `takeNote`), `StickyNotes` (renders the open stickies), `StickyWindowView` (stateless view). Fixed at the right edge in the dock's column, 360 px (`min(360px,100vw)`), header `Note N` + the passage's first words in curly quotes (`quoteHead`, ≤ 80 characters, ellipsis when cut, italic reading face) + a Close (×); body = a text area with `autoFocus` (and a blue square to its left). Escape on the focused sticky closes it; closing flushes and hides, the note keeps everything. Column top: `[data-explain-dock]`'s bottom + 8 when an explain window stands, else `DOCK_TOP_PX` (48); unreadable → `DOCK_TOP_PX + 400` (`columnTop`). Re-read every 250 ms, on scroll and on resize.
3. **Numbers (B10).** `Note.stickyCount`; `addSticky` gives `max(stickyCount, highest anchor n) + 1`; the number is in the header block's text and `anchor.n` and never changes; clearing a sticky's text leaves the header (and one empty text block).
4. **Data model (ruling §1h.78 (f)).** `types.ts`: `NoteAnchor { paperId, paragraphId, quote ≤ 300, n }`, `Block.anchor?`, `Note.stickyCount?`. `store/notes.ts`: `ensureReadingNote(paper: Citable, extras?: ReadingNoteExtras): string` (the paper's note from the existing template, no navigation, same id afterwards), `addSticky(noteId, { paperId, paragraphId, passage })` → `{ id, n } | null` (appends one `h3` "Note N" carrying `anchor`, then one empty `text` block, at the end of the note), `setStickyText(noteId, headerId, text)` (rewrites that sticky's own blocks: one `text` block per non-empty line, existing block ids reused by position; nothing else touched). A sticky owns its `h3` and the `text` blocks right after it, up to the next block of another kind (`stickySpan` in `lib/notes/blocks.ts`). Typing writes through, debounced 250 ms (`makeStickyWriter`), flushed on close, on going behind and on unmount. The quote lives only in `anchor`: `export.ts` is unchanged and the test `export.anchor.test.ts` proves `toMarkdown` carries `### Note 1` and the reader's words and not the quote (nor the paragraph id).
5. **The anchor (B11).** `note-tags.tsx`: `NoteTag` (superscript `[N]`, `font-mono`, `select-none`, `aria-label="Open note N"`, opens that sticky), `AnchorSquare` (a 14 px blue `#3b82f6` button, `aria-label="Go to the passage"`), `goToPassage` (scrolls the paragraph to the top of the window, marks it `bg-accent-dim` + outline for 1.5 s; on the reading page it goes through the registered host, whose `reveal` brings the paper's text on show; anywhere else it navigates to `/papers/<paperId>#<paragraphId>`), `AnchorLink` (the square for the note editor), `registerPassageHost`. `paper-body.tsx` draws one tag per sticky inside the paragraph's `<p>` (after the text; `noteAnchors`, a `Record<paragraphId, {id, n}[]>` from `anchorMap(note, paperId)`); nothing changes without `noteAnchors`. `note-editor.tsx`: the `h3` with `anchor` renders `<AnchorLink>` in the marker column (the only edit there). A page arriving with `#paper-section-N-pM` scrolls to and marks the paragraph once the body is there (`passageFromHash`, in `StickyNotes`).
6. **The stack (B9).** `lib/reader/windows.ts`: `useWindows` (`{ id, kind: "sticky" | "notes" | "explain", title, order }`; `open` — re-opening raises —, `close`, `raise`; not persisted), `stackLayout` (cascaded cards: oldest at the top, each later window one header (40 px) lower, headers only for the ones behind, the last raised in front and whole, 260 px or what the screen leaves), `columnTop`. Stickies stand at `z` 60+ (under the explain window's 70, over the masthead's 50); on the page's unmount the stickies close (a window never follows the reader to the next paper).
