## The rules as built

**R15a.** In `CAPTION_SEPARATED` the consumed separator after the number is `[.:|—–-]`: the bar leaves the caption's words like the full stop and the colon. A bar inside the title stays ("Fig. 6 | Strain | rate curves" gives "Strain | rate curves"); a lone "Fig. 7 |" has no words.

**R6b.** New `captionAt(read, i, pitch, body, furniture)` = `captionOf(read[i])` unless `opensMidSentence`. A label line is no caption when the line above it is, all at once: on the same page; directly above and within a line pitch and a half (a body-size-and-a-fifth pitch when none is measured); in the same column (left edges within 2.5 body sizes; the previous column's last line sits below, another column far to the side); set in the body's size (0.6 pt) and face; not furniture; and does not end a sentence (`.` `!` `?` `:` with a closing bracket or quote after it allowed, and a superscript-digit run or a bracketed number list after that taken off first, `endsSentence`); and that line is not itself part of a caption (`inCaption`: the chain back through `continuesCaption` to a caption that stands — a list of captions that end without a stop is not eaten one by one). The one call site in `buildOutline` reads `captionAt(read, i, pitch, body, furniture)` instead of `captionOf(line)`. The relaxation of R6a: a space and a bracket after the number is a caption when the bracket is a panel mark (one or two letters, or a short list: "(a)", "(B)", "(a,b)", "(a-c)", "(ii)") and a capital, a separator or the end of the line follows it ("Fig. 1 (a) Title", "Figure 2 (A) Overview"); "Fig. 5 (left) shows", "Fig. 1 (a) shows", "Fig. 1(a)" and "Fig. 2 (see below)" are still citations. The tests hold both ways (below).

**R14a.** "Extended Data Fig. N" is a figure of its own numbering, distinct from "Fig. N" everywhere:
- `pdf-outline.ts`: `CAPTION_SEPARATED` takes an optional "Extended Data" prefix (any case, any spacing); `captionOf` keeps it in the label ("Extended Data Fig 3": the label word as printed, the prefix spelled one way), refuses it before Table/Scheme/Chart, and gives it the ordinal `1000 + N` so that the binder's lookup by ordinal (`captions.find`) can never take it for "Fig. N". `CAPTION` and `headingOf` are untouched.
- `pdf-engine.ts`: `CAPTION_RE` and `LABEL_RE` take the prefix (group 1 the prefix, group 2 the number); `labelKey` / `captionKey` (which read those groups) return `ed3` for it; `measurePdfFigure(bytes, page, fig)` takes a number or the token `ed<N>` (a bad token names nothing).
- route `figure-image`: `fig` is a number (as before) or `ed` and plain digits, 1 to 999, no leading zero; the engine label is built from it ("Figure 3" / "Extended Data Fig. 3"); anything else is a 400 before any lookup. The 404 text names the label asked for.
- `reading.ts`: `pictureNumber` returns the number for a main figure (unchanged) and the token `ed3` for an Extended Data one, nothing for any other label; `pdfFigureUrl(paperId, page, fig: number | string)` puts it in `fig=`; `placeFigures` accepts the prefixed labels, dedupes by label, and places each figure after the first paragraph that cites ITS numbering (`cites`).
- `figure-binding.ts`: the explicit citation, the label normalisation and the caption lookup keep the numberings apart; the private copy of `pictureNumber` is replaced by the import from `reading.ts` (the route-URL pin test still holds); `namedFigure` knows `ed3`; the pool is looked up inside the label's numbering (`poolOfSpace`), so `pickFigureForCaption`, which reads a bare "Fig. 3" out of either caption, cannot hand "Extended Data Fig. 3" the picture of "Fig. 3".
- Pool cap: `MAX_PDF_FIGURES` in `pdf-extract.ts` 12 → 24 (see "The cap").
- `FIGURE_EXTRACTION_REVISION` 4 → 5 (caption pairing changed; upload document caches and figure URLs re-key).

**The owner's addition (ruling §1h.433).** A figure the PDF does not print is plain text: "Fig. S3", "Figure S3", "Supplementary Fig. 3", "Supplementary Figure 3", "Supp. Fig. 3", "Supplemental Fig. 3", "Supplementary Information Fig. 3". The outline never lists one (the caption pattern knows no `S` number and no "Supplementary" prefix; tests pin it). `placeFigures` classifies each citation into main / extended / supplementary and a figure is placed only after a citation of its own numbering (before, "Supplementary Fig. 3" placed Fig. 3 after it). The binder skips a supplementary citation when it looks for the explicit "Fig. N" of a result (before, "Supplementary Fig. 3" bound "Figure 3"; "Fig. S3" already bound nothing by number, and still binds nothing by number, as it always did — the binding code did already ignore S-numbers; it did not ignore the "Supplementary" prefix). The route refuses `fig=S3` and the engine refuses `Figure S3`, as before (400 / "does not name a figure"). A caption an HTML source prints as "Figure S3" is a supplementary-numbered figure now (before, `placeFigures` read it as 3 and placed it by the mentions of "Fig. 3"); its pool picture is still paired by words (an existing test pins that).

## The cap (R14a, "say to what, and the work it adds")

Before R14a the whole-document pool did not reach Extended Data at all on an invented 15-figure paper (5 main, 10 Extended Data): `extractPdfCandidatesFromBytes` returned 5 (the Extended Data drawings had no typed caption and a drawing without an explicit caption is skipped). With R14a it finds all 15, and the old cap of 12 would cut it at 12 (mutation M11: the cap put back to 12 turns the 15-figure test red). Raised to 24, the sizing's own ceiling (`MEASURE_MAX` in `pdf-text.ts`): a Nature paper prints about 8 main and up to 10 Extended Data figures. The work it adds is one render per figure past the twelfth, on a paper that has them (a PNG of at most 4.5 megapixels, about a megabyte as a `data:` URL); a paper of 12 figures or fewer is read exactly as before; `EXTRACTION_BUDGET_MS` (25 s) and the 24 pages read still bound the call. Measured on the invented PDF: 15 figures in 363 ms (24 ms a figure) against 5 in 151 ms before; the invented figures are small (6.8 kB each as `data:` URLs), real ones are about 1 MB each, so the pool's memory per paper can grow by up to roughly 12 MB. Sizing (`MEASURE_MAX` 24) already covered 15 figures and takes the token (tested).
