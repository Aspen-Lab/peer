## Choices beyond the brief (small readings, consistent with the rulings)

1. **Seven paragraphs, not four.** The brief's four bullets became: what is sent and when; to whom; the web search; what the server keeps (three short paragraphs: the memory, the log line, the count with the usage row); what stays in the browser. 2. **"(or press E on a selection)"** is in the entry although the brief names only the click, Enter and Send: `e` opens the box on the selection and sends the first request exactly as the click does (P3-02b), so "only when you click" alone would have been untrue.

The one number it does state (an hour) is tied to `EXPLAIN_CAPS.cacheTtlMs` by a test.
4. **The three labels the entry quotes** ("Explain this?", "Search the web", "searched the web") are tied to `EXPLAIN` by a test, so a relabelled button shows up as a red page test.
5. **"Peer's own model" is Gemini** (as the existing "Your own model key" entry says), and "the provider whose key you set" covers a reader's own provider; the entry says only that Gemini searches with Google Search, because only the two Gemini providers set `supportsWebSearch`.
6. **The "Last changed" line on /privacy** already reads 2026-10-06, today's date, so it is unchanged.
7. **Red evidence for the cap fix** was produced in a scratch worktree (see commit 1) because the first instance had already edited the production constant; the edits in the checkout were kept.
