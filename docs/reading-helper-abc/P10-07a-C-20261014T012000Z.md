## The rules as built

1. **The rule is pure and measured.** `unheadedTrunk(sections)` in `web/src/lib/papers/reading-partition.ts`: the `body` section with the most words (earlier on a tie), `>= 0.5 *` all words, `>= 8` paragraphs, at most 2 other sections with a placed bucket (not `body`, `abstract`, `references`, `acknowledgments`, `supplementary`). `TRUNK = { share: 0.5, paragraphs: 8, placedRows: 2 }`. Returns `{ sectionId, sectionIndex, paragraphCount }` (a named `Trunk` type).
2. **The sanitizer enforces every invariant.** `sanitizePartition(raw, { sectionId, paragraphCount })` reads `raw.partition` (an array); role trimmed/lower-cased, `method`/`methods` -> `experimental`, unknown dropped (a `Map`, so `__proto__`/`constructor` are harmless); start a whole number or digit string in range; descending/duplicate starts dropped; neighbours merged; a role at most twice (third use dropped, then merged again); first start forced to 0; fewer than two parts -> null; `toParagraph` derived (next start - 1; the last = `paragraphCount - 1`). Extra: `restorePartition(value)` (a stored/fetched `GuidePartition` through the same sanitizer; the size is the last part's `toParagraph + 1`). `PARTITION_ROLES`, `PART_ROLE`, `GuidePart`, `GuidePartition`, `PartitionRole`, `Trunk` exported.
3. **The prompt asks for a partition only with a trunk.** `paragraph-guide.ts`: `guideTrunk(doc)` (= `unheadedTrunk` over `readableSections(doc)`), `buildParagraphGuidePrompt({ ..., trunk? })`: with a trunk the `task` names the section, `outputSchema` is `{ partition, gists }` (partition first, asking only `fromParagraph`), and B's three rule lines are appended verbatim; without one (absent, null, undefined) the system prompt, user prompt and `maxTokens` are byte-identical to the head's (pinned by a golden taken from the head `b0764747`). `gistMaxTokens(n, withPartition = false)` adds 300 after the cap. No reader field (the five keys `task, paper, paragraphs, outputSchema, rules`; a hostile extra arg is not sent).
4. **The route keeps a partition.** `route.ts`: `trunk = guideTrunk(doc)` after the cache miss; the prompt and `maxTokens` get it; `partition = trunk ? sanitizePartition(parseModelJson(raw), trunk) : null`; `kept === 0 && !partition` -> `unavailable`; the guide is `{ docHash, gists, partition? }` (key only when made), cached under the document hash (key unchanged); the upload revision re-check still gates the cache write; the debug line gains `parts` (a number) **only when a partition was asked for** (a headed paper's line is byte-for-byte as before, so the existing key-list test stands unchanged). Provider called once.
5. **The browser store.** `PARAGRAPH_GUIDE_STORAGE_KEY` = `peer-paragraph-guide-v2`; `readOutcome` keeps a guide with a partition and no gist (`gists: {}`), re-reading `guide.partition` through `restorePartition`; the hook returns `ParagraphGuideView = { gists, partition }` (a memoised object; one shared `NO_GUIDE` when there is nothing; `gists` is `undefined` when empty, so a partition-only guide does not hand the map an empty record). The page destructures `{ gists: paragraphGists, partition: paragraphPartition }` and reads the partition into **`void paragraphPartition;`** (passed nowhere; nothing on screen changes).
6. **Nothing else changes.** Grounding rule, the day's TTL, the 120-candidate cap (a 121-paragraph unheaded paper is `skipped`, no partition; and a prompt built from more than 120 candidates carries 120 paragraphs, both pinned), the report cache, `PaperReading.version` (not bumped), the extractors (read-only).
