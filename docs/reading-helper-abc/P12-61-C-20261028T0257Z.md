## The rules as built

**Part 1, the kept cut.** After the owner check, for an upload, the route looks up `figure-cuts/<hash16>/p<page>-<digest of the label>-r<FIGURE_EXTRACTION_REVISION>.cut` and, on a hit, answers it with the same private / `no-store` / `Vary: Cookie` headers and `X-Peer-Figure-Engine: mupdf`: no PDF read, no engine. The object is a one-line JSON header (`v`, `bytes`, `width`, `height`) and the PNG; a read whose header disagrees with the body, or whose body is no PNG, misses. Written whole or not at all (disk: temp file renamed, 0600 in a 0700 folder; bucket: an object upload). Only a first cut that produced a picture is kept (the store refuses an empty or non-PNG body); a failure to keep never fails the answer; a miss on a stored-but-damaged cut re-cuts and re-keeps. A bumped revision names another object, so older cuts are never read; `deleteUpload` removes the upload's folder (a failure there is logged and does not stop the rest of the deletion); the purge removes the folder of an upload that is gone, blocked or deleted, and in a live upload's folder any cut of another revision and any leftover `.tmp`. A public paper is unchanged (its edge cache; nothing stored).

**Part 3, no whole copy held twice.** `extractPdfFigures(source, opts)` takes `PdfSource = Uint8Array | { filePath }` and opens through `mupdf.Stream` (a Buffer stream for bytes, a file-descriptor stream for a path, closed with the document and on a failed open). The route no longer copies (`new Uint8Array(stored)` and `new Uint8Array(pdf.bytes)` gone). `withUploadPdfSource(hash16, work)`: on disk the stored file itself; from the bucket the object is streamed (signed URL, `fetch`, `pipeline`) into a private temp file (0600 in a 0700 `mkdtemp` directory), removed in `finally` — after success, after `work` threw, after a failed or broken download, and when the object is not there. This overrides the "nothing touches the disk" stance for this path, as ruled; the pool path (`withUploadPdfFile`, `extract.ts`) is unchanged. `measurePdfFigures(source, targets, budgetMs)` measures many figures with one open (null for nothing, undefined for "the budget ran out": not remembered as nothing); `withFigureSizes` makes one call for all missing captions.

**Part 2, the page file, made lazily.** On the first successful cut on a page of an upload the route also calls `cutPdfPage(source, page)` (graftPage + the catalog's `/OCProperties` grafted through the same graft map, `garbage=compact,compress`; null for a password, a missing page, a non-PDF, an oversize source, or a page whose bounds, rotation and crop included, differ from the document's) and keeps `figure-cuts/<hash16>/p<page>.pdf` (no revision; refused unless it begins `%PDF-` and ends with `%%EOF`). A later cut on that page — another figure, or the same one after a revision change — runs the engine on the page file (`onlyPage: 1`) and never opens the paper (`withUploadPdfSource` not called). An upload with no page file, or a page file that is cut short or that the engine cannot read, takes the whole-file path and makes the page file again. A 404 from a page file names the page that was asked for. The purge's revision sweep keeps page files and removes the folder of an upload that is gone or taken down; `deleteUpload` removes them with the cuts. Making the page file never fails the answer; nothing is made for a failed cut or for a public paper.
