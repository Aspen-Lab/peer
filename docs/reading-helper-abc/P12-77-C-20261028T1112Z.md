**Rule 2, O2 (`inline.ts`).**
- **Reader.** `parseInline` reads `<u>x</u>` (any case) as the same `underline` token as `__x__`: three characters of opening tag and four of closing (`from`, `inner = from + 3`, `to`). The dialect's edges hold: a word, not a space, against each tag; nothing empty; no line break; no tag of its own kind inside. Unlike `__` it needs no whole word around it. A paste is stored as it is (`parseMarkdown` keeps a line's inline text), so a pasted `<u>x</u>` is underlined wherever the block is drawn, exported to Word / print / plain text, or searched.
- **The reading of an old `__text__`, as it is today and still is:** underline in this app (CommonMark, Obsidian and Pandoc read it as bold). It needs a non-space, non-underscore character at each edge; it must not touch a letter, a digit or an underscore outside (`a__b__c`, `snake__case__name`, `___x___` stay text); a single `_` may sit inside but not at an edge; nothing crosses a line; it nests with the other marks and holds the escapes `\*`, `\_`, `\=`. Unchanged and pinned (same token, same positions, same refusals), so nothing already exported changes its meaning on the way back in.
- **Writer.** `portableUnderline(src)` is the block's source with every underline as `<u>…</u>`, token by token (code runs, links, bare addresses, escapes and every other mark untouched; a source with no underline comes back character for character; idempotent; the output reads to the same shape). `**__both__**` is `**<u>both</u>**`, `__**b**__` is `<u>**b**</u>`.
- **Not changed, on purpose:** `MARKERS.underline` is still `"__"` (the existing test "names the markers" is unchanged and green) and the toolbar still writes `__`. See section 8, item 1: the stored form is decided by `wysiwyg.ts`, and the Markdown export copies a block's text verbatim from `export.ts`; neither is a file of this item. **So the exported `.md` does not change yet.**

**Rule 3, E2 (`notes-button.tsx`).** The edge tab is shown at every width (`flex`, not `hidden md:flex`), clamped above the thumb bar by rule 1's expression. A press under `md` (`(min-width: 48rem)`, asked at the press by `opensWindow()`) is the notes page's opener: a second `usePaperNotes` built without a window opener, which is the one that records the reader's place (`rememberPlace`) and navigates, exactly what the row does, from wherever the reader is. From `md` the press opens the window, as before. A second press with the window shown still closes it, whatever the width is by then. The in-flow row is unchanged.
