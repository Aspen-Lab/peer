## The rules as built

1. **Three actions** (`selection-toolbar.tsx`). `SELECTION_LABELS` gains `highlight: "Highlight"`. `offeredActions({ canExplain, onHighlight, canHighlight })` says which stand, in order: Explain this only when the page can explain (P10-08b, unchanged), Take notes always, Highlight only when the page hands an `onHighlight` handler and `canHighlight` is true. `SelectionToolbarView` draws the third button (`data-selection-highlight`); every press keeps the selection (`mousedown` prevented). `SelectionToolbar` takes the two new optional props. The page does not pass them: **`onHighlight` stays unwired**, so on the real page there is no Highlight button and no `h` until a later C (P11-17) passes C P11-07's `useHighlight` (`onHighlight`, `canHighlight(target)`).
2. **Placement** (`actionsPlace`, pure, beside `toolbarPlace`; `margin.ts` is C P11-10's and read-only here — no `readMargin`, no right-strip fallback).
   - `margin` mode: `useMarginRect()` non-null and no open card within 4 px of the group's rect → a column, `left = rect.left + 8`, `top = placeInMargin(rect, first line's top, height)`, `aria-orientation="vertical"`, `data-mode="margin"`. The open cards are read through `MARGIN_CARD_SELECTOR` plus today's `[data-explain-dock]`, `[data-sticky]` and `[data-notes-window]` (`OPEN_CARD_SELECTOR`, `openCardRects`).
   - Otherwise `above`: today's pill (`toolbarPlace`), in a row, holding the three buttons.
   - Under 768 px nothing is drawn; hidden while the selection is wholly out of view; 12 px of hysteresis (a group that went above because of a card returns only when the card is 4 + 12 = 16 px clear; `mode` is the one it was drawn in last).
   - Re-measured on scroll (capture), resize, the margin's own change (the registered rect; its `ResizeObserver` is `margin.ts`'s), every change of the window stack (`useWindows.subscribe`, read after the next animation frame so the card is drawn) and the root element's `style` (the dock's reserve — this fixes defect (b): the pill went stale after the reflow). Nothing is listened to while no selection stands.
3. **Keys and phone.**
   - `ReaderAction` gains `note` and `highlight`; `PAPER_KEYS` two rows — `n` "Take notes on the selected passage" (legend word `notes`) and `h` "Highlight the selected passage" (`highlight`) — placed before the `explain` row, so the existing pin "explain is the entry before back" holds. The help sheet and the foot legend read them from the same table. `selectionActions(current, { note, highlight })` builds the two registry handlers: each reads the page's selection at the press, does nothing with none, and is left out when the page has no handler for it. The page: one hunk (H-B) — `...(hasBody ? selectionActions(() => explainTarget, { note: takeNote }) : {}),` beside the `explain` line, plus the import. `h` joins at the same place when the page has a handler. The `g` chord still reads its second key first (tested). `n` acts at every width, as `e` does.
   - `explain-offer.ts`: a second, independent flag (`setHighlightOffer` / `highlightOffered` / `subscribeHighlightOffer` / `useHighlightOffer`) written by the selection toolbar under 768 px while a settled selection on the screen has a highlight on offer; the explain box's own flag is unchanged. `thumb-bar.tsx`: while either flag is on, the rail IS the cells — `ExplainCell` and the new `HighlightCell`, each `min-h-11`, one share of the width (`grid-cols-2`, or the whole rail for one); "← Briefing", the position and "Next →" return when the selection goes.
4. **The margin is empty with no selection and on opening the report; nothing is reserved by the toolbar.** The toolbar returns null without a selection, attaches no listener and no observer, writes nothing to the root element (a source pin forbids `reserveDock`/`setProperty`); Escape is unchanged (`resolvePaperKey("Escape") === "back"`, tested).

`page.tsx`: H-B only. H-A (refs for `n`/`h`) is not needed — the registered actions are rebuilt after every render, so a closure over `explainTarget` is the current selection; H-C (the `<SelectionToolbar />` line) is not touched, because `onHighlight`/`canHighlight` stay unwired.
