## The cause (not the brief's guess)

Not a partition row and not `partitionedMap` / `withPartitionMarks`: each paragraph is one row line in the map's data, once. The "second, monospaced line with a broken line height" is **Peer's gist** (`<span role="note" class="annotation …">`, the label face), which P3-03 draws after each opening when the paragraph guide has one. The stub's guide answers a gist as the paragraph's first eight words (`stub-ext.cjs`), and the invented paper's openings are eight words, so every gist was the opening again; a model may do the same for a short paragraph. The no-key map has no guide, hence no gists, hence one line each. A headed keyed map would show the same doubling given the same gists. The "broken line height" is the label face at `line-height: 1.4` on a different size inside the `<li>`'s own line box; it applies to any gist and is not touched here (a real, different gist is drawn as before).

## The fix (reading-map.tsx, rows' render only)

`repeatsLine(gist, opening)`: a gist that, lower-cased and with punctuation / spacing folded, equals the opening or is its start at a word boundary is not drawn. `gistOf` takes the opening and applies it; `gistShown` (the legend line) uses the same `gistOf`, so a map whose gists are all repeats has no "Peer's reading" legend from the gists (a partition's own tag still shows it). A gist that says something else is drawn exactly as before. A line with no (or a repeated) gist is byte-identical to the no-key map's line (test). Nothing else changed: no-key map, headed map, tints, marks, group rows, the outer wrapper, `reading-map.ts`, `paper-body.tsx`, `reading-partition.ts` untouched.
