## The rules

1. **The store** (`figure-viewer.ts`). One open figure, in memory only. `openFigure(ref)` replaces any open one (D2); the open figure opened again stays open (D4) — same key, nothing closed — but is a **new ref object**, so a host that acts on the ref's identity brings its card forward on a second press without resetting its zoom (the host keeps zoom and pan keyed on `ref.key`); `closeFigure()`; `getOpenFigure()`, `openFigureKey()`, `subscribeOpenFigure()`; the hooks `useOpenFigure()` (the ref or null) and `useFigureOpen(key)` (a boolean: only the figures whose answer changes render again). `FigureRef` = `{ key, src, label, caption, natural: {width,height} | null, origin: {left,top,width,height} | null }`; `origin` is the button's rect in **window** pixels at the press. No `useWindows` call, no `holdInPlace`, no storage, no logging (tests read the file's code, comments stripped, and spy the console). It is a plain external store read with `useSyncExternalStore` whose server snapshot is the current state, **not zustand**: zustand's server snapshot is its initial state, so a render outside a browser (this suite's, node) could never show an open figure, and `aria-expanded="true"` and the ring could not be tested.
2. **The click** (`Figure` only). The picture is wrapped in `<button type="button" aria-label="Open {label} in the margin" aria-expanded={open} onClick className="… cursor-zoom-in">`. In the aspect box the button is `block h-full w-full` (the box stays the mat's first child); with no known size it is `mx-auto block max-w-full` around the unchanged `<img>`. A figure with no picture is no button. The press reads the loaded picture's `naturalWidth/Height` (else the record's width and height, else `null`) and the button's rect, and calls `openFigure`. The store's key is `${label}:${ordinal}`, the one `Section` already gives the figure as its React key (computed inside `Figure`; `Section` is not touched). The four reserve literals (`figureMatClass(waiting)`, `onLoad`, `onError`, `!img.complete) setWaiting(true)`), `onPicture` and `figureBoxStyle` are untouched. The open figure wears `ring-2 ring-accent/45` (D10), a **box-shadow**, not the CSS `outline` property: the global keyboard focus outline (`globals.css`, `@layer base`) is an `outline`, and a utility-layer `outline-*` would have overridden it for a keyboard reader who focused the open figure; measured, both draw together (2px accent ring at 45 % and the 2px focus outline at a 3px offset).
3. **The goldens** moved by the change, updated by me, and no other: `paper-body.test.tsx:40` (`BEFORE`), `paper-body.plain.test.tsx:78` and `:81` (`TODAY_WITH_ROUTE`, `TODAY_NO_ROUTE`), `paper-body.figure-size.test.tsx:94` (the unsized case's mat now holds the button before the `img`; `:95` and the sized case `:77-79` are unchanged and green). ## For the manager

- **`paper-body.tsx`: one line outside `Figure`.** `Figure` cannot use the store without an import, so line 30 is `import { openFigure, useFigureOpen } from "@/lib/reader/figure-viewer";` (in the import block, after `Band`). Every other hunk is inside `Figure`. If C P11-09's hunks add an import next to it, the merge is a one-line conflict; keep both lines.
- **A key from another paper.** The store's key is the body's `${label}:${ordinal}`, which two papers share ("Figure 1:1"). Nothing here closes the figure when the reader goes to another paper; the host (B P11-05 §2.3: `key={paper.id}` plus an unmount cleanup) must call `closeFigure()` then, or the next paper's Figure 1 would read as open. Matching on `src` as well (it carries the paper id) is a one-line change in `useFigureOpen`'s callers if you want the body safe by itself.
- **What the host reads.** `useOpenFigure()` gives the ref; act on its identity (an effect on the ref) to bring the card forward on every press, including a re-press of the open figure (D4); keep zoom and pan keyed on `ref.key`. `origin` is window pixels at the press, not page pixels. `natural` is null when neither the loaded picture nor the record knows the size. B P11-05 §2.3 named `useFigureViewer` / `useFigureOpen(key)` / `mode`: this store has `useFigureOpen(key)`, no `mode` (the width decision belongs to the host) and no `holdInPlace` (ruling §1h.113).
- **D10 is a ring, not an `outline`.** See rule 2; if you prefer the CSS property, `ring-2 ring-accent/45` becomes `outline outline-2 outline-offset-2 outline-accent/50`, and the focus outline of a keyboard reader on the open figure is then replaced by it (utilities beat the base layer).
