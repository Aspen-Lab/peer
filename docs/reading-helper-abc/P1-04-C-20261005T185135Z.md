## Files changed

### Server
`web/src/lib/papers/reading.ts`:
- `ReadingSection` gains `id: string`.
- `PaperReading` gains `map?: ReadingMap` and `version` goes from 5 to 6, in both the type and the value.

`web/src/lib/papers/reading-map.ts`:
- `sectionParagraphs` and `readableSections` (P1-01's extraction) moved here from `reading.ts`, with their code unchanged except for one addition: each entry now carries `id`, the section's own or else `s<index>` over all the document's sections (the same fallback the map used in P1-01).
- `reading.ts` re-exports both names and imports `readableSections`, `readingMapOf` and the `ReadingMap` type from here. `reading-map.ts` imports from `reading.ts` only the `ReadingEquation` type, which is erased at runtime. Reason: `reading.ts` must import the map builder, and leaving the split in `reading.ts` would have made the two modules import each other at runtime.
- New `readingMapOf(rendered)`. `buildReadingMap(doc)` is now `readingMapOf(readableSections(doc))`. P1-01's 47 map and route tests pass unchanged.

`web/src/components/reader/use-reading.ts`:
- `READING_VERSION` 5 → 6. It is typed from `PaperReading["version"]`, so tsc requires the change. Readings cached in the browser under v5 are now discarded by the existing version gate, so no cached reading lacks a map.

### Client
`web/src/components/reader/reading-map.tsx` (new): `ReadingMapView({ map, openRows?, phoneOpen? })`.
- Starts with the eyebrow "Map", then the summary line "N sections · about M min".
- One row per section:
  - a fold control `+`/`−` (`aria-expanded`, aria-label "Show/Hide how the paragraphs of <heading> open"), only when the section has at least one non-null opening;
  - the heading as a link to `#paper-section-<k>`, indented by depth with the same rule as `paper-contents.tsx` (copied as a 3-line local `depthOf`, because `paper-contents.tsx` is not in this item's files);
  - the role tag, absent for `body`;
  - `p.N` for PDF sections only;
  - `N min`, shown when > 0.
- An open row lists its non-null openings, each a link to `#paper-section-<k>-p<index>`. A null opening is not listed. Headings and openings render through `MathText`, as the body does.
- Phone collapse uses a CSS breakpoint, not a viewport hook. The table wrapper is `hidden sm:block` (`sm` = 40rem, the Tailwind 4 default; `globals.css` defines only 3xl/4xl). The "show map"/"hide map" button is `sm:hidden` and expands the table in place (`aria-expanded`). This keeps the server render and the first client render identical.
- `openRows` and `phoneOpen` only set the initial state. The page passes neither; tests use them.
- An empty map renders nothing.
