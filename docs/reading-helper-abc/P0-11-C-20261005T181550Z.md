## Can private or per-user text still reach a figure URL?

- **Upload (`upload:<h>`):** no. It is a POST with no title, and a GET carrying `query` or `paperTitle` gets 400 (P0-10).
- **Public paper with a private attachment:** `SectionFigure` passes `revision`, so it is a POST. The report text and the public title go in the body.
  - The plate and caption requests (`page.tsx:726`, `paper-plate.tsx`) pass no `revision` and no `query`.
  - They remain GETs with the public id, public title, `url` and `doi`. That is all public data.
- **Public paper without an attachment:** unchanged GET. Its `query` is report text about a public paper, as before this campaign. That text comes from the reader's own model run, but about public content; it was outside both rulings.
- **Not guarded on the server:** unlike P0-10's upload rule, the server does not refuse a GET for a public id that carries `rev` plus `query`. The ruling did not ask for it.
  - A client regression there would fall back to a GET silently.
  - The client test is the guard. A server-side 400 for `rev` + `query` would be a one-line follow-up if the manager wants it.
