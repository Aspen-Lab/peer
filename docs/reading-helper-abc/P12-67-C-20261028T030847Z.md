## The rules as built

1. **Learn the code's ligature from the paper** (`learnLigatures(texts)`). A *word* is a maximal run of letters (with combining marks) and private-use characters (U+E000–U+F8FF); it is lower-cased. A word with no private-use character is one the paper prints plainly. For each code, the distinct words that carry it are tried with fi, fl, ff, ffi and ffl in its place; a candidate scores one for every such word the paper also prints plainly. The code's ligature is the candidate with the most words if it has at least 2 and at least twice the runner-up's; otherwise the code is not in the answer. Choices the brief left open, all on the conservative side: a word counts **once** however often it occurs (so "one confirming word" cannot be inflated by repeating it); a word carrying **two different** codes confirms nothing (with one replaced it still carries the other, and no plainly printed word does; this also keeps the cost linear, see rule 3); a code that **stands alone** (no letter in its run: a bullet, a mark between spaces) is not in any word and is never learned, so a paper that prints "Wi-Fi" cannot confirm a bullet as "fi". Evidence is pooled over every text handed in (title, headings, bodies, captions).
2. **Apply it everywhere** (`applyLigatures(text, learned)`, `restoreLigatures(doc)`). Inside a word that has at least one letter, every learned code becomes its ligature's letters (lower-case), every occurrence, not only in the words that confirmed it. Nothing else changes: characters outside the area are never touched, an unlearned code stays where it is, a code standing alone stays. `restoreLigatures` takes the finished document, learns from the title, every section's heading and text and every caption's label and text together, applies it in those places, and carries everything else over (ids, buckets, pages, sizes, the source). A document in which nothing is learned comes back as **the same object**, so a paper with no private-use character is byte-identical. The equations are left out on purpose (a math font reuses the area for symbols, and an equation is not a word the paper prints elsewhere).
   **The call site** is the last statement of `normalize()` in `pdf-text.ts` (`return restoreLigatures(doc)`): the one function both `tryExtractPdfText` (a link) and `extractPdfTextFromBytes` (an upload; `extractPdfTextFromPath` goes through it) pass every section's heading and text, every caption and the title through, after `cleanPaperText`, `dropStrayHeadings` and `withSectionIds` have run and before the document is returned to either caller (and so before `withFigureSizes`).
3. **Pure, deterministic, no dependency, linear.** `ligatures.ts` imports nothing and uses no clock, random, environment or global. One scan collects the words (a `Set` of plain words, a `Map` code → distinct words); each broken word is tried against 5 candidates, each a split/join over that word's own length; a word with two codes is skipped, so no word is ever walked once per code; the apply is one `replace` over the words.

## The tests (new file `web/src/lib/papers/ligatures.test.ts`, 40 tests; none re-aimed, none deleted, none weakened, no existing test file touched)

Rule 1 (17): learns fi, fl and ff from words printed both ways; learns ffi and ffl; learns nothing from a paper with no private-use character; leaves a code alone when only one word confirms it; counts a word once however often it occurs; learns from two confirming words and no rival; leaves a code alone on a tie; wants twice the runner-up (2:1 wins, 3:2 does not, 4:2 wins, and the same with fl ahead); matches case-insensitively; does not take a word that still carries a code for a plainly printed word; lets a word with two different codes confirm nothing; never learns a code that stands alone; reads a word through punctuation, digits and hyphens; pools the evidence of every text (array, set, generator); learns each code on its own evidence; takes the area as U+E000–U+F8FF, edges included (U+F900 is a plain letter); returns a new map with the same answer.
Rule 2 (16): `applyLigatures` — every occurrence, not only the confirming words; an unlearned code stays in its word; no character outside the area changes (accents, dashes, minus, NBSP, CJK, emoji, U+FB01/FB02); a code standing alone stays (nine shapes); the same string when there is nothing to do. `restoreLigatures` — title, headings, bodies and captions all restored; evidence spread over different places; ids / buckets / pages / sizes / equations / source carried over, same key order; the input is not changed; **the measure** (three codes, six words each printed both ways: 11 codes before, 0 after, every word reads correctly); one confirming word or a tie stays unchanged while the others are restored; a paper with no private-use code is the same object, byte for byte; a paper whose codes have no evidence is the same object; a document with no title / sections / captions. The test builds its own PDF (`ligaturePdf`: the font names its ligature glyphs by code, `/uniE103`, with a width for every character code, as an embedded font has; without widths pdf.js sets a space around each glyph).
Rule 3 (7): imports nothing and reaches for no clock / random / process / fetch / console / global (checked on the source); frozen inputs go through and the learned map is never written; the same answer every time and in every order of the texts, and restoring a restored document is a no-op; linear — a million characters of prose, a hundred thousand different broken words each confirmed by a plain one, one word of a million characters with one code and with every code of the area, a document of two thousand sections. ## For the manager

1. **`page1Text` is not repaired.** The upload route's DOI search and title fallback read `page1Text`, which `extractPdfTextFromBytes` builds from the page's lines before the outline; it still carries the raw private-use characters (a broken title there would reach the fallback). Not mine to change (one call, in `normalize()`); a one-line second call on `page1Text` with the document's learned map would need `restoreLigatures` to expose the map, which it can.
2. **Headings are classified before the repair.** `pdf-outline.ts` buckets a heading (`canonicalizeHeading`) from the raw text, so a section named with a ligature ("Conflict of interest", "Findings", "Classification") that came out broken is bucketed as its broken self; the heading *text* is fixed afterwards, the bucket is not. The only way is to repair the page items before `buildOutline` (a different place, in `readPages`/`pdf-outline.ts`, not mine, and one I could not measure on the owner's P1 by design).
3. **Replacement is lower-case.** The rule says "its ligature's letters", and the glyphs are the lower-case f-ligatures; an all-capitals word is never ligated, so no case folding was added. If a font ever coded a capital-initial ligature ("Fi"), it would come out in lower case.
4. **Learning is per paper, over title + headings + bodies + captions, not the equations;** a paper whose ligated words never appear plainly elsewhere (a short note) is left as it is, as the rule says. A code that the font uses for two ligatures (regular and italic faces sharing it) is left unchanged unless one wins by 2:1.
