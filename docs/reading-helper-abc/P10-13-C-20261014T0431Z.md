## 2. The cause

`markEdit` knew only the two cases "the markers sit just outside the selection" and "just inside it"; it never looked at the tokens. So a mark laid over marked text was wrapped blindly: underline over a range holding an underline (`==__al**pha**__==`, select all, Ctrl+U) gave `__==__al**pha**__==__` (measured on the head, §5), a selection that ended inside a mark left its closing `__` or `==` without a partner, and a mid-word underline (`a__lp__ha`) never parsed (the underline regex wants a non-word character outside its markers). Any stray `__` / `==` is a text token, so the rendered note shows it and the Markdown and `.txt` exports carry it (the dump's `alpha____`). The tail of A's exact source (`==alpha__==__ ==hl==`) was not reproduced step for step (the textarea's caret collapses after every edit, so A's reselection is unknown), but the class is the one above and the property test finds it by exhaustion.

## 3. The rules, as built (`inline.ts`)

`markEdit(src, start, end, mark)` (signature unchanged) reads the source's tokens with their positions, nested ones included (`spansOf`), then:

1. **Grow the selection until it cuts nothing.** Any mark, link, citation, URL or code run the selection overlaps without lying inside its content or covering it is taken whole (a selection of only an opening marker is the whole mark). For underline it also grows to the whole word (`a__lp__ha` does not parse). A selection that is exactly the content of a mark of another kind is taken as that whole mark, repeatedly: `__alpha__` with the word selected inside the markers, highlight → `==__alpha__==`; `==__alpha__==` with the word selected, bold → `**==__alpha__==**`.
2. **A range already carrying the mark loses it**: the whole content of the mark (selected inside the markers, or the mark with its markers) unwraps it; a part of a longer run comes out and the rest stays marked with its edge spaces outside (`==alpha beta gamma==`, "beta" → `==alpha== beta ==gamma==`); a selection every word of which already sits under the mark (the mark nested in others, `==__alpha__==` → underline → `==alpha==`) loses it.
3. **Anything else is wrapped**, a part of a marked run nesting inside it (`__alpha beta__`, "beta", highlight → `__alpha ==beta==__`), the same mark inside the selection folded into the new one (or, if folding would join a word to a marker, the mark written around the parts that lack it), an `_em_` at the edge written with a star under underline.
4. **After every edit the source is parsed again** (`strayCount`); an edit that would leave a text token holding `__` or `==` that the source did not hold is refused (`{from: a, to: a, text: ""}`, the caret at the selection's end; `applyMark` writes nothing). Seen only for adjacent marks with no space between (`__alpha__==beta==`, highlight off `beta`): 0 of 4,404 selections in the property.
5. Nothing selected: the pair, the caret between, or the pair out again, as before. `code` keeps its old behaviour (its text is literal; `codeEdit`).

The editor's caret handling is unchanged: after an edit the caret is collapsed after the new text, as before.
