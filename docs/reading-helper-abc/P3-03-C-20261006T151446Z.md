## What was built

**`web/src/lib/papers/paragraph-guide.ts`** (pure; no `node:` import, so the browser could import it — today it imports types only; the hash is the route's). `gistCandidates(doc)`: every rendered paragraph (`readableSections`) with an opening (`openingOf`), in reading order, as `{ sectionId, sectionIndex, paragraphIndex, opening, paragraph }` with the paragraph clipped to 1,200 characters at a word. `tooManyParagraphs(doc)`: more than 120 candidates. `buildParagraphGuidePrompt({ paper: { title }, candidates })`: the title and the candidates in document order (each `topicSentence` = the opening, and its `text`), the schema `{ gists: [{ sectionId, paragraphIndex, gist }] }` and the rules (12 words, condensed from the topic sentence, no new facts, no number the paragraph does not state); at most 120 paragraphs of at most 1,200 characters, the title cut at 300 — and nothing about a reader is a parameter. `sanitizeParagraphGuide(raw, candidates)`: only an entry that names a candidate (the index a whole number or a string of digits), the gist cleaned and whitespace-collapsed, DROPPED (never cut) over 12 words or 120 characters, the first gist for a paragraph wins, anything not the schema is `{}`. `groundedGist(gist, paragraph)`: at least two distinct content words shared (runs of 4+ letters, not a stopword, read through `normalizeForMatch`); `verifyParagraphGuide(guide, candidates)` drops every gist that is not grounded in its own paragraph and every entry that names no candidate. Types `GistRecord`, `ParagraphGuide { docHash, gists }`, `ParagraphGuideResult`; `GUIDE_CAPS`; `gistMaxTokens`; `createParagraphGuideCache` / `paragraphGuideCache` (32 documents, 1 hour, keyed by the document's hash alone).

**`web/src/app/api/papers/[id]/paragraph-guide/route.ts`**: `POST`, `force-dynamic`, `maxDuration = 60`; body `{ paper, llmOverride? }`. In order: JSON, paper, `[id]` equals `paper.id` → the upload owner checks as the explain route makes them (a malformed claim, an unowned upload, an attachment that does not list the paper: one 404 with `PRIVATE_UPLOAD_HEADERS`) → `requireEntitledAiRequest("paragraph-guide", 20)` → `resolveProvider(override, entitledContext(…, "paragraph-guide", byok))`; no provider that can write → `200 { unavailable: true }` before any text is read → `getFullText` → no document or sections → unavailable → more than 120 candidates → `200 { skipped: "too_many_paragraphs" }` (nothing asked, nothing kept); no candidates → unavailable (no model call) → the memory by `explainDocHash(doc)`: a hit answers `{ guide, cached: true }` with no model call → else one `generateJsonText({ maxTokens: gistMaxTokens(n), tier: "small" })`, `parseModelJson`, sanitise, verify, ONE debug line `[papers/paragraph-guide] pass` with sizes only (`promptChars`, `answerChars`, `paragraphs`, `kept`, a hashed user id); zero gists kept → unavailable (nothing cached); the upload-revision re-check (410 with the private headers, nothing cached); cache; `{ guide, cached: false }`. A model failure logs the error's name alone and answers unavailable (`CompanySpendCapRefusedError` adds the quota signal). Every answer is `no-store` (an upload's: `PRIVATE_UPLOAD_HEADERS`). **Not charged:** neither `consumeDeepReport` nor `consumeExplainTurn` is reached (a comment says why: one small call per document per hour across all readers; the entitlement check's hourly cap of 20 bounds one reader).

**`web/src/components/reader/use-paragraph-guide.ts`**: `useParagraphGuide({ paper, hasBody, enabled, llmOverride })` returns `gists` or undefined. One POST per paper when the reading has a body, the reader has a model (`enabled` = the page's `providerConfigured`) and nothing is kept: the memory `peer-paragraph-guide-v1` keyed by `buildReadingKey` (paper id + upload id + revision), a day, every touch in try/catch, pruned to 24 papers, holding `{ guide | skipped | unavailable, at }`. A kept `skipped` or `unavailable` is honoured for a day. A failed request (an error status, an answer that is not one, no network) keeps nothing. The effect is keyed on `[paperId, key, hasBody, enabled, kept]` — the paper object and the reader's key are read through a ref updated in an earlier effect — so a page re-render cannot send a second request; aborted when the page goes, and an answer that arrives after is kept nowhere. The answer and every kept entry are re-read defensively (text only, non-empty, ≤120 characters, a whole-number index, `__proto__` skipped).

**`reading-map.tsx`**: `ReadingMapView` takes `gists?: ParagraphGuide["gists"]`; a paragraph line with a gist for `(row.id, line.index)` gains, after the opening's `<a>` (not inside it), `<span role="note" aria-label={MAP.gist} class="annotation text-text-muted"> {gist} <span class="whitespace-nowrap text-text-faint">{PEERS_READING}</span></span>`. The opening, its anchor, its classes and its tint are untouched; a line without a gist is byte-identical to today's (pinned as a literal and against the whole map); a gist never makes a row foldable and shows only when the row is open. **`copy.ts`**: `MAP.gist` = "Peer's gist". **`page.tsx`**: the hook (`paper: ready ? paper : undefined`, `hasBody`, `enabled: providerConfigured`, `llmOverride: explainLlmOverride(profile)`), called with the page's other hooks above its first early return, and `gists={paragraphGists}` on the map.

## Choices beyond the brief (small readings, consistent with the rulings)

1. **`maxTokens` grows with the paragraphs (`gistMaxTokens`: 200 + 45 per paragraph, floor 600, ceiling 8,000) instead of a fixed 1,600.** A gist entry is about forty tokens with its keys, so 1,600 holds about 35 of them; a real paper has 60–120 candidate paragraphs and the JSON would be cut off mid-list, losing every gist. 120 paragraphs ask for 5,600.
2. **A document with sections but no paragraph that has an opening** answers `200 { unavailable: true }` with no model call (the brief names only `skipped` and `unavailable`); **zero gists kept after the check** is also `unavailable` and nothing is cached (the brief's "nonsense → unavailable"), the debug line still written for that model call with `kept: 0`.
3. **`groundedGist` compares exact words** (no stemming) after `normalizeForMatch`, and reads a hyphenated compound both as the one word the fold makes of it and as the words it is made of (the fold alone would have made "grain-boundary" one token no gist could share). The stoplist is about a hundred function words plus "paper", "study", "shows", "describes" and their kin.
4. **The client re-reads everything it keeps or receives** (text only, ≤120 characters, a whole-number index, `__proto__` skipped); a company-budget refusal is remembered as `unavailable` for a day like any other (the client does not read the route's `quota`). Remembering a transient refusal for a day is the brief's rule applied literally.
5. **`role="note"` + `aria-label={MAP.gist}`** is how "the accessible name for the gist span" is made real (an `aria-label` on a role-less span is not announced).
6. **The gist's ink is the muted one (5.5:1 light, 8.03:1 dark); the paper's opening keeps its existing faint one (3.14:1 / 5.69:1).** Peer's line is therefore the more legible run beside the quieter paper words; the opening was not touched, as the ruling says. A hierarchy call for A and the manager to weigh, and one line to change (`text-text-muted` → `text-text-faint`) if they want the paper's words to lead.
7. **The owner-check helpers are repeated a third time in the route** (the report route's private helpers, mirrored as the explain route mirrors them; a comment names the source). Extracting them would touch the report and explain routes, outside this item's files.
8. **`quota-exemptions.test.ts` reads comments**, so the route's comment says "neither counter is consumed here" rather than naming the deep-report consumer; the scan stays green.
9. **Commit trailers:** the task says to end with the two Fable lines; §1c says the attribution follows the committing agent's model, and my harness mandates `Claude Sonnet 5.5`. As in P3-02, the message ends with the Sonnet line, then the two Fable lines, so the last two lines are exactly the brief's.
