## What changed

1. **`stackRoom(windows)`** (`windows.ts`): what the explain window must leave the stack below it — a gap (8), a header (40) for every window behind the front, and the front's least height (`MIN_FRONT_PX` 160 for a sticky, `NOTES_MIN_FRONT_PX` 240 for the notes window) — exactly what `stackLayout` asks of the screen before it lifts or moves the column. 0 while no sticky or notes window stands. (The brief's wording was "40 px per other window"; I kept the front's usable height too, so the front sticky is not left a bare header. A sticky whose heading left the note is counted though undrawn: one header too much, never one too little.)
2. **`dockInStack({ top, paragraphTop, height, legend, room })`** (`explain-dock.ts`): the dock's top and `maxHeight` with the stack's room counted. Room 0: as always (`top`, down to the legend). Where the column can stand ABOVE the window (`DOCK_TOP_PX + room` fits over the paragraph, read at the thread floor so the window's own height never enters the decision) the window keeps its place, no higher than the column needs. Otherwise the window shrinks: level with its paragraph, ending `room` above the column's foot, down to `DOCK_STACK_FLOOR_PX` = 250 (its sticky header with the X, 140 px, and its sticky controls row with the follow-up field and Send, 101 px, and a few lines between) and never above the masthead's foot. The floor is above `CARD_MIN_HEIGHT` (120) on purpose: at 120 px the two sticky bars overlap and cover each other's controls (rule 2). The decision reads the paragraph's place and the screen only, never the measured card height, so a shrunk window cannot read its smaller height and un-shrink (the oscillation the P10-08 guard exists for). `columnBottomPx(height, legend)` is the column's foot (screen less the legend and a margin, at least 40), moved here from `useColumn` so the dock and the column read one number.
3. **`stackLayout`** (`windows.ts`): with the explain window standing (a `ceiling`) and the column unable to rise above it, the column is no longer lifted UNDER it (the old lift is what hid the headers: the column stands at z 60+, the explain window at 70). The front gives way instead (down to its header); the lift stays where no explain window stands. The existing tests pass unchanged (the "tight" case only asserts the top is not above `minTop`).
4. **`explain-box.tsx`** (beyond "the call" by 7 lines, all one concern): the one line that placed the dock (`placePanel(...)`, ~1089) now passes its result through `dockInStack` with `room: stackRoomPx`; `stackRoomPx` is read through `useState` + `useEffect` + `useWindows.subscribe` (a number, set only on change) and NOT through zustand's `useWindows(selector)`, because `explain-box.*.test.tsx` mock React with a hook runtime that has no `useCallback` for zustand's hook (172 failures on the first try); the new import is `stackRoom, useWindows`; `dockInStack` joins the existing `./explain-dock` import. `reserveDock` and its call untouched.
