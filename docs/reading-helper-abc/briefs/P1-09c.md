# P1-09c — example tags skip sentence fragments and generic words

Role: C. Ruling §1f.20 (5). Acceptance §3d 6, 18. Small; `lib/reader/question-examples.ts` and its test only.

What to build:

1. A multi-word phrase from the challenges or project text is offered as an example only when it has 2–6 words and none of its words (case-insensitive) is in a small local set of pronouns and auxiliaries: `we`, `i`, `our`, `you`, `your`, `they`, `it`, `its`, `this`, `that`, `these`, `those`, `he`, `she`, `is`, `are`, `was`, `were`, `be`, `will`, `can`, `do`, `does`. A rejected phrase is skipped and the next phrase `phrasesFromText` gives is tried, within the source's cap.
2. The single-word fallback (used only when a source has no acceptable multi-word phrase) is offered only when the templated question yields at least one specific route term — use `specificTerms` from `lib/papers/reading-map.ts` on the finished example — so a stoplist or generic word ("study", "work") never becomes an example. A source that yields nothing acceptable contributes no example.
3. Topics and methods stay as typed (they are the reader's own entries).

Tests: "Solid-state batteries for electric aircraft. We test sulfide electrolytes." → the fragment "We test sulfide electrolytes" is rejected and the project example is built from "Solid-state batteries for electric aircraft" (or the next acceptable phrase; state the exact expected string); a seven-word chunk is rejected; "We study how dendrites nucleate under fast charging" (no comma) → no challenge example at all (the fallback "study" routes on nothing); "creep; rafting; oxidation" → still "Does this help with creep?"; the caps and the earlier tests unchanged.
