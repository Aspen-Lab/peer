# P2-04 — the answers on the page

Role: C. Rulings §1g.5, §1g.13 (P2-02's `terms` are rendered by P3-01's strip, not here), §1f.17 (faces), §1a.4 (nothing hidden; "not mentioned" never means "not needed"). Acceptance §3d 9 and 8.

Setup: `git pull --ff-only origin deep-report-reading-helper-enhancement`; read §1g.5, §1g.3 (the shapes), §1f.17, §1f.13, §3d 8–9, `lib/papers/report.ts` (`QuestionAnswers`, `ReadNextItem`, `Claim.sectionId`/`page`), `components/reader/report-sections.tsx` (the Decision block and "What it proposes" positions; `CLAIM_CLASS`), `components/reader/evidence-quote.tsx` (`EvidenceQuote`, `SectionLinks`, `sectionHref`, `SectionAttribution`), `components/reader/reading-map.tsx` (`readingRoute`, the `RouteResult` shape), `components/reader/paper-body.tsx` (`sectionMark`, `ROUTE_TINT`, `HEADING_MARK`), `components/reader/paper-contents.tsx`, `components/reader/copy.ts`, `app/papers/[id]/page.tsx` (`route = useMemo(readingRoute(reading, asked))`, `model.report`), `lib/papers/reading-map.ts` (`RouteResult`, `ReadingMap.sections[].id/heading/page/minutes`).

What to build:

1. **`components/reader/for-your-questions.tsx`** (new), rendered by `report-sections.tsx` immediately after the Decision block and before "What it proposes", only when `report.forYourQuestions` is a non-empty array. Heading "For your questions" (the label face, as the other section eyebrows). Per question, in request order: the question (the reader's words, `font-reading`); the verdict as one line in the label face — "Answered", "Partly answered", or exactly "This paper does not address: <question>." for `not_addressed`, in which case no answers render (a non-empty `readNext` may still render: background reading for a question the paper does not answer is still useful); ≤3 answers, each the `text` as Peer's prose in the reading face with no quote styling, followed by `EvidenceQuote` for `evidence` with its section link (`SectionLinks`/`sectionHref` by `sectionId` → the map's heading, falling back to `evidenceWhere`) and " · p.N" when `page` is known; "Read next" rows for `readNext`: `§Heading · p.N · M min` from `reading.map.sections` by `sectionId` (skip a row whose id is not in the map), then the `why` line in the reading face; a `background` row carries the label "background" in the label face after the heading. Strings live in `copy.ts` under `ANSWERS`: `heading: "For your questions"`, `answered: "Answered"`, `partly: "Partly answered"`, `notAddressed: (q) => "This paper does not address: ${q}."`, `readNext: "Read next"`, `background: "background"`, `page: (n) => "p.${n}"`, `minutes: (m) => "${m} min"`. None of ASK/MAP/ROUTE/ANSWERS may contain "skip", "don't read", "ignore" or "not worth" (extend the existing grep test to `ANSWERS`).
2. **The Tier 2 overlay (§1g.5).** A pure `reportRoute(report: PaperReport | null, map: ReadingMap | undefined): RouteResult | null` beside `readingRoute` in `reading-map.tsx`: null without `forYourQuestions`; otherwise one `byQuestion` entry per question with `sections`: every section named by a kept answer's `sectionId` → `read` (hits `[]`, `paragraphs: []`, `evidence` = the first answer's evidence sentence for that section), every `readNext` with `kind: "answer"` → `read`, with `kind: "background"` → `background`; `vague: false`. A pure `mergeRoutes(tier0: RouteResult, tier2: RouteResult | null): RouteResult` beside `sectionMark` in `paper-body.tsx`: per section the highest tier wins with the order `read > background > skim > none`; `byQuestion` entries are concatenated (Tier 0's first, so the "Q1, Q3" titles keep the request numbering); `vague` is Tier 0's `vague` only when Tier 2 is null. The page: `route = useMemo(() => mergeRoutes(readingRoute(reading, asked), reportRoute(model.report, reading?.map)), …)`; when the model fails or has no questions, Tier 0 stands alone. If the `background` tier does not already pass the type chain of the rail, map and body renderers, do the narrowest typed widening at the page boundary with a comment, and record which files it touched (a ruling may add them).
3. **The `background` tint.** `ROUTE_TINT.background` → `--color-route-background` (the middle token P1-05 defined) on the contents rail, body `h3`, map rows and map lines; the map's fact line for a background-only section reads "background · needed for an answer" (`ROUTE.background` in `copy.ts`); `data-route="background"`. Nothing hidden, collapsed, greyed or reordered — the existing DOM-order/visibility test must still pass with the merged route.
4. **Tests** (`for-your-questions.test.tsx` new; `reading-map.test.ts`, `paper-body.test.tsx`, `route-tint.test.tsx`, the copy grep test extended): renders only with `forYourQuestions`; the three verdict strings exact; `not_addressed` → one sentence, no answers, "Read next" only when present; an answer renders `text` without quote styling and its `EvidenceQuote` with the section link and `p.N`; a `readNext` row shows heading, page, minutes and `why`, `background` labelled, an unknown id skipped; `reportRoute` tiers; `mergeRoutes` highest-wins (Tier 0 `read` + Tier 2 `background` → `read`; Tier 0 `none` + Tier 2 `background` → `background`; Tier 0 `skim` + Tier 2 `read` → `read`), null Tier 2 → Tier 0 unchanged byte-for-byte; `data-route="background"` tint on rail, body heading, map row and line; the body DOM identical with and without the overlay once route marks are stripped.
