## The rules

1. **The build's commit on the version line.**

   - The value is fixed when `next.config.ts` is evaluated, which is at `next build` or `next dev` start. That is what tells the owner a server is older than main. Put it in `next.config.ts`'s `env` under one name (for example `PEER_BUILD_REF`).
   - The value comes from a pure function in a new `web/src/lib/build-ref.ts`:
     - Vercel's `VERCEL_GIT_COMMIT_SHA` first, cut to 7.
     - Else `git rev-parse --short=7 HEAD`, via `node:child_process` (no new dependency), run from the config's own directory with a short timeout.
     - Else the empty string.
     - Anything that is not 7–40 hex characters becomes empty. Nothing else from git or the environment is read or shown.
   - With an empty value the line is exactly what it is today, with no placeholder and no extra dot.
   - Tests: the function (each branch, git failing or absent, a malformed value); the line with and without a value. Add a pin that `next.config.ts` wires the function and that no other config key changes (read the file as text, as other config pins do).
