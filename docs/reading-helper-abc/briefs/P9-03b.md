## The ruling (§1h.49)

The owner's spec says the window is level with the first line of **the selected paragraph** ("被选中的文字段落"), not the explained one; P8-02 chose "moves on explain, not on selection" as a judgment about transient selections. P9-03 showed there is no room beside the column for a floating control while the window stands. So, from 1024 px while the dock stands (a reader with a key, or a Tier-0 definition window):

1. **The window follows the selection.** When a selection is **offered** (settled — on mouseup / selection end, never during a drag; P8-02's `offered` state) in a paragraph other than the one the window stands at, the window moves to that paragraph's first line (`placePanel`'s clamp as today, `DOCK_TOP_PX` … `height − DOCK_BOTTOM_PX − DOCK_MIN_VISIBLE_PX`), with no close, no reflow, `--explain-dock` never removed. Its content is unchanged by the move: the open thread (of the previously explained passage) or the empty state stays. Explaining still replaces the thread as today.
2. **The window carries the control.** While a selection is offered that is not the passage the window explains, the window's header shows a button `Explain this?` (the same `EXPLAIN.ask` text; `data-explain-ask` stays its attribute so the e2e scripts find it) that does what the floating button did (`start(next)`); `e` unchanged. In the empty state the hint line "Select a passage in the paper, then press Explain this? or e." stays, and the header button appears beside it once a selection is offered.
3. **No floating button while the window stands.** The floating `ask` button is rendered only when no window stands (no key and no definition: the card range 640–1023, the phone sheet, and any window below 1024); there P9-03's gutter rule and the old placement apply unchanged.
4. **Level with the first line, everywhere.** The floating button (where it still appears) uses the selection's **first** line (`bounds.top`), not the last (`rect.top`) — the owner's "first line"; P9-03's tests (a), (b) and the runtime ones are re-aimed and named.
5. Comments: the header of `explain-box.tsx` says the new rule (replace "moves when the next passage is explained, not on a mere selection"); `paper-body.tsx`'s `ViewRects` doc says what `rect` and `bounds` are for now (C P9-03 §6.3).
