## The rules

1. **"Open your notes" is at the right under the Explain window's place and opens a window (B12)**: the edge tab stays fixed at the right edge (from `md`), placed under the explain window's column position (top `max(27rem, 50vh)` stays unless the explain window stands lower — keep the existing offset by `--explain-dock-width` so the tab never sits under the dock); pressing it opens `NotesWindow` — a floating panel in the dock's column (360 px wide, right edge, top `DOCK_TOP_PX` with no explain window, else under its bottom, as the sticky notes do; a reader can also drag it by its header within the viewport — optional, say if done), its header `Your notes` with a Close (×) and the export control (rule 5), its body the paper's whole reading note in the block editor (`NoteEditor` with the note from `ensureReadingNote`), scrolling inside itself, growing with the text to the window's bottom above the legend; fixed while the page scrolls. No navigation from the reading page; the label logic (`Notes` / `Open your notes`) stays. The row variant on a phone keeps navigating (phone deferred; say so).
2. **No limit, stays put (B15)**: the editor in the window takes any length (no character cap anywhere in the path; a test with 20,000 characters across 200 blocks); the window's scroll is its own; the page's scroll never moves it.
3. **The whole note is the report (B13 first half)**: the window shows the note's blocks in order — the sticky notes' `h3` "Note N" headings (with P10-09a's blue square, rendered by the editor) and their text — plus anything the reader types in the window directly; it is one note (`readingNoteFor(paper.id)`), the same the Saved page opens (B14, rule 6).
4. **Formatting (B16)**: `note-toolbar.tsx` above the blocks — buttons for bold, italic, underline, highlight, bullets, numbering (and the existing code / headings if trivial) — acting on the selection in the focused block through the editor's existing inline-markdown model: bold `**…**`, italic `*…*` (as now), **underline `__…__`** and **highlight `==…==`** are new inline marks in `inline.ts` (parsed, rendered by `inline-text.tsx` as `<u>` and `<mark>`, exported — `toMarkdown` keeps the marks as written; Word gets `<u>` / `<mark>`; plain text drops the marks); bullets / numbering turn the block's type (`bullet` / `numbered`, as the editor already has). Keys: ⌘/Ctrl+B, I (as now), **U** underline, **Shift+H** highlight (say the keys you chose in the checkpoint). The marks survive a reload (they are the stored text) and an export.
5. **Export (B13 second half)**: a control in the window's header (`Export ▾`): `Copy` (the clipboard gets the note as plain text), `Text (.txt)` (`toPlainText`: the blocks' words without markup, headings as lines, bullets as `- `, numbers as `1. `), `Markdown (.md)` (`toMarkdown`, as now), `Word (.doc)` (`toWordHtml`: an HTML document with the Word namespace, `application/msword`, headings, lists, `<b>` / `<i>` / `<u>` / `<mark>`, downloaded as `<title>.doc`), `PDF` (opens the browser's print of a print view of the note — a print stylesheet that shows the note alone — the reader saves as PDF; label it `PDF (print)`). None carries an `anchor.quote` (a test per format on a note with three anchored blocks). The notes page's existing export (`notes-rail.tsx`) is unchanged.
6. **From Saved, the whole note (B14)**: unchanged behaviour — the Saved page opens `/notes/<id>` which shows the whole note; the toolbar of rule 4 is mounted there too so the note edits the same way in both places. A test pins that the note the window edits and the note the page shows are one (`readingNoteFor`).
7. **Nothing else changes**: the block editor's other behaviour, the rail, the citations, the templates, the store's shape (P10-09a's), the explain box.
