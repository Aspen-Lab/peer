## The symptom

A paper whose font sets the ligatures fi / fl / ff / ffi / ffl as glyphs with no Unicode mapping comes out of pdf.js with a private-use character (U+E000–U+F8FF) in their place: "in\uE104uence", "\uE103gure", "di\uE09Derent". One of the owner's papers has 91 such characters; the reader sees a broken glyph in each.

## The rules

1. **Learn the code's ligature from the paper.** Collect the words that contain each private-use code. For each candidate (fi, fl, ff, ffi, ffl), count how many of those words, with the code replaced by it, are words the same paper prints elsewhere **without** any private-use character (case-insensitive). The code's ligature is the candidate with the most such words, if it wins at least 2 words and at least twice as many as the runner-up; otherwise the code is left unchanged.
2. **Apply it everywhere.** Replace every occurrence of a learned code (body, headings, captions) with its ligature's letters. Characters outside the private-use area are never touched; a private-use code that stands alone (not inside a word) is left as is.
3. Pure, deterministic, no dependency, linear in the text size.

## Measure

Invented text: a paper whose words "figure", "first", "influence", "flow", "different", "effect" appear both with and without three private-use codes — before: the codes stay; after: each code maps to fi / fl / ff and every occurrence reads correctly; a code with only one confirming word, or a tie, stays unchanged; a paper with no private-use codes is byte-identical.
