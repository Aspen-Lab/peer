2. **No window on entry (B2).** The empty standing window of P8-06 goes: `emptyDockStands`, `standing`, `waiting`, `EXPLAIN.empty`, the mount-time `reserveDock` — all removed. On entering a paper, with or without a key, nothing stands at the right and the page keeps its full width. The dock (from 1024 px), the card (640–1023) and the sheet (under 640) exist only while a passage is open; `reserveDock` is taken when the dock opens and released when it closes, as P7-15 built it.
3. **Any selected text is a target (B3's reach)**: the selection listener accepts a selection whose ends are inside one element marked `data-explain-source` — the body's paragraphs (as now, by `paragraphAnchor`), each block of the Summary tab and each answer under the question (the containers get `data-explain-source="summary"` / `"answer"`; the body's paragraphs `"paper"`) — and never a selection inside a control (a button, a link, an input, the commands at the left, the map, the question bar, the notes). `SelectionTarget` carries `source: "paper" | "summary" | "answer"` and, for a non-paper source, `paragraphId` is the container's own stable id (the block's key / the answer's index) so the thread store keys it the same way; the explain request sends the passage and the paper's context as now (the server verifies quotes against the paper; a Peer-words passage is explained in the paper's context). The 1,200-character cap stays. `explain-offer.ts` keeps publishing for the thumb bar.
4. **The window opens from the page's `explain` action only (B4)**: the selection buttons (C P10-09a's toolbar calls the page's `explain`) and the `e` key. The gutter pill, `placeButton`, the header's "Explain this?" control (`onExplain`, `data-explain-ask`) go. While open the window keeps P8-02 / P9-03b: it stays across a new selection, follows the selected paragraph's first line (a paper target) — for a Summary or answer target it stands at `DOCK_TOP_PX`; explaining the new selection replaces the session in place. Escape clears the passage and **closes** the window (there is no empty state to go back to); Close closes it. Reopening a passage already explained shows its kept thread as now.
5. **Close is a large highlighted X (B5)**: at the window's top-left, ≥ 32 × 32 px, the accent colour (the page's `--color-accent` or the one the commands use), an `aria-label` "Close", keyboard-focusable; the title beside it. The card and the sheet get the same X.
6. **No "Search the web" (B6)**: the toggle, its tooltip, the "searched the web" mark, the "not available" line, `EXPLAIN.searchToggle / searchWarning / searchedMark / searchUnavailable`, `explain-thread.ts`'s toggle functions, `replyExplain`'s `search` argument and `replyPair`'s `searched` flag all go; a reply request never sends `search`; the privacy sentence on it goes (its pin re-aimed).
