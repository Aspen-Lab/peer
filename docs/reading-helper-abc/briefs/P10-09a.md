## The rules

1. **The selection buttons (B3).** `SelectionToolbar` is mounted by the page with the current target (`explainTarget`), the page's `explain` action and a `takeNote` action. While a target stands (its `measure()` gives a box) and no window of this toolbar's own is being dragged, it draws one small floating pill **just above the selection's first line** (`bounds.top − its height − 6 px`, left-aligned with `bounds.left`, clamped into the viewport and clear of the masthead; measured again on scroll and resize through `measure()`), in the label face, holding two buttons: `Explain this` and `Take notes`; it goes when the target goes. It never covers the selected words. On a touch screen under 768 px it is not drawn (the thumb bar's cell is the explain control, §1h.66; "Take notes" on a phone is deferred — say so in the checkpoint). It renders where C P10-08's gutter pill used to; both may exist on the branch for a short while — yours is the one that stays.
2. **"Take notes" opens a sticky note (B7).** A floating window at the right edge in the dock's column (360 px wide, under the explain window's place: top = `DOCK_TOP_PX` when no explain window stands, else below its bottom — read the dock's box from the DOM by its `data-explain-dock` / role, or `--explain-dock` height if P10-08 publishes one; if nothing is readable, `DOCK_TOP_PX + 400`), its header `Note N` (the number, rule 3) with the passage's first words quoted (≤ 80 characters, in the quote style, the paper's words) and a Close (×); its body a text area the reader writes in at once (focus on open); closing hides the window — the note stays in the paper's note (rule 4). Escape closes the focused sticky. The window stays fixed while the page scrolls.
3. **Numbered in order (B10)**: the paper's note keeps `stickyCount`; a new sticky is `N = stickyCount + 1`; the number never changes afterwards (deleting a note's text leaves the number).
4. **Saved into the paper's note as written (B8) — the data model (ruling §1h.78 (f))**: `Block` gets `anchor?: NoteAnchor` with `NoteAnchor = { paperId: string; paragraphId: string; quote: string /* ≤ 300 chars, the passage's start, for the tag and the square */; n: number }`; `Note` gets `stickyCount?: number`. A sticky note is stored in the paper's reading note (`ensureReadingNote` makes it if absent, from the existing template, without navigating) as **one `h3` block `Note N` carrying `anchor`, followed by its text as `text` blocks** (one per paragraph the reader typed), appended at the end of the note; typing writes through (debounced ≤ 300 ms) into those blocks — the sticky edits its own blocks, never others'. The quote is never a block's text, so no export carries it (the test in `export.ts`). Reload: the sticky windows are closed, the note holds everything.
5. **The anchor (B11)**: `note-tags.tsx` draws, after the paragraph a sticky was taken on, a small superscript tag `[N]` in the label face (one per sticky on that paragraph) that opens that sticky; `page.tsx` passes the paper's note's anchors to `PaperBody` as `noteAnchors`. In the sticky and in the note editor's `h3` with `anchor`, a small blue square (≥ 12 px, `aria-label` "Go to the passage", a button) at the left of the text scrolls the paper to `paragraphId` (`document.getElementById` → `scrollIntoView`, then a brief highlight of the paragraph by a class for ~1.5 s) — from the reading page; on the notes page (no paper) it navigates to the paper's page with `#<paragraphId>`.
6. **The stack (B9)**: `lib/reader/windows.ts` is a tiny store of the open floating windows at the right (`{ id, kind: "sticky" | "notes" | "explain", title, order }` with `open`, `close`, `raise`); `StickyNotes` (the component that renders the open stickies) places them from the top of the column down, each later window offset by its header's height (~40 px) so that only the headers of the ones behind show, the raised one in front and full; clicking a header raises it. The explain window and C P10-09b's notes window are not in the stack this round (they stand by their own rules; round 2 joins them — leave the `kind`s in the type).
7. **Nothing else changes**: the explain box, the notes page, the export's content, the Saved page, the thumb bar, the keys.
