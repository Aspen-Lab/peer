## The fact

For a supplement reading (a reader's own PDF attached to a public paper), `buildReading(paper, fullText)` takes the captions and their pages from the upload's text but writes each picture URL with the public paper's id, so the figure-image route renders the public PDF's page — which may be another version with other page numbers, or no PDF at all (then the caption shows alone).

## The rule (§1h.67)

`buildReading` takes the id the figures are drawn from as an option (default: the paper's own id, as today); the supplement branch passes the upload's id (`upload:<hash>`), so every picture URL of that reading is `/api/papers/upload%3A<hash>/figure-image?page=P&fig=N` — answered only to its owner, `private, no-store` (P9-29's route). A plain public reading and an upload's own reading are byte-identical to today.
