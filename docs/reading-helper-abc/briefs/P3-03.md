# P3-03 — paragraph gists: one Peer line per paragraph in the map, condensed from the paragraph's own opening, grounded or dropped

Role: C. Rulings §1h.6 (this item), §1a.8 (the user's decision: a paragraph's opening is its first sentences; Peer's gist is in addition, never instead), §1f.12 / §1f.21 (the map: one line per paragraph, the opening verbatim), §1f.17 (Peer's words labelled with `PEERS_READING`; the paper's words through `EvidenceQuote` or `MathText`, never restyled), §1g.4 (a server memory keyed by the document, never by the reader), §1g.9 (how a small-tier call is gated; this one is not charged against the deep-report allowance — a gist pass is one small call per document, counted in the debug log only), §3d 5 (the Tier 2 half), §3d 17. Last C item of P3 before P3-04 (A).

Setup: `git pull --ff-only origin deep-report-reading-helper-enhancement`; read `lib/papers/reading-map.ts` (`ReadingMap`, `ReadingMapSection`, `ReadingMapParagraph { index, opening }`, `buildReadingMap`, `openingOf`, `readableSections`), `components/reader/reading-map.tsx` (the paragraph line — the anchor to `paragraphAnchor(k, line.index)` holding `<MathText text={line.opening} />` — and the row's folding), `components/reader/use-reading.ts` (the per-paper localStorage pattern: `STORAGE_KEY`, a version, a key per paper and upload revision, every touch in try/catch, pruned), `lib/papers/explain.ts` (`createExplainCache` — reuse its shape for the gist memory; `explainDocHash`; `parseModelJson`; `EXPLAIN_CAPS`), `app/api/papers/[id]/explain/route.ts` (the gating sequence to mirror: owner checks, `requireEntitledAiRequest`, `resolveProvider`, `getFullText`, `no-store`, the debug line with sizes only), `lib/papers/evidence.ts` (`normalizeForMatch`), `components/reader/copy.ts` (`MAP`, `PEERS_READING`), the copy grep in `route-tint.test.tsx`.

What to build:

1. **`lib/papers/paragraph-guide.ts`** (pure): `gistCandidates(doc)` → the paragraphs the pass is asked about: for each rendered section (`readableSections`) and each paragraph with a non-null opening (`openingOf`), `{ sectionId, sectionIndex, paragraphIndex, opening, paragraph (clipped to 1,200 characters at a word) }`; `tooManyParagraphs(doc)` = more than 120 such paragraphs (the pass is skipped, the client asks nothing); `buildParagraphGuidePrompt({ paper: { title }, candidates })` → system + user prompt: the task is one gist of at most 12 words per paragraph, condensed from that paragraph's opening (named in the prompt as its topic sentence) and the paragraph's own text, in plain words, no new facts, no numbers the paragraph does not state; the schema `{ gists: [{ sectionId, paragraphIndex, gist }] }`; nothing about the reader is a parameter; the prompt is bounded (the candidates in document order, each ≤1,200 characters; ≤120 of them). `sanitizeParagraphGuide(raw, candidates)` → `{ [sectionId]: { [paragraphIndex]: gist } }` keeping only entries that name a candidate, `gist` cleaned, whitespace collapsed, ≤12 words and ≤120 characters (longer ones dropped, not cut), anything else dropped. `groundedGist(gist, paragraph)` → true when the gist shares at least two content words (≥4 letters, not in a small stoplist, compared through `normalizeForMatch`) with the paragraph; `verifyParagraphGuide(guide, candidates)` drops every gist that is not grounded. The wire type `ParagraphGuide = { docHash: string; gists: Record<string, Record<number, string>> }`.

2. **`POST /api/papers/[id]/paragraph-guide`** (`dynamic = "force-dynamic"`, `maxDuration = 60`): body `{ paper, llmOverride? }`; the owner checks, the gate (`requireEntitledAiRequest("paragraph-guide", 20)`) and the provider exactly as the explain route (a provider that cannot write → `200 { unavailable: true }`); `getFullText`; no document → unavailable; `tooManyParagraphs` → `200 { skipped: "too_many_paragraphs" }`; the server memory keyed by `explainDocHash(doc)` (a `createExplainCache`-shaped memory of its own, ≤32 documents, 1 hour) → a hit answers `{ guide, cached: true }` with no model call; else one `generateJsonText({ maxTokens: 1600, tier: "small" })`, `parseModelJson`, sanitise, verify, the upload-revision re-check (410, nothing cached), cache, `{ guide, cached: false }`; a failure or nonsense → `{ unavailable: true }`. One debug line per model call with sizes only (`promptChars`, `answerChars`, `paragraphs`, `kept`, a hashed user id). Not charged against the deep-report allowance; no explain tenths either (a gist pass is one small call per document per hour across all readers — say so in a comment).

3. **The client**: `components/reader/use-paragraph-guide.ts` — asks once per paper when the reading has a body, the reader has a model (`aiAvailability(...) !== "none"`, the page's `providerConfigured`) and no guide is kept: a per-paper localStorage memory `peer-paragraph-guide-v1` (key: paper id + upload revision; a day; every touch in try/catch; pruned to 24 papers) → `{ guide | skipped | unavailable, at }`; a kept `skipped` or `unavailable` is not asked again for a day; one in-flight request per paper, never two; aborted on unmount. The hook returns `gists` (the record) or undefined.

4. **The map** (`reading-map.tsx`): a paragraph line gains, after the opening (`MathText`) and on the same line when it fits, Peer's gist in the label face with the `PEERS_READING` mark beside it — `<span className="annotation …">{gist}<span …>{PEERS_READING}</span></span>` — only when a gist exists for `(section.id, line.index)`; the opening is never replaced, shortened or restyled; a line without a gist is byte-identical to today's. `ReadingMapView` takes `gists?: ParagraphGuide["gists"]`; the page passes the hook's result.

5. **Copy**: `MAP.gist` (the accessible name for the gist span, e.g. "Peer's gist") in `copy.ts`; the copy grep covers it.

6. **Tests** (no real model call; a counting provider stub): `paragraph-guide.test.ts` — candidates (only paragraphs with an opening; the clip; the 120 rule), the prompt (the title, each candidate's opening named as its topic sentence, bounded, nothing about a fake reader), sanitise (12 words, 120 characters, unknown paragraphs dropped), `groundedGist` (two shared content words; stopwords and short words do not count; a gist with no shared word dropped), the three committed fixtures each yield candidates and `tooManyParagraphs` is false for them. The route — the gate, a provider that cannot write, no document, the skip, a hit with no model call, the 410, the debug line's keys, no paper text in `console.*`. The hook — asked once, not twice; not asked without a model or a body; a kept `skipped` is honoured for a day; aborted on unmount (the pattern of `use-model-report.effects.test.ts`). The map — a gist rendered after the opening with the label; the opening unchanged; a line without a gist byte-identical to the current render (pin it against the `renderToStaticMarkup` of today's output). The copy grep.
