## The rules

1. **A Peer-words passage is explained in the paper's context.** For `source: "summary"` or `"answer"` the route does not call `locatePassage`; the prompt carries the passage as "Peer's own words about this paper" with the paper's abstract and the map's one line per section as context (the same context budget as a paper passage; the passage ≤ 1,200 characters); the first answer keeps its two parts — "What it means" and, for "Why it is here", why Peer's summary or answer says it, with a verified quote from the paper when the model gives one that verifies, else the prose labelled as Peer's reading and no quote (the existing path for an unverifiable quote); follow-ups as now. The cache key includes `source` so a paper passage and the same words selected in the Summary never share an entry. A passage that is neither in the paper nor marked with a source still gets 422 (the guard stays for the paper source).
2. **Nothing per-user and nothing new leaves the browser**: the request carries what it carried plus `source`; the privacy page's "Explain this" sentence says a selection in the Summary or an answer sends that selection and the paper's context the same way (re-aimed pin named) — only if the current sentence would be untrue otherwise.
3. **The selection buttons offer "Explain this" only when the page can explain** (P10-08's unsettled 2): with no key and no paper-defined term inside the selection, the pill shows "Take notes" alone; with a key, both; with no key and a defined term, both (the Tier 0 definition).
