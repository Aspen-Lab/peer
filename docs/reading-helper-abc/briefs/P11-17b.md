## The rules

1. **Highlight on the page** (`page.tsx`, beside `takeNote`): `const highlight = useHighlight({ paper, questions: settledQuestions(asked), forYourQuestions: report?.forYourQuestions, body: reading?.body })`; `SelectionToolbar` gets `onHighlight={highlight}` and `canHighlight={canHighlight(explainTarget)}`; `selectionActions(() => explainTarget, { note: takeNote, highlight })` so `h` and the thumb bar's cell call it. Highlight is offered for every selection in the paper's body **with or without a key** (Tier 0; never gated by `canExplain`), never for a Summary or an answer selection (D8).
2. **The strip in the margin.** A new `web/src/components/notes/highlight-strip-host.tsx` (`HighlightStripHost({ paperId })`), mounted once in `page.tsx` beside `<FigureHost …/>`, keyed by the paper: while `useHighlightStrip` names a highlight and `useMarginRect()` is not null, it renders `HighlightStrip` with `noteId` = the paper's reading note (`readingNoteFor`), `blockId`, `left` / `width` from the margin rect, and `top` = the mark's first line **now**: it re-reads `mark[data-highlight="<id>"]`'s first client rect on scroll and resize (one rAF per frame), so the strip stays level with its mark, and hides the strip when the mark is more than one screen away (B P11-04 §5) or gone. `PaperBody` gets `onHighlightClick={(id, rect) => useHighlightStrip.getState().show(id, rect.top)}`. Below 1024 (no margin rect) there is no strip; the mark is still drawn and the colour is changed from the notes window. The strip stands where the three actions stood (C P11-13's margin placement for the same line); if a card in the stack covers that line, the strip follows the rule the actions follow there (O-2) — say which in the checkpoint. A new selection, Esc and a click elsewhere hide it (`useStripClose`, already built).
3. **The blue square for a Summary or an answer note (defect (c), second half).** Take notes on a Summary or an answer selection anchors by the selection's own `paragraphId` and `source` (P11-14), but those blocks carry no element id, so the note row's blue square scrolls nowhere. Give the Summary's and the answers' blocks stable, unique ids that match what the selection reports (where the selection's id is made, `block.id || container.id || kind`, and where the blocks render — `page.tsx`, `paper-words.tsx`, `for-your-questions.tsx`; or a `source` rule in `note-tags.tsx` if ids cannot match — say which and why). The square then scrolls to that block and flashes it, as for a body paragraph.
