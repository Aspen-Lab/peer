## The rule (B §4, variant B — §1h.49 (b); do not combine with A or C)

A request to focus a line belongs to the render that adds that line: it travels with the lines as **state** set in the same batch, never as a ref another render's effect can read and clear. `const [focusLine, setFocusLine] = useState<{ index: number; caretAtEnd: boolean } | null>(null)`; one `useEffect` keyed on `[focusLine]` focuses `inputs.current[focusLine.index]` and sets the caret at the end when asked; the chip path (~l.400) and the Enter-adds-a-line path (~l.460) call `setFocusLine(...)` instead of writing the ref; the direct `.focus()` for an existing empty line (~l.463) stays. A repeated request is a new object, so it re-fires. Remove `pendingFocus` and the no-dependency effect. Nothing else in the field changes (the settle rules of P5-04 / P7-13 stay as they are).
