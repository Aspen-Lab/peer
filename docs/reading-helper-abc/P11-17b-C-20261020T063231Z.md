## 2. The rules as built

**Rule 1 — Highlight on the page.** `page.tsx`, beside `takeNote`: `const highlight = useHighlight({ paper, questions: settledQuestions(asked), forYourQuestions: report?.forYourQuestions, body: reading?.body })`; `SelectionToolbar` gets `onHighlight={highlight}` and `canHighlight={canHighlight(explainTarget)}`; `selectionActions(() => explainTarget, { note: takeNote, highlight })` registers `h` and the phone's Highlight cell. Offered for every selection in the paper's body **with or without a key** (`canHighlight` never reads `canExplain` or the key; a test pins that), never for a Summary or an answer selection (D8: `canHighlight` is false there, and `h` on one leaves the selection and makes nothing).

**Rule 2 — the strip.** New `highlight-strip-host.tsx`, `HighlightStripHost({ paperId })`, mounted once after `<FigureHost/>`, keyed `highlight-strip:<paper id>` (not the stickies' key, not the figure host's), outside the zoom container and the section links. While `useHighlightStrip` names a highlight and `useMarginRect()` is not null it renders `HighlightStrip` for `readingNoteFor(...)`, `left`/`width` from the margin (8 px in, the margin's width less 16), and `top` = the first client rect of `mark[data-highlight=id], mark[data-highlight-part=id]` **now**: measured after every commit and, on scroll (capture), resize, each change of the window stack, in one `requestAnimationFrame` at a time repainted with `flushSync`, so it is level inside the frame of the scroll. Below 1024 there is no margin rect and no strip. `PaperBody` gets `onHighlightClick={(id, rect) => useHighlightStrip.getState().show(id, rect.top)}`.
- **The strip goes (B P11-04 §5)** when the mark is more than one window (`AWAY_SCREENS = 1`) beyond the window's top or foot, or is gone from the page; the store is cleared (scrolling back does not bring it up, a click on the mark does). Up to that distance it is held at the band's edge (`placeInMargin`), as the three actions are.
- **A card in the stack covers that line — which rule: O-2 / D4, the one the actions follow.** The strip uses the toolbar's own constants and functions (`CARD_SLACK_PX` 4, `MODE_HYSTERESIS_PX` 12, `clearanceFrom`, `openCardRects`, `toolbarPlace`): where an open card comes within 4 px of the place it would have in the margin it stands **above the mark's first line, left-aligned with it, 6 px clear** (the pill's place), and returns to the margin only when the card is 12 px further clear. With no room above it goes.
- **Escape.** `HighlightStrip`'s own listener hides the strip but does not take the key, and on a paper page Escape is "back to the briefing" (`keyboard.tsx`, on `window`, which does not look at `defaultPrevented`). The host takes the key while a strip stands (`takeStripEscape`: document, bubble phase, from the moment it mounts, leaves a handled key and a modal dialog) — measured: Escape hides the strip and the URL stays the paper's.
- A new selection and a click elsewhere hide it (`useStripClose`, C P11-07's; measured, §4.1). The host hides the strip when it unmounts (the paper changes).
- The place is told to React by a small store, not by a state set in an effect: `react-hooks/set-state-in-effect` is an error on this lint.

**Rule 3 — the blue square for a Summary or an answer note.** Ids, not a `source` rule: the selection reports `block.id || container.id || kind` and the square reads the element with that id, so one string cannot drift from the other; a `source` rule would only have found the container, which has no box (`contents`), and not the block.
- `paper-words.tsx`: `SUMMARY_ID` (`summary-skim`, `-claim`, `-abstract`, `-tldr` and the report's eleven: `-new-here`, `-proposal`, `-method`, `-results`, `-for-you`, `-glance`, `-related`, `-caveats`, `-next-step`, `-record`, `-library`; constants, never positions: the Summary is regenerated) and `SummaryBlock` (a plain `div` around a block, nothing around nothing). `for-your-questions.tsx`: the section is `id="answers-block"`. `page.tsx` wraps each report block in `<SummaryBlock id={SUMMARY_ID.…}>`; every direct child of the Summary's container is wrapped or carries its own id (a test reads the source and fails on a stray block).
- `note-tags.tsx`: `goToPassage` brings the right tab back. A Summary block (`summary-` prefix) asks the page's Summary host (`registerSummaryHost`, filled by `useSummaryHost`, which `page.tsx` calls beside `useReaderTab`: it runs the jump at once with the Summary on show, else shows the Summary tab and runs it once after the render that put the blocks on the page). A paper paragraph asks the paper's host as before. The answers' block stands under both tabs: it asks neither (a tab switch there would take the reader off the tab for nothing).
- `scroll-mt-20` on every block the square scrolls to (a body paragraph keeps 80 px; without it the block's top stood at y = 0 under the 48 px masthead).

## 6. For the manager

1. **The notes page's square for a Summary or an answer note does not reach the block.** `/notes/<id>` has no paper on show, so `goToPassage` navigates to `/papers/<id>#summary-proposal`; the paper opens on Paper digestion (default), where the block is not on the page, and `passageFromHash` (`sticky-note.tsx`, not mine) only knows `paper-section-N-pM`. Measured: URL `/papers/…#summary-proposal`, tab "Paper digestion", `scrollY` 0. A fix is an arrival rule (hash `summary-…` / `answers-block` → show the Summary tab, scroll, flash) in `sticky-note.tsx` or `use-reader-tab.ts`; the in-page square (the notes window) is done. (A sticky with no words is removed when the reader leaves the page — `removeEmptyStickies` — so the notes page shows a Summary note only once words are typed.)
2. **"More than a screen away" is B P11-04 §5 read literally**: one window's height beyond the window's top or foot (held at the band's edge up to there: 850 px above is still held at 1440 × 900, 1000 above is gone). Brief rule 2's measure sentence ("scroll a screen away: the strip goes") is true at "a screen and a bit away", not at one PageDown from a mark in mid-window (318 above: held). If the manager wants it gone the moment the mark leaves the window, `AWAY_SCREENS = 0` is the one constant (`stripStanding` then returns null as soon as the mark is wholly out of view).
3. **Pressing the notes tab (or any press outside the strip) hides the strip** — `useStripClose`'s "a press anywhere else", C P11-07's rule. With the notes window open, the strip is raised again by a click on the mark; it then stands in the margin below the window, or above the mark where a card covers its place (§4.2).
4. **The abstract-only paper's Summary has no selection target at all, by the code** (`useSelectionListener(hasBody && …)` in `page.tsx`, as at the base), so neither Take notes nor Highlight is offered there; I measured its layout only (§4.4), not a selection on it.
5. **Files outside my list were touched, test pins only**: six `page.*.test.ts` files (§3), each because `page.tsx`'s pinned text changed; no source file of another C's.
6. **Things the host does not re-measure on**: a CSS transition of the reading scale / Fit zoom (no scroll, no resize, no commit during it) — the strip catches up at the next commit or scroll; and the empty `<div id="summary-glance">` etc. that stand where a report block draws nothing (zero height, no layout effect, measured).
7. **Order of Escape**: the figure card's listener (mounted first) takes the key before the strip's, so with a front figure card and a strip up the first Escape closes the figure and the second the strip.
8. A harness artefact worth knowing, not a defect of mine: a drag that begins below the fold left `useSelectionListener`'s `down` flag set in my script and the next selections were not read until the page was reloaded; selecting with the paragraph in view always read.
