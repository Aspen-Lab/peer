## The rules, as built

1. **The math** (`figure-zoom.ts`, plain): `FIGURE_ZOOM_STEPS = [1, 1.5, 2, 3, 4, 6]`, `SUMMARY_ZOOM_STEPS = [1, 2]`, `DETAIL_ZOOM = 2`; `clampZoom`, `nextZoom(zoom, steps, ±1)`
   (the nearest step from between steps; the end itself at an end), `zoomAbout(pan, zoom, next, anchor)` (`anchor - (anchor - pan) * next / zoom`, the anchor from the viewport's
   centre), `wheelFactor({deltaY, deltaMode})` (`exp(-deltaY * unit * 0.0015)`, unit 1 / 40 / 800 px for pixels / lines / pages), and the moved `clampFigureSize` / `clampFigurePan`
   (code unchanged). A pan is re-clamped at every size change: `visibleView(view, fit, viewport, steps)` draws the view asked for held to the size NOW (the asked-for view is not
   rewritten, so the pan comes back if the box grows back); `zoomView` = `zoomAbout` + the clamp for the new size. Types `Size`, `Point`, `FigureView`, `FIT_VIEW`, `scaleSize`.
2. **The pointer and keys** (`use-figure-zoom.ts`): `useFigureZoom({ natural, viewport, steps?, wheel?, keys? })` returns `{ size, scale, offset, zoomed, dragging, canZoomIn,
   canZoomOut, zoomIn, zoomOut, reset, toggle, surface, surfaceRef, style }`. Click = `surface.onClick` (swallowed once after a real drag, a cancel or a lost capture; else `toggle`:
   zoomed -> fit, fit -> 2x, pan reset); drag = 4-px threshold, primary button/pointer only, pointer capture, focus taken, clamped; `style` is the lightbox's own
   `{ width, height, transform: translate(x px, y px) scale(z) }`. **The wheel** (`wheel: true`, default false) and **the keys** (`keys`, default true) are NATIVE listeners put on the element
   given to `surfaceRef` (the wheel `{ passive: false }`, because react-dom 19 registers wheel passively); the wheel always `preventDefault`s over the picture (plain, Ctrl/Cmd, pinch; at either end of
   the range too) and zooms about the pointer; `+ =` / `-` step, `0` fits, the arrows pan 48 px (Right moves the picture left, as a scroll would) and are taken even at fit; a key with
   Ctrl, Cmd **or Alt** is never taken, every other key passes. Several wheel events in one frame accumulate (the hook holds the latest view in a ref ahead of the render).
3. **The Summary is as it was**: `FigureViewer` calls `useFigureZoom({ natural, viewport, steps: SUMMARY_ZOOM_STEPS, wheel: false, keys: false })` and spreads `zoom.surface` / `zoom.style`;
   it does NOT give `surfaceRef` to the button (no ref, no listener, no extra render). The frame observer, the capture `keydown` effect (`document.addEventListener("keydown", onKeyDown, true)`,
   `event.stopPropagation(); if (event.key === "Escape") { event.preventDefault(); onClose();`), the focus handling, the portal, the markup and the labels are untouched; `FigureLightbox`'s props
   and closed markup are untouched. Diff of `figure-lightbox.tsx` against the head: the clamps and the pointer code out, the import, the `export`, the hook call, the button's props.

## For P11-15 (the card) — the contract as built, and where it differs from B §2.2

- `useFigureZoom({ natural, viewport, steps?, wheel?, keys? })`: **`keys` is an addition** (default true; the lightbox passes false). The card passes `{ natural, viewport, wheel: true }` and gives `surfaceRef` to the surface `<button>`'s `ref` (the wheel and key listeners attach to that element; the element may mount later than the hook).
  Spread `surface` on the button, `style` on it too. The readout is `Math.round(scale * 100)` (`scale` is the zoom as drawn, 1 = fit). `zoomIn` / `zoomOut` step `FIGURE_ZOOM_STEPS` about the viewport's centre; `canZoomIn` / `canZoomOut` are the ends; `reset` is Fit.
- `viewport` is the box the picture is centred in (net of padding); the anchor of a wheel event is computed from the surface's own rect and assumes that centring.
- A pan is re-clamped as the box changes (a divider drag, the caption's height) without the card doing anything; the zoom and pan live in the hook, so the card's wrapper must stay mounted for them to survive "behind" (B §2.3).
- Safari / Firefox on macOS do not focus a `<button>` on click: the card should focus its surface on open (B §2.3 already says so) or the keys will not work until Tab. The hook focuses the button on a zoomed pointerdown only (as the lightbox did).
- Observed, not caused by this item: the Summary's lightbox is closed by a window resize that crosses the layout breakpoint (1440 -> 1100 x 800 and -> 1000 x 700 closed it; 1440 -> 1300 x 760 did not), i.e. the plate's subtree remounts there. A card must not live in a subtree that remounts at the breakpoint.

## Decisions I took inside the brief (the manager may overrule)

1. Alt joins Ctrl/Cmd as a never-consumed modifier (Alt+Left/Right is the browser's history).
2. Arrow direction: the view moves the way a scroll would (ArrowRight pans the picture left). Step 48 px.
3. The view asked for is not rewritten by a resize (`visibleView` clamps for drawing); growing the box back gives the pan back (measured in Chromium).
4. Ctrl/Cmd + wheel uses the same rate as the plain wheel (B §2.1). A real trackpad pinch sends small deltas, so it will feel slow at 0.0015; unverified without a trackpad. One constant to change (`WHEEL_ZOOM_RATE`) if the owner says so.
5. `deltaMode` lines = 40 px, pages = 800 px (the usual normalisers); Firefox's 3-line notch then equals a 120-px one.
6. One extra commit (`8be072cd`) for rule 3's unit pin, beyond the brief's list; tsc is red on the first two commits only because the hook test imports a hook that lands in the third.
