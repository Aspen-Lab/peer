## Observations (noticed, not changed)

1. **Full-width terminal marks get a period.** The ruling names three marks, `?`, `.`, `!`. A question typed in Chinese or Japanese that ends in `？`, `！` or `。` would read `…？.` or `…。.`. The reader may well write such questions (the chat is in Chinese; Peer's own voice is English-only, the questions are the reader's). Adding the three full-width marks to the regex is a one-line change plus a test; I did not make it because the ruling is explicit.
2. **A trailing `)` or a closing quote after `?`.** `Does it discuss "recycling?"` ends in `"`, so it gets a period: `…"recycling?".` That is a reasonable English reading and I left it; noting it only so the manager knows the rule is "the last character".
3. **`readNextLabel` builds its own `p.${…}`** (`for-your-questions.tsx`) while the attribution now uses `MAP.page`. Both read `p.N`; unifying them is outside the four findings.
4. **The `EvidenceQuote` page tests live in `for-your-questions.test.tsx`.** The natural home is `evidence-quote.test.tsx`, but that file is not in the brief's list, so I kept the work inside the named test files. If the manager wants them moved, it is a copy of one `it` block.
5. **The `page` an answer shows can come from the map's section when the answer has none**, matched by `sectionId`, while the link is matched by `evidenceWhere`. The server sets both from the same located section (§1g.3), so they agree in practice; a hand-built report with disagreeing fields would show one section's page next to another's heading. Not changed.
6. **The bare word "background" no longer stands alone as a map fact line**; `ROUTE.tiers.background` is now only the first half of the with-hits line. The Read next tag uses its own `FOR_YOUR_QUESTIONS.background` and is unchanged.
