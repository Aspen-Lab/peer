## What changed

### `web/src/lib/papers/report.ts`

**`questionAnswers(value, questions)`** now returns `{ entries, unmatched }`.

How entries are matched to questions:
- A question's text is compared normalised: trimmed, whitespace collapsed, case folded. After that the match must be exact; there is no fuzzy matching.
- **Text first.** Every entry whose normalised `question` equals a request question claims that question.
  - A second entry for a question already claimed is dropped and counted.
  - When the request has two questions that normalise the same, the first one's index is used.
- **Then position.** Only entries whose text matches no request question fall back to their position, and only if that position is below the request's count (capped at 5) and still free. Otherwise they are dropped and counted.
- Kept entries come out in the request's order and carry the request's own text.
- An entry with a verdict the schema does not name is still dropped uncounted, as in P2-02: it fails the schema, not the matching.

**The count.**
- `sanitizePaperReport` starts `provenance.droppedClaims` at 0, always, with or without questions. A number the model wrote into its output is no longer carried.
- `basis`, `sourceKind` and `pageCount` are carried as before.
- With questions, it adds `unmatched`.

- **Position fallback.** An entry with unknown text at a free position, 0, takes Q1. The request's text is kept.
