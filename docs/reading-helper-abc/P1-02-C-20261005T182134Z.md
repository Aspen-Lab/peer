### `web/src/lib/papers/reading-map.ts` (additions only; P1-01 code unchanged)

Types:
- `RouteTier`, `RouteSection { tier; hits; evidence?; paragraphs }` and `RouteResult { byQuestion: { question; vague; sections: Record<sectionId, RouteSection> }[]; vague }`, following §3c.

`specificTerms(question)` (§1f.6):
- Takes `tokenize(question)`, keeps the first token per `canonicalize` form, and drops tokens where `isGenericTerm` is true.
- The reported term is the user's token: lower-cased by `tokenize`, otherwise as typed.

`routeByQuestions(map, sections, questions)`:
- A question with fewer than 2 specific terms gives `{ question, vague: true, sections: {} }`.
- Otherwise every map section k gets an entry under `map.sections[k].id`, computed from `sections[k].paragraphs` by `routeSection`.
- Top-level `vague` = `byQuestion.length > 0 && every vague`. With zero questions it is `false`; the ruling does not cover that case, and the page shows no hint with no questions.

`routeSection(paragraphs, terms)` (§1f.7):
- `hits`: `termOccurrences` on `canonicalize(paragraphs.join(" "))`, computed once per section per call. Terms with a count ≥ 1 are kept, sorted by count descending, then by term ascending.
- `paragraphs`: the indices whose `canonicalize(paragraph)` gets a `termMatches` for some term.
- Matching sentences: `splitSentences` over each paragraph; a sentence matches when its canonical form `termMatches` some term.
- Tier:
  - `read` when there are ≥ 2 hits and ≥ 2 matching sentences;
  - otherwise `skim` when there is ≥ 1 hit;
  - otherwise `none`.
- `evidence`: the matching sentence with the highest `scoreSentence(sentence, 0)`. On a tie the earlier one wins (strict `>`). It is verbatim, because `splitSentences` output is a substring of a whitespace-normalised paragraph. It is absent for `none`.
- No TF-IDF, no state.
- Imports: `lib/scoring/tokenize`, `lib/scoring/term-expand` and `./skim`. None of them imports anything from `node:`, so the module is browser-safe. No fetch, no model.

## Question for the manager (applied literally, not changed)

`tokenize` has no question words in its stoplist. "how", "what", "why", "which", "when", "where", "who", "about" and "during" survive, and under §1f.6 they count as specific terms.

Measured: `tokenize("How does LCO degrade?")` gives `["how", "lco", "degrade"]`, so three specific terms.

Effect:
- A one-concept question phrased as a question ("What is LCO?" gives `what`, `lco`) is not vague. It is routed with "what" as a term.
- Any section with "what" in a sentence gets a hit for it, so a section can reach `skim` or `read` on a question word.

I followed the ruling exactly and wrote no test that cements this. A small question-word stoplist local to `reading-map.ts` would fix it, without touching `lib/scoring`, which is off limits. It needs a dated ruling.

## Other notes for A

- Section-level counts use the paragraphs joined with a space, per the amendment. A multi-word variant can therefore match across a paragraph boundary in `hits` but not in `paragraphs` or in the sentences. This is an edge case.
- A `skim` section can lack `evidence` when its only hit spans a sentence boundary (a multi-word variant split by a full stop). The contract allows this: evidence is optional.
- No UI, store or route consumes this yet (P1-03…P1-05). The shared reading response is untouched; this module only reads its argument.
