## 4. The rules as built (globals.css, the 6-09 region only)

Six rules added to the three, same use-site form, each under `.reading-scaled`, each on a `--text-*` token that is a plain px size at the `@theme` block (checked by the test), unlayered like the three:

```
.reading-scaled [class~="text-title"] { font-size: calc(var(--text-title) * var(--reading-scale, 1)); }
.reading-scaled [class~="text-title-lg"] { font-size: calc(var(--text-title-lg) * var(--reading-scale, 1)); }
.reading-scaled [class~="text-display-sm"] { font-size: calc(var(--text-display-sm) * var(--reading-scale, 1)); }
.reading-scaled [class~="text-body-sm"][class~="font-reading"] { font-size: calc(var(--text-body-sm) * var(--reading-scale, 1)); }
.reading-scaled [class~="reading-prose"] { font-size: calc(var(--text-lead) * var(--reading-scale, 1)); }
.reading-scaled figcaption[class~="annotation"] { font-size: calc(var(--text-caption) * var(--reading-scale, 1)); }
```

The comment above them now says three wrap points (it said two), names the P11-48 rule, and lists what does not scale. At scale 1 each is `token * 1`, the token's own size; outside the wrappers `--reading-scale` is not set and no rule matches. Line-heights are unitless (the `text-*` utilities' pairs, `leading-[1.65]`, `reading-prose`'s 1.6), so they follow the size. The measures are in `em`, so the column's character count holds at every step, as the 6-09 text already did.
