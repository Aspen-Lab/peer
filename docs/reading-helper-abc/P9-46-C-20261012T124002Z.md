## 2. The rule as built

**The preferred way worked, so the fallback (record each step's gap and assert against it) was not needed.** `setTimeout`, `clearTimeout` and `Date` are Vitest's fakes (`vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout", "Date"] })` in `beforeEach`, `vi.useRealTimers()` in `afterEach`), and time moves only when the test moves it.

Why it runs under the hook runtime without changing it: `hook-runtime.ts` reads the global `setTimeout` at call time (its `settle()` is five `setTimeout(resolve, 0)`), so the runtime's own steps, the page's 1 ms poll and the hook's 250 ms debounce are all on the one fake clock. `setImmediate` is not faked.

The driver, in the test file only:

- `elapse(ms)` moves the fake clock one millisecond at a time and after each lets one turn of the real event loop pass (`await new Promise(r => setImmediate(r))`), which drains every promise the runtime is awaiting. So a gap in the script is exactly that many fake milliseconds, whatever the machine is doing; a stalled real clock cannot change it.
- `mountAndPlay(hook, play)` mounts, runs `play` (the reader: steps, waits), then ends the poll (`live.over`) and keeps advancing the clock a few milliseconds until the mount finishes its last round (a guard throws if it never does), and returns the mount for the test to unmount.
- `page(script)` keeps its shape and its call sites (`wait(20)`, `key(…)`, `pause`): a function step now runs at its instant, a `wait` is exactly its milliseconds (before, a step took a render round, a few ms, and a wait was rounds of a real poll). Consecutive function steps run at one instant.
- `useKeepAlive(live)` is the old 1 ms poll, minus the script (which the driver now plays).

The three tests that mounted by hand (hydration, unmount's wait, the id change) go through the same driver; nothing in the file reads the real clock any more.
