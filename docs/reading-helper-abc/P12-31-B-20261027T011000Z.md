## Three external candidate experiments — no safe choice yet

The probes change only a private copy of the overlap decision, never repository code. All are counterfactual rules, not recommendations. Invented input has a panel with a connected path extending past a caption; a second invented input puts a typed line just inside a panel; a third puts it deeper inside. The current candidate rejects both the overlapping case and the interior labels.

Each experiment retained expected counts on the sampled existing invented Table veto, genuine same-label tie, above-caption framed multipanel, and two-column cases. This is a small subset, not a full test run or proof of safety. The numerical probes are not proposed thresholds. A C implementation is not yet justified. ## Follow-up: path clipping and neighboring images

This section replaces the in-progress checkpoint only. Earlier results and the three overlap-rule experiments remain unchanged. The new work uses the same source identities, public bytes and Node 22.23.4; it adds no UI, upload, dependency, product change or full test run.

**Observed mechanism.** On page 14, all 54 collected fill-path boxes that extend beyond the typed caption's top are subject to four nested path clips. Their effective clip bounding-box intersection ends at y=603.954, while the typed line starts at y=615.082. On page 15, all 135 such boxes are fills under four nested path clips whose effective intersection ends at y=592.071, while the typed line starts at y=603.199. Thus the finite examples' lower overhang is clipped away before the page is painted, with an 11.128 pt gap to the typed line. These are transformed page-space coordinates. In representative offending paths, the transform matrices are `[1.255,0,0,-1.255,108,603.954]` and `[1.245,0,0,-1.245,108,592.071]`. The engine's walked control-point bounds and MuPDF native fill bounds agree for the representatives; these offending paths are fills, so stroke-width inflation is not their cause. The complete path events, transforms, bounds, operation and nested clip records are in `path-trace.json`.

A separate paths-only raster forwards path painting and the original active clips and groups to a draw device at 1 pixel per point. In each page, scanning x=108–503 and the 25 pixel rows starting at the ceiling of caption top finds zero nonwhite pixels from the painted paths. Text and images are omitted from this particular raster, so this is evidence about path painting, not a substitute for the complete page render. `paths-pixels.json` and `paths-only-14.png` / `paths-only-15.png` retain the measurements. The source-page and baseline crops from the earlier section remain the whole-content comparison. In this sample the overlap driving the rejection is an unclipped bounding-box artifact, not a painted path crossing the caption.

**Bounded counterfactual, not a patch.** An external probe intersects each collected path's box with active path-clip bounding boxes before clustering, without changing caption matching, floors, padding or product files. It yields page 14 `[121.98,146.19,503.74,603.95]` and page 15 `[120.79,158.07,499.35,592.07]`. Inspection of `clip-probe-4.png` and `clip-probe-5.png` against source pages shows the visible panels and no clipped caption in those sample crops; this is not a universal completeness proof. Captions remain 266 and 269 characters respectively. In invented examples the same probe recovers a clipped-extension caption, rejects a real path crossing its typed line, rejects an interior typed label, selects the proper figure with a nearby Table, and preserves the sampled same-label tie, above-caption framed multipanel and two-column outcomes. The baseline candidate erroneously groups the clipped-extension Table example with the lower figure, demonstrating a second measured collateral effect. These are bounded samples, not a full regression suite.

The first private probe accidentally discarded horizontal and vertical zero-width path boxes. It was corrected to retain degenerate lines and rerun before these results; the genuine-crossing negative then remains absent. `clip-comparison.json` records the corrected outputs. The external probe only tracks path clips and does not correctly model every clip form or graphics state; its code must not be copied as a complete implementation. Bounding rectangles of nonrectangular clips can overestimate visible pixels. Strokes require conservative treatment of actual stroke width, transforms and joins; masks, text clips, images, clip stack and graphics groups require their own correct handling. No numerical overlap allowance is justified.

A bounded C investigation may use `web/src/lib/figures/pdf-engine.ts` and `web/src/lib/figures/pdf-engine.caption-pairing.test.ts` to test whether conservative active-clip-aware path collection can fix this mechanism. Require invented nested clips, transformed fill and stroke cases, un-clipped zero-width lines, genuine painted overlap and interior labels, nearby Table veto, same-label tie, above/below/two-column/multipanel positives, complete caption text and full source content in rendered crops. Preserve every resource limit and derived-cache freshness guard; fail conservatively on unsupported clip/mask states rather than assuming no clip. Independently compare whole-page content and run the existing fixture suite and manager UI verification before any landing decision. This is a testable direction, not authorization to relax pairing or a claim that the prototype covers every PDF graphics state.
