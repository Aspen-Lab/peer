## 2. The rules as built

**Routes.** `/api/saved` POST and `/api/feedback` POST answer `400 { error: "unsupported itemKind" }` for any kind but `"paper"` (after the 401 and the missing-field 400, before any write): a refusal, not a quiet 200, so a stale tab on the old bundle shows its one push-failed warning (B's default). `GET /api/saved` filters `item_kind = 'paper'` in the query. `DELETE /api/saved` is unchanged (it deletes by id; it reads nothing). Rows of kind event / job that older builds wrote stay in Supabase (R3); nothing reads them.

**Store (`store/feed.ts`).** Removed: the events and jobs lanes of `loadFeed` (two `fetch`es, two lane blocks, the two dismissal-id sets), `opportunityRequestBody`, `fetchRealEvents`, `fetchRealJobs`, `OpportunityClientPool`, `activeSurfaceTopics` (now `activePaperTopics`), the completion-stamp helpers (`withCompletionPayload`, `completionMap`, `payloadTimestamp`); the **15 state fields** `events`, `jobs`, `eventPool`, `jobPool`, `eventFacetCounts`, `jobFacetCounts`, `savedEvents`, `savedJobs`, `eventsLoading`, `jobsLoading`, `appliedAt`, `registeredAt`, `submittedAt`, `eventFeedback`, `jobFeedback`; the **11 actions** `saveEvent`, `notInterestedEvent`, `moreLikeEvent`, `saveJob`, `notInterestedJob`, `moreLikeJob`, `unsaveEvent`, `unsaveJob`, `setJobApplied`, `setEventRegistered`, `setEventSubmitted`; the event / job branches of `undoDismiss`, `commitDismiss`, `hydrateFromRemote`, `applyMigrationPushResult` (its `pushed` argument is now `{ savedPapers, readIds }`), `resetLocal`, `retryPendingPushes`. `ItemKind` is `"paper"`; `PendingDismissal` is `{ kind: "paper"; item: Paper; … }` (`wasInPool` gone); `submitFeedback` sends feedback for `type === "paper"` and for nothing else. The imports of `lib/events/types`, `lib/jobs/types`, `lib/opportunities/facets` and the event / job ledger snapshots are gone from the file. The pending-key format is untouched (`saved:paper:<id>`, `feedback:paper:<id>`, `read:<id>`), so no paper outbox entry is orphaned.

**Persisted keys and the migration.** `partialize` no longer writes `savedEvents`, `savedJobs`, `eventFeedback`, `jobFeedback`, `appliedAt`, `registeredAt`, `submittedAt`. The store is **version 4**; `migrate` has one new last step (`version < 4`): it deletes those seven keys and the old shared `oppFeedback` map from the blob, and from every owner record of `pendingPushByOwner` and `pendingFeedbackPayloadByOwner` it deletes the entries whose key starts `saved:event:`, `saved:job:`, `feedback:event:`, `feedback:job:` (the payload snapshots, which held titles and companies, go with them). A malformed outbox (null, not an object) is returned as it came; a blob with nothing of theirs comes out equal. The old version 0 → 1 step (which split `oppFeedback` into `eventFeedback` / `jobFeedback`) is gone with its subject: `oppFeedback` is dropped. The v2 → v3 `deliveredLocal` step is unchanged. Nothing in the migration touches a ledger: **no ledger entry was edited, and no `origin` was dropped** (C3's, deleted whole on clean).

**Sync (`feed-sync.tsx`).** The two halves of the sign-in sync are exported for headless tests (the repo has no effect-mounting test harness): `pushLocalSignals({ savedPapers, readItems })` — pushes saved papers (`itemKind: "paper"`) and read marks only, reading only those two fields — and `savedPapersFromRows(rows)` — keeps rows of kind `paper`, `null` stays `undefined` (a failed pull) and `[]` stays `[]`. `onSession` calls them; `applyMigrationPushResult` and `hydrateFromRemote` no longer get event / job arguments. `SavedApiRow.itemKind` is `string`, so a row an older server still sends is recognised and dropped.

**Stale comments fixed** in these files: `store/feed.ts` "Omitted means all three" (B: `:1164-1169`) and the comments that narrated events / jobs lanes, standing pools, `searchConnectors` ("events and jobs still need it… `opportunityRequestBody` is where it is still sent"), the outbox payload capture ("an unsaved event/job"), `feed-sync.tsx`'s four-source comment.
