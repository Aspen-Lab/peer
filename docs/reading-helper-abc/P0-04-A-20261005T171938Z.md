## Findings, ranked

### F1 — HIGH (privacy) — a case-variant upload id bypasses the owner check and lands private text in the shared cache

- Where:
  - `web/src/lib/papers/full-text.ts:368`: `if (input.paperId.startsWith("upload:"))` is case-sensitive.
  - `web/src/lib/papers/upload-store.ts:54-56`: `bareUploadId` matches `/^upload:([0-9a-f]{16})$/i`, which is case-insensitive.
  - `web/src/lib/papers/full-text.ts:261` (`buildResult`): any id `bareUploadId` accepts is read from disk with `tryUploadLink`. With `UPLOAD:…` that read runs on the shared path at `full-text.ts:376-389`: no `ownedUpload` call, and the result is stored in `cache` under the key `UPLOAD:<hash16>`.
  - `web/src/app/api/papers/report/route.ts:322` (`paperPrivateUploadHash`): `paper.id?.startsWith("upload:")` is case-sensitive, so the route's own owner check (`:600-606`) is skipped too.
- Reproduction 1 (unit, real pdf.js, `p1-upload-path.probe.test.ts`): `ownedUpload` is mocked to refuse everyone. `getFullText({paperId:"upload:<h>"})` gives `source_unavailable`. `getFullText({paperId:"UPLOAD:<h>"})` gives `ok`, and its sections contain a word that exists only in the private PDF. `ownedUpload` is called once (only for the lower-case call). After the PDF is deleted from disk, the `UPLOAD:<h>` call is still `ok`, served from the shared cache. 1 pdf.js open in total.
- Reproduction 2 (route, `p2-routes.probe.test.ts`): only the cookie jar, the model registry and the model passes are stubbed. Owner A uploads through the real upload route. A stranger with a different capability cookie POSTs `/api/papers/report` with `{paper:{id:"UPLOAD:<h>",title:"x"},deepReport:true}`. With `Accept: application/json` the answer is 200 and the deep pass's `doc` contains A's private word. With `Accept: application/x-ndjson`, what the client always sends, the answer is 200: `mode:tier2 … report`, same leak. The lower-case `upload:<h>` request from the same stranger gets 404 "Upload not found.".
- Expected (§1b, §3d 17, and the P0-02 checkpoint's own claim that "the shared public `cache` Map … never sees an upload"): a non-owner gets "not found"/"unavailable", and no upload text enters the shared cache. Observed: a deep report built from another owner's private PDF, plus a 1 h shared-cache entry for it.
- Preconditions: the attacker must know the victim's hash16. It is owner-salted (`privateUploadHash`), so it cannot be guessed from public PDF bytes, but it appears in page and file URLs. In production the attacker must also be signed in, and the call charges the attacker's deep-report quota.
- Provenance: identical code at the baseline `ed189e1` and at `74e81ae`, so this predates P0. P0 neither introduced nor fixed it.
- Direction (one line): decide "is this an upload id" in one place, with the same case rule, for `getFullText`, `buildResult` and `paperPrivateUploadHash` (or reject any non-canonical upload id).
