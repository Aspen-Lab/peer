## 1. The rules as built

**Rule 1 — X13, never on the words (commit 1).** `placeButton(rect, viewport, paragraph?, bounds)` returns `ButtonPlace = { left, top } | { edge, bottom }`. The gutter branch is unchanged (`viewport.width − paragraph.right ≥ BUTTON_WIDTH + 2·BUTTON_MARGIN`: `{ left, top }`, A measured it clean from 768 up). Where it cannot place the control — no gutter, no paragraph reported — it no longer falls back to "under the selection's end": it returns the **furniture's** place: `edge` = the column's right edge (`paragraph.right`, else the window's margin: `width − 8`), clamped to `[128, width − 8]`; `bottom` = **under 768 px** `calc(56px + env(safe-area-inset-bottom) + 8px)` (the thumb bar's height as the bar sets it, `THUMB_BAR_HEIGHT`, then 8 px) and **from 768 px** `legend + 8` px (28 + 8 = 36 at zoom 1). `buttonStyle(place)` turns a corner into `{ left, top }` and the furniture into `{ right: "calc(100% - <edge>px)", bottom }`, `position: fixed` as the control already was. Nothing in the furniture's place reads the selection's rectangles or the page's scroll (`rect` / `bounds` are not read; `edge` comes from the paragraph's right edge, which does not move with the scroll), so the pill **stays put while the selection stands and goes with it** (`ask` is rendered only while `next && askAt`, as before; pinned). `explain-dock.ts` gains `THUMB_BAR_PX = 56`, pinned against `thumb-bar.tsx`'s own `THUMB_BAR_PX`, its `h-14` cells and its `calc(${THUMB_BAR_PX}px + env(safe-area-inset-bottom))`, and the swap pinned against both components' classes (`md:hidden fixed … bottom-0` / `hidden md:flex fixed … bottom-0`).
Why CSS `bottom` and not a `top` computed from `innerHeight`: the bar is `fixed bottom-0` and grows with the safe area; a `bottom` keeps the pill 8 px above it whatever the browser's toolbars or a future `viewport-fit=cover` do, and the toasts (`undo-toast.tsx`, `reader-toast.tsx`) stand above the bar the same way.

**Rule 2 — BACKLOG-44, a region (commit 2).** `ExplainCard`'s root is `role="region"` with its existing names (`aria-label` "Explain this?" while empty, "Explanation of the selected passage" with a passage); never `role="dialog"`, never `aria-modal`; the focus was never trapped. **`region`, not `complementary`**: the box mounts inside the page's `<main>`, where a complementary landmark is flagged by axe's `landmark-complementary-is-top-level` and a named region is not; and the card and the sheet are the same content in another place, not a sidebar.
