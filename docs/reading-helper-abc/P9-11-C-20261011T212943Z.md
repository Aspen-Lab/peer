## 1. The rule as built (B §4, variant B — §1h.49 (b))

A request to focus a line belongs to the render that adds that line: it travels with the lines as **state**, set in the same batch, never as a ref another render's effect can read and clear. In `web/src/components/reader/question-field.tsx`:

- `pendingFocus` (the `useRef`) and the effect with no dependency array are gone.
- `const [focusLine, setFocusLine] = useState<{ index: number; caretAtEnd: boolean } | null>(null)` and one `useEffect(..., [focusLine])`: if there is a request and `inputs.current[focusLine.index]` exists, `focus()` it and put the caret at the end when asked.
- The two writers call `setFocusLine({ index, caretAtEnd: true })` instead of writing the ref: the example tag that adds a line (`onChip`) and the Enter that adds a line (`onKeyDown`). A repeated request is a new object, so it fires again.
- The direct `inputs.current[added.focus]?.focus()` for an Enter that lands on an existing empty line stays. The settle rules of P5-04 / P7-13 are untouched. A comment above the state says why (the stale commit's effect).

Why it closes the race: an older commit's effect closes over an older `focusLine` (null) and, its dependency unchanged, does not run again; the effect that runs is that of the commit where `focusLine` changed, together with the lines and after the refs are attached.

## 4. Mutations

1. **The brief's example, the dependency array removed** (`}, [focusLine]);` → `});`): the eight tests of B stay **green** — the state-keyed design does not need the array to survive the stale-effect case, because each commit's closure carries its own request. What the array still guards is real: an effect with no dependency would read the request after every later render and pull the focus back to the line Enter had opened, whatever the reader did since (a click back on line 1 would be undone at the next render). Nothing pinned that, so commit 3 adds one test; with the array removed it is the only red (**1 red / 8 green**, `expected 1 to be 0`), with the array it is green.
