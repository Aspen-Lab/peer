## 3. The rules as built (ruling §1h.155)

**Rule 1: Highlight is offered only where it makes a mark.** A selection whose two ends are in two blocks of one Summary or answer container (what `readSelection` computes as `oneBlock: false`) is not offered Highlight. It is still a target, and still offered Explain this and Take notes, exactly as before (the P10-08 pin stands: it is a target up to 1,200 characters, none above).

**The field I chose: `spansBlocks?: true`, on the `ExplainSelection` type** (the target the page already hands to `canHighlight`). `readSelection` sets it from the `oneBlock` it already computes (`endsAtNextStart || start.id === end?.id`, now a named constant), only when `oneBlock` is false: `...(oneBlock ? {} : { spansBlocks: true as const })`. The key is absent, not `false`, for every other selection (pinned). `canHighlight` takes `spansBlocks?: boolean` in its parameter type and returns false first thing when it is `true`. `highlightSelection` already asks `canHighlight` first, so the margin's button, `h` and the phone's cell are all covered by the one check. `selectionTarget` is untouched (it stays the pure "is this a target" decision; its tests pin its output byte for byte). `page.tsx` is untouched: it already passes `canHighlight={canHighlight(explainTarget)}`, and the field rides on `explainTarget`.

**Nothing else reads the field.** `grep -rn spansBlocks web/src` outside tests: the type and the `readSelection` line in `paper-body.tsx`, and `canHighlight` in `highlight.tsx`. `selection-toolbar.tsx`, `sameSelection`, `explain-box.tsx`, the store and the exports do not.

**Rule 2: everything else is unchanged.** A selection inside one block of any length (body paragraph, caption, heading, Summary block, answer), a triple click on a Summary block (the browser ends it at the next block's start; `endsAtNextStart` reads it as one block), the cross-block offering of Explain this and Take notes, the group's place and the strip: pinned in the tests, and identical before and after in the browser (§8).

## 9. Unsettled

1. **`sameSelection` does not compare `spansBlocks`** (the brief: nothing else reads the field). It cannot matter: two reads of the same passage and the same rectangles with the flag differing would need a cross-block selection whose second block adds no words, and a triple click, the one selection that looks like that, is read as one block.
2. **The page's answers are one block.** `answers-block` holds every question's answer, so a selection across two answers is one block to `readSelection` (one id): it is offered the three buttons and Highlight marks it (the paragraph break between two answers is the 3 characters the mark lacks, as on the base). The new flag matters for answers only if the page ever renders two children in the answer container; the two-id case is pinned by a test, and the measured case is pinned as unchanged.
3. **The phone's Highlight cell** follows `offeredActions`, and `h` calls `highlightSelection`: both follow `canHighlight` by the code (the `h` key measured: 0 stored, selection kept). I did not measure at phone width; the brief's matrix is the two desktop sizes.
4. **A sticky on a cross-block selection** keeps its quote (at most 300) and has no range, as any Summary-block sticky (P11-47 §9.1): unchanged.
