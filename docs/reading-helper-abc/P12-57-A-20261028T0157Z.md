## 1. The harness

Path: `/tmp/claude-0/-home-user-peer/9602921a-6ac5-5952-88ce-8364fcd8f733/scratchpad/p12/a57/harness/keyed.mjs` (outside Git, by the brief; about 400 lines). Run: `PORT=4244 PEER_TEST_PDF=<pdf> OUT_DIR=<dir> TAG=P1 node keyed.mjs`. Playwright is `require('playwright')` (found through `NODE_PATH`), `chromium.launch()` with no options.

What it does, in order:

1. First visit, skips the walkthrough. Profile → Edit → provider **Gemini** → the key filled with `page.fill` from `process.env.PEER_TEST_GEMINI_API_KEY` → the **Deep report** switch on (it is disabled until the sign-in check answers; a copy with no sign-in counts as allowed) → Done. It then reads back the profile view line, the stored provider, that a key is present, that it equals the environment value (a boolean), and that the visible Profile text holds no part of it. No screenshot is taken of the Profile; no storage state is saved (it would hold the key).
2. Uploads the paper by path through the real UI (upload square, consent dialog, "Upload PDF"), waits for the reading page, and dumps the **reading map rows** as the page shows them to `rows-initial.json` (when the body appears) and `rows-final.json` (after the keyed calls settle): heading, role tag, level (`data-level`), page, words, minutes, the first paragraph's first 60 characters, the second paragraph's first 60, the body heading, the number of paragraph-id hosts in the body, the number of paragraph lines the map's fold lists, the first of those lines' first 60 characters, and the number of gist lines drawn.
3. Records every `/api/` call in a ledger: method, path (ids replaced), status, start offset from the Upload click, duration, and a **shape** for the model-backed routes (JSON keys; for the gist call, counts of gist sections / gists / partition; for errors, the error text capped at 200 characters). It never stores a request body and never stores paper text.
4. Waits until the gist call and the report stream have both been seen, nothing model-backed is in flight, and 8 s have passed since the last such event; then dumps the final rows, expands every fold to count drawn gist lines, and reads the Summary tab (band labels, alerts, tabs).
5. Probes the structure route: `POST /api/papers/<id>/structure` with an empty body and no key. Today: **404, "absent"**; the page itself never called it. When the route exists the same ledger records the page's own call to it (status, time, shape).
6. Non-local requests are aborted and counted; any request to a non-local host that carries the key in its URL or headers is counted (expected 0). Everything the script writes goes through `scrub`, which replaces any echo of the key and counts the echoes (reported below). A 429, RESOURCE_EXHAUSTED, PERMISSION_DENIED, quota or billing marker in an error answer sets `stopReason` and ends the waits.

Outputs per run, under `OUT_DIR`: `result.json`, `rows-initial.json`, `rows-final.json`, `console.log` (the browser console, scrubbed). `rows-*.json` hold paper text (60-character openings) and stay in the scratchpad, never in Git.

Harness faults found and fixed on the way (all mine, none in product code): the path normaliser folded `/api/papers/report` into the id pattern, so the report call was invisible; the first version settled before the gist answer arrived (run 1's "0 gist lines" below is that, not the product); the row's role, page and words are read from the `data-meta-part` spans (the first version read the wrong nodes and printed no roles); the Profile Edit click is retried because the dev server can reload the page once while it compiles. The report stream's body cannot be read through the browser protocol after the page has consumed it, so the harness takes the report's duration from the request-finished time and its content from the Summary tab and `dev.log`; it does not inspect the report's text.
