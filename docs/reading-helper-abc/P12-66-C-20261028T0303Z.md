## The rules as built

1. **Rule 1 (M2 / M3).** `sticky-note.tsx`: the render-phase branch of `StickyWindow` that follows a store change is now two exported pure functions. `stickyHoldsFocus(active, headerId)` is true when the focused element sits inside the holder `<div data-sticky-editor={row.id}>` that wraps the card's `NoteEditor`. `stickyFollow({ stored, content, writer, held })` is the old branch (pending keystroke: nothing; else `writer.sync(stored)`; if stored differs from what the editor shows: a new content) and returns `{ content, refocus: held }`. The card reads `document.activeElement` in the same render that re-keys, while the old editor is still in the page, keeps it in state (`const [refocus, setRefocus] = useState(true)`, so a new card still opens ready to write in), and passes `autoFocus={refocus}` (was bare `autoFocus`). A reader typing in the notes window keeps the window's caret; a reader typing in the sticky keeps typing in it.
2. **Rule 2 (M3).** `note-editor.tsx`, the `autoFocus` effect only: the part that focuses the first textual block for `autoFocus` is a `useLayoutEffect` (once, on open) instead of the passive effect. `focusBlock` sets state in it; React flushes that update before the paint, and the editor's own layout effect puts the caret in. The editor being replaced and the new one stand in one synchronous turn, so no frame and no key event falls between them. The passive effect keeps the "note just made" branch unchanged, and now returns early for `autoFocus || transient` (see "For the manager", item 2).
3. **Rule 3.** No code of its own: the follow (waiting keystroke never overwritten; the sticky's own write never taken back; a window change taken once idle; the stored blocks as the next base), Save / Delete / Escape handlers and `STICKY_SAVE_MS = 150` are untouched; tests pin them.
