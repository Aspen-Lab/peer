## Three candidate rules and cost

### 1. Explicit bounded segment metadata, strict canonical validation

Send only descriptors of the portion actually being explained: source, block identity, canonical start/end and optionally quote-piece length; derive quote slices from the existing capped passage. Never send full paragraphText or the unbounded full selection. Server validates recognized homogeneous source, actual block identity/offsets, document render order and adjacency, full interior blocks, first suffix/last prefix, exact correspondence to the bounded passage, and formula barriers. Reject whole request if any component fails; no partial answer or arbitrary-text fallback. Keep legacy payload behavior for callers without metadata.

Cost: best occurrence/provenance disambiguation, but highest cross-file/API cost: `paper-body.tsx`/page owned by08, `ExplainBox.asked`, first request, `requestReply`, route request type, validation/frame/cache identity, and local cache identity when applicable. Metadata count/byte limits need explicit caps independent of passage characters. Scratch strict prototype accepted the adjacent group and rejected reverse, skip, forged offset, forged quote, duplicate block, mixed source, passage mismatch, partial first end and partial last start (10/10). This is a small constructed proof, not product-ready normalization or complete render coverage.

### 2. Ordered contiguous canonical range matching, same bounded request

Keep the current request. A dedicated server locator validates the whole clipped normalized passage against a contiguous sequence of canonical **rendered** blocks. It must match a first-block suffix, every intervening block completely, and a last-block prefix, never search each fragment independently. No numerical anchor sort: headings have index P but render before paragraph0; captions have index P+1+k but render after `figure.after`. Recognize only exact caption variants the existing renderer can draw (with or without PDF-page suffix according to image state), and include display/inline formula barriers instead of removing them. Keep source boundaries and existing Summary/answer semantics outside paper-range matching.

Cost: smallest wire/context change and no added model calls. A streaming/memoized matcher can scan canonical source with a 1,200-character matching window; it need not allocate all paper text or expand the prompt. The scratch prototype traversed canonical blocks, bounded matching to clipped passage, memoized block/offset paths, and accepted9 valid/rejected10 invalid cases (19/19): adjacent, heading/section/caption boundaries including image-caption variant; reverse/skipped paragraph/heading/caption, invented fragments, display-equation skipping, inline-formula crossing and unknown text. A naive concatenation version first rejected a genuine image-caption boundary and accepted a forged skip across an omitted display equation; it is unsuitable.

The prototype is deliberately external and incomplete as a product fix: document-scale performance, all caption/image-failure shapes, dynamic rewrite/control surfaces, repeated ambiguous occurrences and integration with current grounding/cache/frame types still need C tests and manager verification. Existing single-block lookup semantics must be pinned. For a genuine group whose same joined words also appear inside another block, first hints plus actual contiguous range must determine context rather than accepting the unrelated global match. If that cannot be disambiguated safely without a request change, use candidate1's small bounded descriptors instead of guessing.

### 3. Honest limited applicability

Offer model Explain only when the existing single-block validator can truthfully explain its bounded prefix; show a clear reason for unsupported groups while retaining Highlight and Take notes. Preserve no-key matching-term Explain. Do not present an enabled button which knowingly ends in generic failure.

Cost: least backend code, but reduces the requested grouped-selection action surface and may conflict with P12 B6 and ruling198. **Manager policy decision required; this report does not approve it.** A blanket hide for every cross-paper-block group is too broad: it also hides the existing no-key term path and long groups whose clipped prefix already validates. No score/exclusion is inferred.
