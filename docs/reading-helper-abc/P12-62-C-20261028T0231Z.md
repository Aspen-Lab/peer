## The rule as built (`web/src/lib/papers/pdf-outline.ts`, `buildOutline`'s end-matter handling only)

The heading that closes the argument is no longer left unnamed. `tail` / `opensTail` are set as before (`endsTheArgument`, unchanged); then the same branch that names every later heading names it: `tailPartOf(heading, canonical, opensTail || ends)` (an opener ends the argument by definition, so `ends` is `true` for it, also when a wrapped second line has joined it).
- **note** (a data statement, acknowledgements, a supporting-information line, author information / contributions, conflicts, funding past the body): `reading = true`, so the heading opens a section of its own, its own text is read, `canonical` is by its own heading (`acknowledgments`, `supplementary`; a part no bucket names, "Associated content", gets `acknowledgments` as the later ones do);
- **out** (the references): `reading = false`, as today, the entries stay out of every section;
- **appendix** (`Appendix …`, `Supplementary material/information`): `reading = false`, as today, and as the later ones are.
Everything after the opener goes through the same code as before: the `appendix` flag is set / consulted only for headings after the opener (`if (!opensTail) {…}`), so nothing after the first heading changes from C P12-51's rule. `endsTheArgument` is **unchanged** (no word needed adding: the opener is still found by the same words). Comments updated in place: the block above `tailPartOf` and the `tail` / `opensTail` note in `buildOutline`.
