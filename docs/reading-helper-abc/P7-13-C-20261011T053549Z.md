## 2. Commit 2 — (c) Submit; leaving the box settles nothing

`question-field.tsx`: a `Submit` button (`ASK.submit`) in a `mt-2 flex sm:justify-end` row under the lines, `annotation` (label face), `w-full sm:w-auto` (full width on a phone), `disabled` when there is nothing new. It calls `submit()`: `settleQuestions(paperId)` (the path × already used) and then reads the settled set back from the store. `submit()` is also what Enter on the empty last line (and on the last line of a full box, `enterEndsTheBox`), the × and a tick now call — one path. "Nothing new" is `hasNewQuestions(lines, marked, settled)`: the cleaned lines and the marks they carry are not the settled set (spaces and case at the edges change nothing; a moved mark does, because the ledger waits for it). The settled set the button compares with is the field's own state (`settledSetOf(entry)` at mount, and after each settle the field makes), not a store subscription, so a box cleared of every settled question — which makes the store forget the paper, `settled` with it — still has something to send (Submit then takes the words out of the ledger, and the box is quiet again, without a button).

Removed, by the owner's order: `BOX_IDLE_MS`, `settleBoxSoon`, `stopIdle`, the `idleMs` prop, the blur + 1.5 s settle, the `pagehide` listener, the settle on unmount. A set is sent only by Submit, Enter on the empty last line, × or a tick. `leftTheBox` stays (the chips hide when focus leaves). With no key the button still shows (it settles the ledger; the field never reads the key).

`use-model-report.ts` / `use-model-report.effects.test.ts`: **comments only**. The hook's own unloading guard (§1h.8 (2): nothing is sent from a page that is hiding) stays — a tick, a × or a Submit pressed as the page hides re-key it just as the box's `pagehide` settle did — and its tests still drive it with a set that changes while hidden; the comments no longer say the box settles on `pagehide`.

## 7. Where the brief was silent, and what I chose

a. **Submit in the quiet box.** The brief says "at the right of the box … below the lines" and "with no key the button still shows". §1f.10 says an empty, untouched box is one label and one line, and `question-field.test.tsx` pins `not.toContain("<button")` for it. So the button shows when the box is in use (a question, the gist, or focus — the chips' own gate) **or** when there is something to send (a cleared box with settled words); it is not in the untouched empty box. If the owner wants it there, one condition changes.
b. **"Cancels a pending wait"** (brief, commit 2 tests): moot — the wait is removed in the same commit (§4).
c. **Counter "from 400"**: kept as "past 400" (shown at 401), as 160 was "past 160".
d. **The debounce lets a settle through at once.** Not in the brief ("updates React state 250 ms after the last change"): when this paper's `settled` set changes (Submit, Enter-on-empty, ×, tick, and the store's rehydration of a visit's settled set after mount) the hook publishes immediately, with whatever was typed. Without it Submit would reach `useModelReport` 250 ms late, and a rehydration would open the deep report with no questions and then ask again. A keystroke never changes `settled` (`set` carries it over by reference), so typing is still one update per pause. Rehydration of a paper with items but no settled set is debounced (the tints appear 250 ms after load).
e. **Enter on the last line of a full five-line box** still settles (it was the done gesture, §1g.21 (5)); now at once.
f. **One call to the hook**, serving both `page.tsx` sites (the route/settled questions and the example tags).
g. **`routeByQuestionsCached` is a new export**, `routeByQuestions` unchanged (the brief: "stays pure").
h. **Strictness of the cache key**: the exact text (` Q` and `Q` are two keys); the map is part of the key beside the body array, for safety.

## 8. What I could not verify

- **No browser.** `fitHeight` (the border arithmetic, the first-baseline alignment of the counter and × beside a multi-line textarea, `overflow-hidden` with the resize listener), the phone-width full-width button and the right alignment are pinned by element type, class and arithmetic, not by sight. A browser pass in the P7-03 style (60 characters typed: ms/key, long tasks, DOM mutations per key, the 200-character question shown whole, the settle on Submit) is the check that matters; the expectation is that the page no longer re-renders per key, so the per-key cost falls to the field's own render.
- **The React render and commit cost** (most of 290–320 ms in dev) is not in my numbers; they are the JS before React, on this container's CPU, noisy.
- **Hidden box.** `fitHeight` leaves a box that is not laid out alone and there is no `ResizeObserver` (observing the textarea in its own callback raises "ResizeObserver loop" errors). If P7-14's tabs hide the box with `display: none` and show it at another width, the heights refit on the next keystroke or window resize, not on show. P7-14 should keep `QuestionField` mounted and keyed by the paper id only (it is: `key={paper.id}`) and may call a refit when the tab is shown (`fitHeight` is exported).
- **Server-side 500.** `deep-report.ts` and the route mirror the constant; a test pins each at 500, none ties the three together by import (the route does not import the browser store). Prompts grow by at most 5 x 300 characters (P7-02).
