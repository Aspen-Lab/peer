## 0. The answers in brief

1. **Item 6, why no map at the side.** Two causes, both measured. (a) The side-panel layout ("the spread": a panel beside the text column) exists only from a window of **1280 css px** (`SPREAD_QUERY = "(min-width: 80rem)"`, `spread.ts:20`). Below it the map is not in the side panel but in the one column, after the question field (1024 / 1093 / 1242 css px: map top 699 px down, body 1,966 px down on a one-line-title paper). A 1366 px laptop at browser zoom 110 % is 1242 css px, at 125 % 1093 css px: **both are one column**. (b) Even at ≥ 1280 the map is **below the fold on arrival** on a paper with a real head (the owner's PDF, uploaded through the real UI: plate + six-line title): the tab strip is at y = 845 and the map at y = 915 at 1280 × 720, 1366 × 768 and 1440 × 900; it only appears, pinned at y = 134, after the reader has scrolled the page. So the owner who never scrolled saw no map.
2. **Today at 1440 the explain dock moves the whole page.** Opening "Explain this" slides the spread 184 px left and re-wraps the column (640 → 632 px at 1440, 640 → 472 at 1280); below 1280 the one column narrows 712 → 600 px (1024) and slides to x = 24. Measured at all seven widths, light and dark. This is the reserve (`--explain-dock`, `reserveDock`) the three-pane design deletes.
3. **Design.** One full-width shell from 1024 css px: left pane (sticky, scrolls inside itself, rail / peek / pin) | divider | centre (the paper's text, window-scrolled) | divider | margin (an empty, fixed-width slot; every card is a fixed element placed from its rect). Two dividers: pointer (reusing the lightbox's capture pattern, `figure-lightbox.tsx:122-152`) and keyboard (`role="separator"`, arrows). Widths in unzoomed px, remembered per browser, clamped on read. Below 1024: today's one column, byte for byte.
4. **Contracts.** (a) margin: `useMarginRect()` + `placeInMargin()`; the pane is an empty placeholder whose horizontal extent is measured and whose vertical band is the masthead's foot to the legend's top; nothing to reserve any more. (b) left: a fixed zone (title, commands, tabs) and a scroll zone that holds the map. (c) the centre scrolls with the **window**; why, and what the pane alternative would break, is in §3.3.
5. **C split.** C1 splitter kit (leaf, new files) → C2 shell + margin contract → C3 blocks into the panes ∥ C4 dock/cards onto the margin rect. Files are disjoint; `page.tsx`, `globals.css`, `store-hydrator.tsx` only as named hunks (§4).
6. **No dependency.** The splitter is in-house; the pointer-capture drag in the lightbox and its pure `clampFigurePan` are the model.
7. **The owner decides** ten things (§7), each with a default; the ones that move the most: how low the three panes go (default 1024), the left pane's composition (default: fixed top, scrolling map), the centre's text measure (default capped at ~87 characters).

### 1.5 Item 6, in one paragraph

The map is in the left panel only when the window is ≥ 1280 css px **and** the reader has scrolled until the sticky part reaches the masthead. On a paper with a plate and a long title the head fills the first 845 px, so the strip is under the key legend and the map is below the window's foot on every common laptop height (720, 768, 900). ## 2. The design

### 2.1 Shape

```
masthead (stays, sticky, 48 px, z 50)                                    [window scrolls]
┌──────────────┬┬────────────────────────────────┬┬─────────────────────┐
│ LEFT pane    ││ CENTRE                         ││ MARGIN (empty slot) │
│ sticky,      ││ question bar, answers          ││ nothing in it until │
│ scrolls      ││ the paper's text (the window   ││ a selection; then   │
│ inside       ││ scrolls)                       ││ fixed cards placed  │
│ itself       ││ Next row                       ││ from its rect       │
└──────────────┴┴────────────────────────────────┴┴─────────────────────┘
 rail 48 / 240-480   divider 12      min 440          divider 12   280-560
 (default 320; 360 from 1536 css px)                               (default 360)
```

One grid, `grid-template-columns: var(--left-w) 12px minmax(0,1fr) 12px var(--margin-w)`, full width of the window (no max-width cap: the P10 page caps `1072 / 1184 px` go away for the reader). The variables are set on the grid element: by React from the persisted prefs, and directly on the element during a drag (no React render per pointer move, so the text reflows at the browser's speed).

### 2.2 Widths, thresholds, what gives way (computed)

| constant | value | why |
|---|---|---|
| `SHELL_MIN_VIEWPORT_PX` / the media query | **1024** (`(min-width: 64rem)`) | equals `DOCK_MIN_VIEWPORT_PX` (`explain-dock.ts:48`): the margin exists exactly where the dock existed; pinned at all minimums the panes need 240 + 440 + 280 + 24 = **984** ≤ 1024 |
| left pane | min 240, default 320 (360 from 1536 css px, as `SPREAD_GRID` today), max 480 | the commands' two-up row needs ~260; 320/360 is today's track |
| centre | min **440** (a constant, independent of A/A) | the narrowest column today is 472 (1280 with the dock, measured); 440 ≈ 58 characters of Newsreader at the lead size |
| margin | min 280, default **360** (= `DOCK_WIDTH_PX`, the cards keep their size), max 560 | the explain thread, a sticky, the notes window and the figure viewer all fit 360 today |
| rail (left collapsed) | 48 | Claude's collapsed sidebar |
| divider | 12 hit area, 1 px line | |

**What gives way when the window is too narrow for the remembered widths** (pure function `fitPanes`, remembered values are never overwritten by the clamp, so a bigger window restores them): (1) clamp each width to its own min/max; (2) if left + margin + 440 + 24 > window, shrink the margin toward 280, then the left toward 240; (3) if still over, the left becomes the **rail** (auto-collapsed; the remembered pin is kept); the rail case needs 48 + 280 + 440 + 24 = 792, so inside the shell (≥ 1024) there is always an answer. At the **defaults** all three panes pinned need 320 + 440 + 360 + 24 = **1144**: a reader who pinned the left pane keeps it pinned below that by shrinking (a 1093 window gets margin 309, left 320; at 1024 left 280, margin 280, centre 440); a **first visit** below 1144 starts with the left as the rail.

**Below 1024 css px**: today's one column, byte for byte (the P9-04 X3 order), the margin is the existing card (640–1023) and sheet (< 640) (`explain-dock.ts:36`); no panes, no dividers, no rail. `useSpread()` stays the one switch (its query moves from 80rem to 64rem; the blocks remount when it flips, as the comment at `reader-layout.tsx:52-55` already says).

### 2.3 Left pane: rail, peek, pin; its composition

**States** (one DOM node, three CSS states, `data-state="pinned|rail|peek"`; nothing unmounts, so the map's open rows, the decision block's observer and the question field survive):
- *pinned*: a grid column, `position: sticky; top: 4rem/zoom`, window-high minus masthead and legend, **the pane scrolls inside itself** (`overflow-y: auto; overscroll-behavior: contain`, the existing `reader-panel` rule's shape).
- *rail*: a 48 px column holding one icon button (`aria-expanded`, `aria-controls`); the pane is `inert` + `visibility: hidden`.
- *peek*: pointer rests on the rail ≥ 150 ms (or the icon is pressed on a touch screen, `(hover: none)`, 44 px target), the pane is shown as an overlay over the centre (`position: fixed; left: 0; top: 3rem/zoom`, a shadow, **no reflow**); leaving it (250 ms) or Escape closes it; focus inside keeps it open.
- A pin / collapse icon button at the pane's top (and in the rail) toggles pinned ↔ rail. The choice is remembered per browser (`peer-reader-panes`, §4 C1). First visit: pinned where the defaults fit (≥ 1144), else rail.
- Reduced motion: no slide.

**Composition — recommended (decision D3), "Claude's sidebar": a fixed top and a scrolling list.** Today's head is 845 px tall on the owner's paper (§1.2); the pane cannot keep the map on screen if it scrolls as one. So:
- **Z0 header row**: the pin/collapse button and the reading controls (A A ☀ ☾ ⛶; today inside the decision block, `reading-controls.tsx`).
- **Z1 fixed zone** (never scrolls): the title (up to four lines, then clamped, the full title in `title=`), the commands (Read it here / Save / Copy …), the Summary / Paper digestion strip. On the owner's paper Z0 + Z1 are ≈ 430 px of the ≈ 790 px pane at 1440 × 900 (900 − 64 − 28 − 16, the existing `max-height` rule), which leaves ≈ 360 px for the map.
- **Z2 scroll zone** (the only scroller in the pane): **the map**, then the paper's details (the plate, the "Read by your model…" sentence, DOI, private-PDF status). The map is no longer its own `overflow-y: auto` region (`reading-map.tsx:259`'s `xl:min-h-0 xl:overflow-y-auto`) — one scroller, not two nested.
- A paper with no body (no strip, no map): Z1 + the details, no Z2 scroll.

The cheaper alternative (A): keep P10-04b's rule inside the pane (head in the flow scrolls away, strip + map sticky). It changes no block, but the map is still below the fold on arrival (the measurement of §1.2). Cost of the recommendation: `DecisionBlock` is split in two parts (commands; details) and the order tests change in the three-pane branch only.

### 2.4 Centre

- **The paper's text and Peer's additions, as today**: `common` (the question field and the answers), then the active tab's blocks, then the Next row. DOM order is the visual order, unchanged.
- **The question bar and the answers: in the centre, at the top, scrolling with the text (as today).** Why: the answers are long, bulleted, collapsible (P10 4.1) and are themselves selectable and explainable (`data-explain-source="answer"`), so they are text to read, not controls; the field is meant to be a wide search bar (P10 2.6) that 320 px cannot give; the margin must be empty until a selection (item 5); and the field is "before you read", used once per paper, so it need not be pinned. The `Q` key still focuses it. (The left pane may carry a one-line "Ask" shortcut that focuses it; not required.) The owner decides (D4).
- **Measure.** The paper's measure (`.measure-paper` 34 em, `globals.css:642`; `.measure` 28 em) is lifted on the spread today (`COLUMN_CLASS`, `spread.ts:117-118`) because the column was sized for the text. In a fluid centre it is kept: the centre's content is `max-width: 38em` (≈ 665 px, ≈ 87 characters at 1x, today's 640–680 column) centred in the pane, so wider windows add blank gutter rather than 150-character lines, and a pane narrower than 38 em re-flows (D5; "fill the pane" is the alternative).
- Block wrappers keep `reading-scaled` and `--reading-scale` (`reader-layout.tsx:195-200`).

### 2.5 Margin

- An empty `<aside data-reader-margin aria-label="Margin">` placeholder cell, no children, no border but the divider's hairline: **completely blank until a selection is made** (item 5). It is permanent (not collapsible in the first build; D7): a collapsing margin would re-wrap the paper under the reader's pointer at the moment they select.
- Everything that appears is a **fixed** element in window px, mounted outside the zoom root exactly as today (`page.tsx:1645-1656`), positioned from the margin's rect (§3.1): the three selection actions at the selection's first line, the explain card, the sticky-note stack, the notes window, item 1's figure viewer (the whole margin rect).
- Width: the cards are as wide as the margin (280 to 560; they were designed at 360, so C4 must check the explain thread, a sticky and the notes window's toolbar at 280); a card scrolls inside itself, as now.

### 2.6 The dividers

`<div role="separator" aria-orientation="vertical" tabIndex=0 aria-valuemin/max/now aria-controls aria-label="Resize left panel">`, one per boundary (left | centre, centre | margin):
- **Pointer** (`pointerdown` button 0, primary only; `setPointerCapture`; `touch-action: none`; a 4 px move threshold; `pointerup / pointercancel / lostpointercapture` end it; `cursor: col-resize`; `user-select: none` on `body` while dragging; writes the CSS variable on the grid per animation frame; commits to the store on release; the clamp is the pure `clampPane`). Double-click: back to the default width.
- **Keyboard**: ← → ± 16 px, Shift ± 64, Home = min, End = max, Enter = default; focus ring = the product's.
- **Zoom**: the pointer delta is divided by `--page-zoom` (read as `explain-box.tsx`'s `pageZoom()` does, `PAGE_ZOOM_VAR`); `aria-valuenow` and the stored widths are in unzoomed px. Measured in §1.4.
- Touch: the pointer path works for touch and pen; below 1024 there are no dividers.

### 2.7 "The text re-flows and its size never changes" — what it means for A/A and Fit

- Dragging changes **widths only**. Font size comes from `--reading-scale` (A/A) alone, via the `.reading-scaled [class~="text-*"]` rules (`globals.css:713-715`); a divider never writes it.
- **A/A stops changing the column's width.** Today the step scales the page cap and the grid tracks (`page-container.tsx` `spread` variant: `calc(1072px × scale)` and `calc(504px + 680px × scale)`; `fitZoom` divides by them): "scale by width" (`reading-prefs.ts:119-133`). In the fluid shell the centre's width is the window less the panes; the step changes the text size and, through the `38em` measure, how wide the readable block is, nothing else.
- **Fit** (CSS `zoom`, `usePageZoom`, `reader-layout.tsx:164-171`) stays a function of the **window width and the A/A step only**, never of a pane width, so a drag cannot change it. Its reference width is the three-pane default (320 + 640 × scale + 360 + 24 = 1,344 at 1x) instead of the retired caps: `zoom = clamp(1, 0.85 × window / reference, 2.5)` → 1.0 at 1440, **1.21 at 1920, 1.62 at 2560** (computed; today's 1.14 at 1440 and 1.38 at 1920 would over-zoom a layout that already fills the window). Below 1024 Fit has nothing to do, as today (D8).
- With Fit on the margin rect is read in window px (§1.4) and the cards stay unzoomed, as the dock is today.

## 3. The contracts the other items build on

### 3.1 (a) The margin

**Recommendation: a measured rect in a small store (a hook), not a React context and not a portal target.** The cards stay where they are (mounted at the page's top level, `position: fixed`, outside the zoomed container — placed in window px, which a `zoom` ancestor would scale). They need only a rectangle.

```ts
// web/src/lib/reader/margin.ts  (owner: C2; a zustand store like windows.ts)
export const MARGIN_SELECTOR = "[data-reader-margin]";
export interface MarginRect { left: number; width: number; top: number; bottom: number } // window px
export function useMarginRect(): MarginRect | null; // null below 1024 (no shell): consumers fall back to today's card / sheet
export function registerMargin(el: HTMLElement): () => void; // the shell calls it with the <aside>
/** Where a card of `height` stands level with `anchorTop` (a window y): clamp(anchorTop, rect.top, rect.bottom − height). */
export function placeInMargin(rect: MarginRect, anchorTop: number, height: number): number;
```

- `left`/`width`: the placeholder cell's `getBoundingClientRect()` (window px, zoom already applied), re-read by a `ResizeObserver` on the cell and on `resize` — which also catches every divider drag, so a card follows its margin while it is dragged.
- `top` = the masthead's foot = `DOCK_TOP_PX` (48); `bottom` = `columnBottomPx(innerHeight, legendHeightPx(pageZoom))` (`explain-dock.ts:198`) — the same numbers `placePanel` and `useColumn` already compute, so the placement code changes only where it reads its frame. The cell is **not** sticky: a sticky cell would be pushed up at the page's foot (the P10-21 problem, `spread.ts:98-102`); a rect made of the cell's horizontal extent and the viewport's vertical band cannot move.
- **What replaces the reserve.** The margin is a permanent grid track, so nothing is reserved: `reserveDock`, `DOCK_VAR`, `DOCK_WIDTH_VAR`, `.peer-main-content { padding-right }` (`globals.css:613`), `bindWindowsReserve`, `holdInPlace`, `readingAnchorTop` (`windows.ts:231-303`) and the scroll compensation in `explain-box.tsx:803-824` are deleted (C4). The words do not move when a card opens: the acceptance test is "text column x and width identical before and after Explain opens" (today −184 px at 1440).
- **Dock mode ⇔ shell active ⇔ window ≥ 1024** (one constant; a test pins `DOCK_MIN_VIEWPORT_PX === SHELL_MIN_VIEWPORT_PX`). Below it, the card and the sheet are untouched.
- Selection actions: fixed at `left = rect.left + 8`, `top = placeInMargin(rect, selection.bounds.top, h)` (`bounds.top` is the first line's top, `paper-body.tsx:466-481`), hidden when the selection is off screen, re-measured on scroll as the pill is today. Cards open at the paragraph's top as today (`placePanel`); the actions stand over the cards in z.
- The Notes edge tab (`notes-button.tsx:83-84`) is a thin tab on the window's right edge, outside the margin's rect; while the notes window stands it is placed at `rect.left` (a `useMarginRect` read, not `--explain-dock-width`). Moving "Open your notes" into the left pane's commands is the alternative (D9).

### 3.2 (b) The left pane's slot for the map

`ReaderShell` takes `left: { fixed: ReactNode; scroll: ReactNode } | { whole: ReactNode }` and `centre: ReactNode` (§4 C2/C3). The map goes in `scroll` (variant A: in a sticky tail inside `whole`). Data attributes: `[data-reader-left]`, `[data-reader-left-fixed]`, `[data-reader-left-scroll]`. The map is a plain block in the scroll zone: its own `overflow-y: auto` (`reading-map.tsx:259`) is removed so there is one scroller. The map stays outside the tabpanel and is never remounted by a tab switch (`reader-layout.tsx:37-41`); that invariant moves to the new structure.

### 3.3 (c) The centre's scroll container: the window or the pane

**Recommendation: the window** (D2). The side panes are sticky and window-high; the centre is a grid cell of unbounded height. The pane alternative (Claude scrolls the centre itself) is a larger change with no gain the owner asked for. What each choice does:

| thing | window scrolls (recommended) | centre pane scrolls |
|---|---|---|

2. One DOM node per block: no remount on a tab switch, a pin / rail / peek change or a drag (the question field's text, the map's open rows, the decision block's observer survive).
3. A drag never changes a computed `font-size` (measure a paragraph before / after) and never the Fit zoom; the centre is never below 440.
4. The margin cell has no children and no text until a selection is made, and on opening the report (item 5).
5. A card stays inside the margin rect horizontally and between the masthead's foot and the legend's top vertically, at every width 1024 … 1920, with Fit on and off.
6. No horizontal document scroll at any width ≥ 1024, including at all minimum widths.
