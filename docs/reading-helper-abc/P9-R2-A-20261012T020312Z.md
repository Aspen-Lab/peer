## 6. BACKLOG-45 and BACKLOG-46: reading of the code and the fix each needs

### 6.1 BACKLOG-45 — "settled" is the 150 ms debounce
*Where:* `web/src/components/reader/paper-body.tsx`, `useSelectionListener` (l.411–431) and `SELECTION_DEBOUNCE_MS` (l.247). The hook listens to `selectionchange` only and re-arms one timer on each; it has no notion of a pointer. A pause of 150 ms with the button down reports, `PaperBody`'s `onSelect` reaches the page's `selectExplain`, `ExplainBox` gets a new `target`, and (P9-03b) the window moves and the control appears; the floating button in the card range appears the same way.
*The rule:* offer a selection when the primary pointer is up. In the hook, keep a flag `down`: set on `pointerdown` (document, capture) when `event.isPrimary && event.button === 0 && event.pointerType !== "touch"` (touch selection is made with handles that fire no pointer events, or `pointercancel`, and must keep the debounce), clear the timer then; `selectionchange` arms the timer only when `down` is false; on `pointerup` and `pointercancel` (document, capture) and on window `blur` clear the flag and arm one read with delay 0 (the last `selectionchange` of a drag arrived before the release, so nothing else will schedule it); a click that collapses a selection reports `null` the same way. Keyboard selection (shift + arrows) and programmatic changes keep the 150 ms. Upstream `sameSelection` already drops duplicates.
*Test:* `b45.test.tsx` (appendix) is the red-first test; it goes into `paper-body.selection.test.tsx`, whose `window` stub needs `addEventListener` / `removeEventListener` for the `blur` listener. The existing "reports a drag once, at its end" stays green. *Comments to correct afterwards:* `explain-box.tsx` l.74–76, `explain-dock.ts` l.20–21.

### 6.2 BACKLOG-46 — the window's floor against its header
*Where:* `explain-dock.ts` `DOCK_MIN_VISIBLE_PX` (l.61) and `explain-box.tsx` `placePanel` (l.328–336, `clamp(paragraphTop ?? bounds.top, DOCK_TOP_PX, height − DOCK_BOTTOM_PX − DOCK_MIN_VISIBLE_PX)`), called for the empty window (l.1183) and the open one (l.1191). The 160 was chosen in P8-02 for a window whose bars were the quote and the controls row (a one-word quote: 57.5 + 101 = 158.5, with 1.5 px to spare; any longer quote already overlapped); P9-03b added 38 px to the header (the control) and made the floor reachable by selection.
*The rule:* the floor is a property of what the window holds. A window that holds a thread needs, at least, `header + controls row + two reading lines`: measured 140.2 + 101 + about 52 ≈ **295 px** (long quote with the control; 196 + 52 ≈ 250 with a one-word quote; 203 + 52 ≈ 255 without the control). The empty window (≈ 125 px) needs only its own height. So: `placePanel(bounds, viewport, paragraphTop, floor)` takes the floor as a fourth parameter (default `DOCK_MIN_VISIBLE_PX`); `ExplainBox` passes `DOCK_THREAD_FLOOR_PX = 300` (new, `explain-dock.ts`) when a passage is open and nothing (the default 160) for the empty window, whose own height (≈ 125 px) is below it, so an empty window still stands level with a low paragraph. A runtime-derived floor (read `cardRef`'s header and `[data-explain-controls]` heights in the existing layout effect) is more exact and costs a render; the constant is the one-line version and the measured numbers above are its bound. Moving the control inline with the quote's first line instead of under it would give back the 38 px.
*Tests:* re-aim the two pins (`explain-dock.test.ts` l.40–45: `DOCK_TOP_PX + DOCK_MIN_VISIBLE_PX + DOCK_BOTTOM_PX` is 236; `explain-box.thread.test.tsx` l.453–460: `{top: 712, maxHeight: 160}`); add a placement test for the thread floor (`placePanel(…, 5000, DOCK_THREAD_FLOOR_PX)` → `top = height − 28 − 300`); and one layout check in a browser (the harness of this review: render the card at the lowest top for heights 600–1080 and assert `header.bottom ≤ controls.top`), because no unit test here can measure it. The cost: a selection in the last 300 px of the window keeps the window above its paragraph by up to 140 px — the owner should know (his rule is "level with the first line").
