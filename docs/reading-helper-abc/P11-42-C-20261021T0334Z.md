## 1. What was wrong, and where the locator looked

The owner's item 5: a selection is offered **Explain this / Take notes / Highlight**. A selection in a figure's caption or a section's heading was offered the last two only, and `e` did nothing. Three gates held it, each citing the same cause (C P11-27 measured it: `e` on a caption opened the card with "Select text from the paper itself.", the 422 `not_in_paper`):

- `selection-toolbar.tsx`: `explainable = canExplain && target?.block === undefined`;
- `explain-box.tsx`: `isExplainable` and the `blocked` / `target = blocked ? null : given` pair, plus `if (blocked) return` in `openBox`;
- `reader-keys.ts`: **no gate** (`e` is the page's `explain` action, `openExplain`, which is the box's `openBox`; nothing there reads a block). Nothing changed in it.

**How the paper's text holds them.** A heading is `ExtractedSection.heading`; a caption is one of `ExtractedDocument.figureCaptions` (a label and its words; the page places only the ones labelled "Fig…", each after the paragraph that first names it, `placeFigures`; tables are never placed). The page draws both as blocks of the section they stand in and numbers them after its paragraphs (`anchor-blocks.ts`: `paper-section-<k>-p<n>`, `n` = the paragraphs, then the heading, then the captions in `ReadingSection.figures` order). The page already sends that `n` as `paragraphIndex` with the section's id as `sectionId` — **the request needed no new field**.

**Where the locator looked before.** `locatePassage` (`lib/papers/explain.ts`) searched `readableSections(doc)[k].paragraphs` only: the hinted paragraph, the rest of the hinted section, then the whole body in reading order. A heading's or a caption's words are in no paragraph (unless a paragraph happens to repeat them), so the route answered 422. The verifier's corpus (`placeQuote` → `sectionCorpus`) is the sections' text only; the captions are not in it.

## 2. The rules, as built

**Rule 1 — the route explains a caption's or a heading's words.**
- `locatePassage(doc, passage, hint, { blocks: true })` (new fourth argument, **off by default**, so the plain route's rewrite is untouched). With it: (a) the block the hint's number names, tried first and only when its number is past the section's paragraphs (so "Figure 2" selected in the caption is the caption's, not the paragraph that names the figure); (b) everything as before, the paragraphs; (c) only then the headings and captions, the hinted section's first, then reading order. The body's blocks are numbered as the page numbers them: the server rebuilds the figures' placement with the page's own `placeFigures` over `readableSections`. A caption is matched as the page draws it (label, " · ", words, and " · p.N of the PDF" where the picture is not drawn), so a selection may span the label and the words. Tables and the abstract's heading are not found. A passage found nowhere is still `not_in_paper` (422), no provider is still `unavailable`.
- Context, as a paragraph's is: the block as `context.paragraph`, its neighbours as `before` / `after` — a heading: nothing before, the section's first paragraph after; a caption: the paragraph the figure follows before, the next after — plus what a paragraph's context does not need: `block`, and for a caption `figure` (the label) and `section` (the heading); and one rule in the prompt (first answer and reply). A paragraph's context and rules are exactly what they were.
- **A finding:** the explain verifier holds a quote to the sections' text, so a caption's own sentence can never be a verified quote (it is Peer's reading). The caption rule therefore asks for the quote from `context.before` / `context.after`; the heading rule from `context.after`. A test pins that a caption's own sentence leaves "Peer's reading".
- The server memory's key gains `|block:<kind>` for a heading or a caption only, so the same words in a heading, a caption and a paragraph are three entries; a paragraph's key is byte-identical.
- Tier 0, no key: no provider means the route reads nothing (`unavailable`); the page asks for nothing. Unchanged (test, measurement).

**Rule 2 — the page offers it.** `selection-toolbar.tsx`: the `explainable` line is `canExplain` (its two comment lines above it say why). `explain-box.tsx`: `isExplainable`, `blocked` and the `if (blocked) return` are gone; `const target = given`. So the margin's button, `e` and the phone's thumb-bar cell are offered for a caption and a heading as for a paragraph; the card's placement is P11-39's and is untouched (it opened at the first line's top, 329 against 330). A selection across two blocks is still no target (the toolbar is not drawn; `e` does nothing).

**Rule 3 — nothing else changes.** A paragraph's request, its two prompts (user and system, first answer and reply), its token budget, its answer path and its memory key are what they were: pinned by sha256 of the prompts taken on `43c1811f` (`route.blocks.test.ts`), and the paragraph's stub prompt is 4,055 chars on the base and on the fix.

## 8. Unsettled — for the manager

1. **Tier 0 with a defined term.** `selectionCanExplain` is true with a key *or* when the paper's own definition of a term is inside the selection. With the gate gone a caption or a heading that contains a defined term is now offered the (model-free) definition card, as a paragraph is. In the harness there are no terms without a key, so the no-key measurement is unchanged. The brief says "Tier 0, no key: nothing is offered and nothing changes"; if that is meant to close the Tier 0 definition on blocks too, the toolbar would need the key itself (its prop is the one boolean `canExplain`, made in `page.tsx`, P11-40's) — I did not do it.
2. **Stale header note in `selection-toolbar.tsx`** (lines 38–39, "P11-27 rule 2 … Explain this is not offered for it"): not my region; my gate comment says it is retired. P11-38 or the manager may tidy it.
3. **A caption's own sentence cannot be a verified quote** (the explain verifier's corpus is the sections' text; the report's evidence corpus has the captions, this one does not). I asked the model for the quote from the neighbouring paragraphs instead. With the stub (which quotes `context.paragraph`'s first sentence) a caption's or a heading's answer therefore shows "Peer's reading — not a quote"; a real model following the rule quotes the paragraph. Extending `placeQuote` to captions would be a separate item (it would also touch paragraph answers that quote a caption).
4. **Client-kept answers are keyed by passage** (`store/explain-threads.ts`): the same words selected in a heading and in a paragraph share one kept answer on the page. The server's memory now separates them; the client's was not asked about and is not mine.
5. **Figure placement is rebuilt on the server** from the extracted document with the page's `placeFigures` (figure order and each figure's `after`); if the page's reading was built from another document than the route's `getFullText` (a supplement), a stale hint falls through to the search, which still finds the block (test: wrong or absent hint).
6. The base worktree used for the base numbers (`scratchpad/p11c42/wt-base`) is a throwaway; it is left in place and can be removed with `git worktree remove`.
