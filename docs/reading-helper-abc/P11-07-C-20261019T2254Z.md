## 6. For the manager

1. The contract commit is `efc2afb0`; the others start from it. It touched two files that are not mine only by the one-line widenings tsc forces (`export.ts` twice, `note-editor.tsx` `TYPE_LABEL`). P11-08 will replace the two `case "highlight": return null` lines in `export.ts` with the real export (D1) and owns the rest of `note-editor.tsx`.
2. Until P11-08 has a highlight row in `note-editor.tsx`, a highlight block in a note would be drawn there as an ordinary empty text row. Nothing makes one yet (the hook is not wired into the page), but P11-08 must land before the margin's C wires `onHighlight`.
3. The strip is not mounted. The margin's C mounts `<HighlightStrip noteId blockId top left width />` while `useHighlightStrip.getState().id` is set, and takes `noteId` from `readingNoteFor(notes, paper.id)?.id` (the store keeps the block id and the top only, as the brief's `show(id, top)` says). `top` is the selection's `bounds.top` (re-measured by `measure()` when the selection offers it) at the moment of the highlight; the strip does not re-measure on scroll, so the margin's C re-calls `show(id, top)` or hides it when the page moves. B §5's "goes when its mark is more than a screen away" is not in the brief and was not built.
4. `onHighlight` clears the browser's selection, so `useSelectionListener` reports null and the margin's three actions leave; that is the intended step 4. A click on a mark (P11-09's `onClick`) raises the strip with `useHighlightStrip.getState().show(id, top)`.
5. `target.offset` is typed locally (`HighlightTarget = ExplainSelection & { offset?: number }`) because `SelectionTarget` has no `offset` yet (P11-09 adds it). When it does, the intersection is redundant and harmless; `useHighlight`'s result is assignable to `(target: ExplainSelection) => void`.
6. Choices the brief left open: `addHighlight` returns null for a passage over 1,200 characters (it never cuts the quote, which has to be the whole passage); `highlightSelection` takes away a reading note it made if the highlight could not be made (so a failed Highlight leaves no empty note behind); `readHighlight` returns the stored object itself when it is well-formed and a repaired copy when the colour was unknown; `anchorMap`'s `order` is the block's index among all the note's blocks; the swatches follow the radio-group keys (arrows, Home, End) and only the current one is in the tab order.
7. `sticky-note.tsx` is untouched: `removeEmptyStickies` already ignores a highlight (`withoutSticky` finds no `h3` at a highlight's id, `stickySpan` ends at one); the new tests pin it.
8. The flaky `use-model-report.status.test.ts` is load-induced and is on the base too; if the full suite is red on it alone under load, it is not this item.
