## 2. The rules, as built (`for-your-questions.tsx`)

The meta row is a list of parts — **section, page (when the map knows it), minutes, role word (a background row)** — from one function, `readNextParts(section, kind)`. `readNextLabel(section, kind)` is now `readNextParts(…).map(text).join(" ")` and is exported (see §7).

1. **The separator belongs to the part it introduces.** Every part but the first begins with its own `"· "`: `§2 Methods…`, `· p.1`, `· 3 min`, `· background`. A line can therefore open with `· background` and none can end on a `·`: the `·` is followed, inside the same element, by the word it introduces.
2. **Each short part is unbreakable.** Page, minutes and role word are `<span data-meta-part="…" class="whitespace-nowrap">`; a part never splits. The `"· "` and the `N min` (its space is still the no-break space P9-05 put there) stay on one line.
3. **The section's title is the one part left free to wrap inside itself** (no `whitespace-nowrap` on it: a long heading must not run off a 350-px phone column). This is the answer to the brief's "a part that does not fit": only the title can be that long, it is allowed to wrap at its own spaces, and nowrap is on the short parts only.
4. **One plain space between two parts, outside both,** is the only break opportunity of the row (`{index > 0 ? " " : null}` between the spans). It has to be outside: a break opportunity needs a space whose nearest common ancestor is the `<p>` (white-space normal); a leading space inside a nowrap span would give none at all and glue the parts into one unbreakable run. The break lands on that space, the space collapses at the line's end, and the next line starts with `· …`.
5. **Same words, same order, same separators, one string** to a screen reader and a copy: the spans are inline with no role and no `aria-*`, text content = `readNextLabel`'s string (`§heading · p.N · N min`, then ` · background`, the minutes on U+00A0 as in P9-05, the page plain). The Markdown export (`reading-markdown.ts`) is untouched.

`data-meta-part` names the part for the tests and the measurement; it adds no style.

## 7. For the manager

1. **`readNextLabel` is exported and now used only by the tests** (the one-string reading of the row, which `reading-markdown.ts` l.133 names in its docstring and P9-05 / P9-19 name in their checkpoints); the row itself is drawn from `readNextParts`, which is also exported though only this module uses it. Un-export `readNextParts` if you prefer a smaller surface; I did not add a fourth commit for a keyword.
2. **Why the space is outside the parts.** The brief says "the separator belongs to the part it introduces, rendered as that part's leading ' · '". It is: `"· "` is inside the part. The *space before it* is not — a break opportunity is a space whose controlling ancestor allows wrapping, and a space inside a nowrap span is no opportunity, so with the space inside every part the row would not wrap at all (it would run off a phone). The one plain space between two spans is both the word space of the copied string and the row's only soft break. A `::before` would have left the separator out of the copy, so the separators are text.
3. **A heading's single unbreakable token** (a very long unspaced word in a section title) still overflows the column as it did before: the title part wraps only at spaces. Not part of X10; no `overflow-wrap` was added.
4. **The flake** of §4 (`use-debounced-questions.test.ts`, a 250-ms timer under load) is P7-13's file and not touched; it passed alone 3 of 3 and on the second full run.
5. **Re-aimed tests** (§3): six tests read the row's text instead of its raw markup, none weakened; the P9-19 cross-check changed by one line and is forced to (a copy of the head's file fails at 0 rows on the new markup).
