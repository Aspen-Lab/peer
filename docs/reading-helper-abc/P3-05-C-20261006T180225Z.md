### Commit 2 — F2: nothing is sent from an unloading page (§1h.8 (2); §1g.21 (6))

- **`use-model-report.ts` only** (plus test stubs): `pagehide` marks the page unloading, `pageshow` clears it; the request effect, at the point where it would start a request (after the existing skip conditions and after the §1g.18 in-flight rule, before the controller is made), returns instead and records that a request was withheld; `pageshow` then bumps `released` — the re-run trigger the hook already has — so the effect runs again and sends **the one request for the current key**, the settled questions riding it. The two listeners are added once per hook instance (a `useEffect` with `[]`) and removed on unmount. The in-flight rule, the keys and the `finishedKey` guard are untouched.
- **Where this differs from the brief's wording (a design correction, not a false premise): a ref and `released`, not an `unloading` state in the effect's dependency list.** Two reasons, both about the ruling's substance (nothing from the dying page; the one request on the next show):
  1. *A state in the dependency list re-runs the effect on every `pageshow`.* The effect reads `cached` from the hook's first render (`useMemo` on the key), which does not see a report this visit wrote, and the one-shot `finishedKey` guard is spent by then — so a back/forward-cache **restore with nothing settled in between** would ask for a report already shown (a second charge). I measured exactly that: with the `withheld` check removed (the probe: `if (false && !withheld.current) return;` in the `pageshow` handler, restored byte-identical, sha256 `87efa76a…7e22` before = after), my two tests "a page hidden and shown again with nothing settled in between sends nothing" and "a pageshow with no pagehide before it … changes nothing" go red with 2 requests where 1 is right. With `withheld`, a restore re-runs nothing unless a request was held back.
  2. *Ordering (from reading React's semantics; not measurable in this no-DOM suite, so recorded as reasoning):* the question box reaches the hook through a Zustand subscription (`useSyncExternalStore`, a sync-priority render flushed in a microtask), while `setUnloading(true)` from a native `pagehide` listener is a default-priority update. The browser runs microtasks between listeners, and the hook's listener (added at mount) runs before the field's (added when its wait starts), so a state set by the first listener can still read false in the sync render the second one causes — the dying page would fetch anyway. A ref is read at the moment the effect runs and has no such gap. Tests on `test-support/hook-runtime` apply state synchronously, so they cannot tell the two apart; A's real-browser re-measure can.
- **Tests (the hook's effects test, and the P2-10 flow test as the end-to-end home):** `use-model-report.effects.test.ts` +7 in a new `describe` (a scripted browser: one act per render round): a settle after `pagehide` sends nothing and `pageshow` sends exactly one request carrying the questions (and no JSON fallback); the questions settled in two steps while hidden go once, the latest set; hidden-then-shown with nothing settled sends nothing; a request in flight when the page hides is left alone (not aborted) and the questions settled meanwhile go once it is shown, with only the open sent while hidden even after the flight ended; without either event a settle sends one request at once (as before); a `pageshow` with no `pagehide` changes nothing; exactly one listener per event per hook instance across re-renders, none after unmount. `question-box.flow.test.tsx` +1 — A's reproduction on the **real field, store and hook**: three-step script (type, leave the box so the idle wait is pending, fire `pagehide`) → the questions are settled by the `pagehide`, still only the open's request was sent, `pageshow` sends one request with the question, nothing aborted, no listener left. **Red first:** 4 effects tests + the flow test failed (the flow test showed `calls: 2` where 1 is right — A's measurement at unit level) before the guard existed.
- **Existing tests touched only to give them a `window` that can hold listeners** (the hook now registers two on mount, as the field already did): `use-model-report.effects.test.ts` (`window` was `globalThis`, which has no `addEventListener` in Node), `use-model-report.quota.test.ts` (same), `question-box.flow.test.tsx` (its no-op `window` became a registry that can fire).
