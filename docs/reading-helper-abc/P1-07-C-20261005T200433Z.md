## What changed

### `web/src/components/reader/question-field.tsx` (§1f.18 a)

New pure exports:

- `settleLine(unsettled, { type, index })` tracks the line being written:
  - `focus` or `change` on line *i* → *i*;
  - `enter` or `blur` on line *i* → null if *i* was the unsettled line; otherwise no change.
- `vagueHintShown({ vague, lines, unsettled })` is `vague` and at least one non-empty line other than the unsettled one. `vague` is still the page's route verdict (`route.vague`).

In the component:

- New state `unsettled: number | null`, starting at null so a stored question is settled on mount.
- Each input feeds it from `onFocus`, `onBlur`, `onChange` and the Enter branch of `onKeyDown`.
- Removing a line resets it to null, because the line indices shift.
- The hint `<p role="status">` renders when `vagueHintShown(...)` is true.
- The store still writes through on every keystroke; `commit` is unchanged, so persistence and the live tints are as before.

What this means for the reader:

- The hint never shows for the line being typed.
- A line settles on blur, or on Enter: after Enter the focus moves to the new line, and the line above counts as settled.
- Another settled vague line keeps the hint showing while a new line is typed. That matches the route's own verdict, which is "every stored question is vague".
- Focusing a settled line without typing also hides the hint for it ("never for the line that currently has focus").

### `web/src/components/reader/reading-map.tsx` (§1f.18 b)

- A tinted paragraph line (`read`, `skim`, or `background`) carries `text-text-muted` and no longer `text-text-faint`.
- An untinted line carries `text-text-faint` as before. The class order changed; the classes did not.
