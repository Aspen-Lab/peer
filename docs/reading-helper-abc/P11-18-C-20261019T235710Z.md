The other fourteen tests run a stub with no timer and need no change.

## The rules (the same as part 1)

1. Every wait is a condition with the 20 s ceiling, polled on real timers, that fails the test naming the wait: drain `streamsClosed`, `requestHeld`, `actAndSettle`; effects `reportOnPage`, `requestsClosed`, `requestHeld`, `actAndSettle`, `aFullCycle`. The runner's 5 s timeout is raised to 60 s so it does not cut a slow machine off first. No wait is a number of milliseconds or ticks.
2. Drain: each stub event is sent only after the page has drawn the one before (`drawn`). The first request, which the queued question waits behind, is held until the test releases it. The deadline test's fake keeps its `setTimeout` spy and fires the deadline once the page has drawn the report. Effects has no event to pace (its stub is microtask-only), so it uses no `drawn`.
3. Effects: the stub's hold is a gate (`holdFirst`, `released`), released by the test or by the page abandoning the request. `drive` moved up to the module so both describes use it, and takes the paper as a value or a function so the swap test no longer counts rounds.
4. Shared: `until`, `drawn`, the ceiling, the lapse record and `throwIfLapsed` live in `test-support/page-pacing.ts` (a module, one state per test file). It has no dependency and no React.
