## Findings, ranked (privacy and fabricated text first)

### F1 — HIGH, fabricated text — a quote's middle is never checked (row 7)

- `evidence.ts` `supportedIn` accepts a quote over 80 characters when its **first 80 and last 40 normalised characters each appear in the same section**; the characters between are not compared. It was written to tolerate a dropped citation. P2 now applies it to every answer's `evidence` (and to Pass 1q sentences and terms), whose text the page prints in italics as the paper's own words with a section link and page.
- Reproduction, real verifier on my extracted paper (`verifier.probe.test.ts`, 243-character sentence "Vanadium has been added in small amounts … but no report has yet followed both effects …"):

| Altered quote | Accepted |
|---|---|
| exact; lower-cased; trailing period removed | yes (by design: NFKC, case, whitespace, hyphen-break folding) |
| "but no report has yet followed" → "and a report has already followed" (meaning reversed) | **yes** |
| an invented clause inserted at character 100 | **yes** |
| first 80 characters + an invented sentence + last 40 characters | **yes** |
| head of one sentence + tail of another, same section | **yes** |
| a word changed inside the first 80 or the last 40 characters | no |
| an 81–120 character sentence with a word inserted at character 50 | no (head and tail cover it) |

- Real path (`real-flip.cjs`): real route, real hook, my stub proposing the reversed sentence for a question → `droppedClaims` unchanged, the page shows it in italics as "— §1 Introduction · p.1", and it is **not** a substring of the paper body (`isSubstringOfPaperBody: false`), under the Decision sentence "every claim below carries a verbatim sentence".
- Exposure: in the three committed real-paper fixtures, 347 of 530 sentences of 40+ characters (65%) are longer than 120 characters, so most real quotes have an unchecked middle. A flipped number or negation inside such a sentence passes.
- Classification for B: pre-existing leniency in the verifier now reaching a new surface; a spec-vs-implementation conflict with §1b ("verbatim"), probably a policy question (how strict, and what to do about a dropped mid-sentence citation).
- Direction (one line): require the whole normalised quote to be a substring of one section (allow only the citation and math-token variants the leniency was written for), and make Pass 1q's `locateSection` use the same rule.

### F2 — MEDIUM, privacy — the questions travel when no deep report is asked for (row 21)

- `use-model-report.ts` adds `questions` to the body and to `reportKey` whenever settled questions exist, whatever `deep` is. The route's own comment says the deep path is the only reader.
- Reproduction (`ui-nodeep.cjs`, real hook, canned route): (a) no key, no deep: after 2 settled questions the page made 3 report requests, bodies `deepReport:false` with `questions` of 0, 1 and 2 items; (b) BYOK key, deep off: the same, with `llmOverride` present. The answers block never appears in either case. With a key, each settle is a new abstract-tier request, so one extra model call per settle for nothing.
- Against: /privacy "Your questions": "Questions you type on a paper page stay in this browser. When Peer writes a deep report for that paper, they travel with that one request…". The server does not log or keep them (row 19), so this is data minimisation and a claim that is not true as written, not a leak. A smaller point: the same questions also go to the model provider inside the Pass 1q and Pass 2 prompts, which the entry does not say.
- Direction (one line): put `questions` in the key and the body only when the request is deep.

### F3 — MEDIUM, cost and quota — every Enter settles a deep report (row 27)

- `settle` runs on Enter, blur and removal (§1g.11 a) and each distinct settled set is one deep report (§1g.11 c); the field's own multi-question flow therefore requests, charges and aborts once per line.
- Reproduction on the **real counter** (`real-multi.cjs`, fresh server, default `one_tier`): open the paper, then type five questions with Enter between them (model slowed to 1.5 s, as a real one is). 6 report requests (question counts 0,1,2,3,4,5; Playwright's `requestfailed` fired 6 times, the hook aborts the in-flight request at every key change) and 5 Pass 2 model calls (`large` tier), of which at most the last set's report can be read. I did not check the final page in this default-mode run. I read the counter by looping provider-present requests until the breaker tripped: it tripped at request 195, so the session had used 201 − 195 = **6** of the 200 daily units (and 6 of the house's 1000).
- Under the free plan's accounting (`real-tiered.cjs`, `PEER_ENTITLEMENT_MODE=tiered`, 5 per month): the same session made 6 requests, 5 allowed and the 6th refused; the final page shows "Deep reports are used up for now. This is the shorter report." and **no answers block**. A free reader's first paper with five questions spends the whole month and returns no answer.
- §1g.11 c accepts one unit per distinct set and BACKLOG-08 covers question-only re-requests; neither considers the intermediate sets of a single typing session or the charge for requests the client aborts.
- Direction (one line): settle only when the reader leaves the question box (or debounce), and do not charge a request the client has already abandoned.
