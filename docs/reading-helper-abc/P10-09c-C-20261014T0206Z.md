## The rules as built

1. **One `ensureReadingNote`.** `ensureReadingNoteLocal` is deleted. `openPaperNotes` takes the store's `ensureReadingNote` as `ensure` (in place of `add`): with the paper's note already there it opens the window (or navigates, with no `openWindow`) and makes nothing; without one it calls `ensure(citableFromPaper(paper), { questions, forYourQuestions })` and opens/navigates to the id. `usePaperNotes` passes `useNotesStore((s) => s.ensureReadingNote)`. The sticky's "Take notes" calls the same action, so the window and the stickies, and the Saved page's `readingNoteFor`, are one note (the test of 09b still pins it, now through the store's action).
2. **The notes window is in the stack (B9).** `NotesWindow` calls `useWindows.getState().open({ id: NOTES_WINDOW_ID, kind: "notes", … })` on mount and `close(NOTES_WINDOW_ID)` on unmount. `lib/reader/windows.ts`: `stackLayout` takes every kind in one cascade (40 px apart, the last raised in front and whole, a header click raises); the notes window in front takes all the height the screen leaves (it scrolls inside) with a floor of `NOTES_MIN_FRONT_PX` = 240 (stickies keep 260 / 160); `stackRows(windows, blocks, frame)` is the one filter (the notes window, and each sticky whose anchored `h3` is in the note; not the explain kind) — both `StickyNotes` (via `stickyRows`) and `NotesWindow` lay out through it, so they agree on every position; `useColumn(active)` moved there from `sticky-note.tsx` (reads `[data-explain-dock]`, 250 ms + scroll + resize) and its bottom is now `innerHeight − max(40, legend at the page zoom + 8)` (the legend rule the notes window's own box had). The notes window's own box (`notesWindowBox`, `measure()`, `z-[70]`) is gone. Behind another window the notes window shows its header alone, a header tall (Export hidden, Close kept); its editor stays mounted, hidden, so nothing it holds is lost; a header press raises it. Escape closes the focused window (sticky or notes; with the export menu open, the menu first). Z is the stack's (60+), under the explain window's 70.
3. **A sticky follows its blocks.** `stickyFollowText({ local, stored, pending })`: the stored text when the blocks changed outside and no keystroke of the sticky's own is waiting (`makeStickyWriter` gained `pending()`); the text area's words are compared as paragraphs, so what the sticky wrote itself (blank lines and trailing spaces dropped by the store) is never taken back. Applied in `StickyWindow` while rendering (not an effect). The notes window's editor restart on an outside change stays, and the race of BACKLOG-69 is **narrowed, not closed**: `reconcileWindow(base, mine, theirs)` decides `same` / `keep` / `restart` / `merge`; when the editor holds unsaved typing (within its 500 ms) at the moment a sticky's words land, `mergeBlocks` merges by block id (a block only the window changed keeps the window's, only the outside changed keeps the outside's, window-added blocks stay, window-deleted ones go), and the window stores the merge itself after the old editor's unmount flush (an effect after the restart), so the stale flush no longer wipes the sticky's words. What is left: the **same block** edited in both places inside the same half second — the outside write stands. A sticky's write-through debounce went from 250 to 150 ms (see measured).
4. **An empty sticky leaves nothing behind.** `closeSticky(noteId, headerId)` (the × and Escape): `withoutSticky` removes the `h3` and its text blocks when all are empty (whitespace counts as empty), then the window leaves the stack; `stickyCount` is not touched, so the next sticky is numbered past the freed one. A sticky with words is closed and keeps everything.
5. **Nothing else changes**: data model, export, selection buttons, tags and square, explain window, the editor (all untouched).
