## The defect, and what causes it

With a figure card, an Explain card and a sticky open, narrowing below 1024 px and widening again brought back the Explain card and the sticky and not the figure card. Three facts, read from the code and then from the browser:

1. **The host closed the figure.** `figure-host.tsx` called `closeFigure()` when the margin went (`rect === null`): the store was emptied and the card's window left the stack. Nothing remembered it.
2. **The zoom and the pan are not in the store.** They are the card's own state (`useFigureZoom`, inside `FigureCard`; `use-figure-zoom.ts` and `figure-card.tsx` are not mine), so a card that is unmounted loses them whatever the store keeps.
3. **The Explain card follows the width on its own clock** (`explain-box.tsx` reads `window.innerWidth` in a `requestAnimationFrame`, not when the margin registers): it leaves the stack at narrowing and joins it again, **in front**, at widening — on the base, with no figure involved, opened Explain, sticky is `sticky < explain` after the step back. Measured: at widening it joined **after** the margin was back. So a restore that reads the stack when the margin goes, or that is finished when the margin is back, misses the Explain card. My first code state (park the figure, put its window back by order value) passed every unit test and **failed the order check in the browser** for exactly this reason (`explain < sticky < figure` came back `sticky < figure < explain`); it is reworked below, and the stack memory works with the Explain card on either side of the margin (both are unit-tested).

## The rules (ruling §1h.138 (d))

1. **Parked, not closed.** When the margin goes while the card stands, `parkFigure()` moves the figure from the store's open slot to a parked slot; the card's window leaves the stack (so the other cards count no header for a card nobody sees). A parked figure is not open: the body's button is not pressed, Escape has nothing to close, `useFigureOpen` is false. When the margin is back, `resumeFigure()` opens **the very same ref** (not a copy, so the card's "focus once per ref" logic does not act: a return is not a press).
2. **The same zoom and pan: the card is kept.** `FigureStack` renders the card inside an `Activity` in both states (`mode="visible"` in the margin, `"hidden"` while parked). It is the same element at the same place in the tree, so React keeps its state: the zoom, the pan, the picture it drew. While hidden it draws its header only and `display: none` (React's own, `Activity`).
3. **The same stacking order.** `createStackMemory` (a closure in `figure-host.tsx`, one per host) is kept by a subscription to the windows store, gated on the window's width (`window.innerWidth >= DOCK_MIN_VIEWPORT_PX`, the Explain card's own rule): the stack as it stood while wide, the cards that left it while narrow, and the cascade's origin. On return the figure's window is opened in the stack and every window is raised in the old order, the figure among them (`stackAfterReturn`, pure). A card nobody touched while narrow — it stands with the order it had, or it left and is back (the Explain card) — goes where it stood; a card the reader opened or raised meanwhile stays in front. A card that left and is not back yet is waited for, `REJOIN_WAIT_MS` = 1000 ms at most (a bound, not a delay: nothing waits on the figure), and put in its place when it joins. The origin is put back through `open`'s `anchorTop` (the stack forgets it when it is empty, which it is below 1024 when only the Explain card and the figure stood: without it the cascade came back at the margin's top instead of level with the selection).
4. **A figure closed while narrow stays closed.** `openFigure` and `closeFigure` forget the parked figure: a figure pressed below 1024 is the lightbox and replaces the parked one (D2); closing it, or the X, Escape, or the host unmounting (the paper changing), leaves nothing to come back.
5. **Nothing per-user is written anywhere new — which memory.** The parked figure is a module variable in `figure-viewer.ts` (the same lifetime as the open figure: this tab, gone at a reload); the stack memory is a closure in the host (gone with it); the zoom and pan are the kept card's React state. No `localStorage`, `sessionStorage`, IndexedDB, cookie, URL, network or console; the page's existing session state is neither read nor changed (`useWindows` is the existing in-memory store, written only through its own `open` / `close` / `raise`). Guarded by the existing source tests of both files (`never touches storage…`, `leaves the page alone`), which still pass on the new code.
6. **Below 1024 the behaviour is unchanged, and it is: the lightbox, or nothing.** A figure pressed while the window is under 1024 is today's lightbox overlay (a modal, closed by Escape or its X, nothing reserved). A card that was open in the margin is not drawn (nothing; no overlay). An overlay open when the window widens stays an overlay (today's rule) and no card comes with it.

## For the manager

1. **The parked card is kept in the DOM, hidden.** To keep the zoom and pan without touching `figure-card.tsx` / `use-figure-zoom.ts` (not mine) the card stays mounted in a hidden `Activity`: while the window is narrow `[data-margin-card="figure"]` is in the document with `display: none` and no box (header only). A count of `[data-margin-card]` that does not test the box (the round's `cardsState`) lists it at narrow (`sticky+figure` where the base said `sticky`); nothing that reads a box does (`openCardRects` in the selection's actions already skips a card with no box). If that is not wanted, the other way is to let `FigureCard` take an initial view and report its view, so that the card can be unmounted and the host keeps `{zoom, pan}`: two files outside this item's.
2. **With a figure parked, the Explain card comes back in its old place, not in front.** The whole old stack is put back (rule 3), including the Explain card's own slot; with no figure parked the Explain card still rejoins in front (`explain-box.tsx`'s `useEffect([docked])`, not changed). A reader's own touches while narrow (a card opened or raised) stay in front.
3. **Two numbers I chose.** `REJOIN_WAIT_MS` = 1000 (how long the host waits for a card that left to join again; it only bounds a stale wait, nothing is delayed by it) and the gate `window.innerWidth >= DOCK_MIN_VIEWPORT_PX` for the stack memory (the Explain card's own rule; the shell's media query is `64rem`, the same 1024 at a 16-px root).
4. **Unchanged by design:** a lightbox open when the window widens stays; the focus goes back to the pressed figure's button when the card goes, as before (nothing has the focus), and a return moves no focus.
5. **Not measured on the base:** the two scenarios without a sticky (Explain, figure; figure, Explain) — added after the base run; the mechanism is the same.
6. The brief's `git commit -m "…" -- <path>` form was used throughout; the new test file was `git add -N`'d first.
