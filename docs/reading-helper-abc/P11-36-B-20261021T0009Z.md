## 0. Result in eight lines

### 2.1 The pane steps under Fit (defect 1)

- `web/src/components/shell/masthead.tsx:166`: the masthead is `h-12`, 48 px, and is **outside** the zoom root.
- `web/src/app/papers/[id]/page.tsx:714-718` and `:1402-1410`: the `<PageContainer data-zoom-root>` carries `zoom: Z` and `--page-zoom: Z`; everything inside it, the article's padding, the grid, the pane, `KeyLegend` (`:1708`), is painted at `local x Z`.
- `web/src/components/ui/page-container.tsx:49` (`xl:pt-4` in the `reader` rhythm) and `:55` (`lg:pt-4` in the compound variant): the article's top padding is `1rem` **local**, painted `16 x Z`. The pane, which is the grid's first thing, is therefore first painted at `48 + 16 x Z`: 67.43 at Z 1.2143.
- `web/src/app/globals.css:597`: `.reader-left { top: calc(4rem / var(--page-zoom, 1)); }` is local `64 / Z`, painted at **exactly 64** (not a rounding: the product is 64 at every Z in the table, to the layout's 1/64 px: 63.98 at Z 1.0119). The comment at `:554` ("4rem = the article's top padding under the 48px masthead … so the stuck position is the first-paint position") and `page-container.test.ts:19` ("so the pinned pane's 4rem top is its first-paint position") are true only at Z = 1: the masthead's 48 does not scale, the padding's 16 does, so `4rem / Z` is `16 x (Z - 1)` short of the first-paint position.
- A sticky box whose static position is below its `top` rides with the page until the page has scrolled by the difference, then stops: 3.43 px at 1920 (the first-pixels line above).
- `globals.css:680` (`.reader-rail-button`, the same `4rem / Z`) steps the same (67.42 to 64: the rail column of 1.1). `globals.css:744` (`.reader-divider { scroll-margin-top: calc(4rem / var(--page-zoom, 1)) }`, which P11-29 set equal to the pane's top on purpose) makes the browser align the separator's margin box with the window's top while its top edge is at `48 + 16 x Z`: the window moves by `16 x (Z - 1)` rounded: +3, +6, +10, +23, +1 at 1680, 0 at 1600 (0.19).   // The static position of the pane at scroll 0 is the masthead (unzoomed) plus the container's padding (painted x zoom). A `top` that is not that
  // number lets the pane travel the difference with the page's first scroll (3.4 px at 1920 x 1080, Fit on) and makes the separator's focus move the window.
  it("sticks the pane, rests the rail's button and aligns the separators' focus at the pane's static position, at every Fit zoom", () => {
    for (const zoom of ZOOMS) {
      const want = staticTop(zoom);
      expect(painted(declaration(PANE, "top"), zoom), `the pane's top at Fit zoom ${zoom}`).toBeCloseTo(want, 1);
      expect(painted(declaration(rule(".reader-rail-button"), "top"), zoom), `the rail button's top at Fit zoom ${zoom}`).toBeCloseTo(want, 1);
      expect(painted(declaration(rule(".reader-divider"), "scroll-margin-top"), zoom), `the separator's scroll margin at Fit zoom ${zoom}`).toBeCloseTo(want, 1);
    }
  });

  // The peek is fixed from the masthead's foot; its content (the header row, the title, the first map row) must start at the pinned pane's top.
  it("starts the peek's content where the pinned pane's starts, at every Fit zoom", () => {
    for (const zoom of ZOOMS) {
      const top = painted(declaration(PEEK, "top"), zoom);
      const pad = declaration(PEEK, "padding-top");
      const content = top + (pad ? painted(pad, zoom) : 0);
      expect(content, `the peek's content top at Fit zoom ${zoom}`).toBeCloseTo(painted(declaration(PANE, "top"), zoom), 1);
    }
  });

  // The peek is drawn to the legend, not past it: the legend is `legend-h` x zoom tall once Fit scales the page (key-legend.tsx is inside the zoomed container).
  it("ends the peek at the legend's top, not under it, at every Fit zoom and window height", () => {
    for (const zoom of ZOOMS) {
      for (const vh of [720, 1080]) {
        const foot = painted(declaration(PEEK, "top"), zoom, vh) + painted(declaration(PEEK, "height"), zoom, vh);
        expect(foot, `the peek's foot at Fit zoom ${zoom}, ${vh} px high`).toBeCloseTo(vh - legendPainted(zoom), 1);
      }
    }
  });

  // The pinned pane keeps 16 px of air above the legend whatever the zoom (P11-23: "it still ends 16 px above the legend"; Fit off 16, Fit at 1920 was 10).
  it("keeps the pinned pane 16 px clear of the legend, at every Fit zoom and window height", () => {
    for (const zoom of ZOOMS) {
      for (const vh of [720, 1080]) {
        const foot = painted(declaration(PANE, "top"), zoom, vh) + painted(declaration(PANE, "max-height"), zoom, vh);
        expect(vh - legendPainted(zoom) - foot, `the air above the legend at Fit zoom ${zoom}, ${vh} px high`).toBeGreaterThanOrEqual(15.5);
      }
    }
  });
});

## 5. Unsettled

1. **P-full or Q-full is the manager's call.** I recommend P-full: it changes nothing outside the pane's own box, as the brief asks, and it keeps "the stuck position is the first-paint position" true at every zoom. Q-full gives a 16-px gutter under the masthead that does not grow with Fit (a defensible design) at the price of the paper's text moving up 3.42 px at 1920 (9.89 at 2560) and the page's height changing by as much.
2. **A custom property for the shared `top`** (`--pane-top` on `.reader-shell`): not measured. It must be declared on a descendant of the zoom root.
3. **Not measured:** the dark theme (geometry does not depend on it), a touch device's peek (the same node and rule as the hover's; `onRailClick`'s touch branch), "Larger text" steps with Fit on (Z then also depends on the reading scale; the numeric tests cover Z 1 to 2.5, the browser matrix covers the Z values listed), windows under 1024 px (one column, no pane), and the one-column page's legend.
4. **A trap in the harness (A's, mine at first):** after a click on "Collapse sidebar" the pointer rests inside the rail's cell, so moving the pointer "onto the rail" gives no `pointerenter` and the pane stays in `rail` (hidden) state, whose geometry is the peek's. The numbers are the same geometry, but "the peek" was not open. A's `b8-peek.json` polls the state; any harness that reads the peek after a collapse click should leave the cell first and assert `data-state="peek"`.
5. **Left alone:** the separators' focus from the foot (-64 / -78 / -86 / -103 / -155): the same on the head and under P-full (Q-full: -104 at 2560); B P11-24's case.
6. **Cost to say plainly:** under Fit the pinned pane is `44 x (Z - 1)` painted px shorter than on the head and the map's zone 8 / 17 / 26 px at 1920 / 2560 / 3840: that is the legend's real height, which the head's formula under-counted; at Z = 1 nothing changes.
7. **Not on anyone's list:** the pinned pane crosses the legend by 1.33 px at 2560 x 1440 (24 px at 3840 x 2160) on the head; BACKLOG-105 names only the peek. P-full fixes both with the same formula.
