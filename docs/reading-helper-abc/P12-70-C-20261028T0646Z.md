## Each failure: the cause, the fix, the test

1. **"never reads a short line of figure text as a heading…" (sections O8).** C P12-51's O8 takes "5 Min / 10 Min / 20 Min" for figure text and drops them; C P12-56's R6b refuses a label line ("Figure 4: …") whose line above is in the body's size and face and ends no sentence. The figure text is set in exactly that size and face and stands directly above the caption, so the caption was refused and read as prose. **Fix (code):** `captionAt` takes `leftOut(index)`, the lines the reading leaves out (figure text, margin print, the dated box); `followsOpenProse` says no when the line above is left out, and `inCaption` passes it down. `buildOutline` passes `skipped[j] || figureText.has(j)`. The optional parameter keeps every direct `captionAt` call as it was.
2. **"keeps the short last line of a body paragraph… with or without a full stop" (sections O8).** The same meeting, in the other direction: P12-51's required negative has "of the new set" (no full stop) then a caption; R6b read the missing stop as an unfinished sentence and glued the caption in. **Fix (code):** a line under half the length of the line above it (same page, directly under it, same column, same face and size — `endsParagraph`, `SHORT_LAST_LINE` 0.5) is a paragraph's last line, not a wrapped one, so a label line after it is a caption. A `PdfLine` has no width, so the length is the characters (the faces and sizes being equal). A line that wraps near the column's width (R6b's ghost), or a line with no line of its paragraph above it (every direct `captionAt` test with two lines), is read as before. Both rules hold; no test was changed for this.
3. **R6b "holds only for body text directly above…" (extended-data).** C P12-49's O4 keys a running head by its normalised words (`headKey`), and `isFurniture` reads a plain `Set` by the words alone; the test built its Set with the old key `"<height / 6>:<words>"`. **Fix: the test was re-aimed**, no code (see below).
4. **R14a "(a) lists both… sizes both…" and 5. "withFigureSizes sizes a caption labelled Extended Data by its token".** C P12-61's `measurePdfFigures` took `fig: number` and built `"Figure N"`; C P12-56's sizing passes the token `ed1`, which the batch measurer read as `"Figure ed1"` and never sized. **Fix (code):** one `figureLabelOf(fig: number | string)` (a number is "Figure N", `ed<N>` is "Extended Data Fig. N", any other string names nothing) serves `measurePdfFigure` and `measurePdfFigures`; the batch target is `{ page, fig: number | string }`; `withFigureSizes` no longer casts the token to `number` (the follow-up C P12-56 flagged).
6. **Item 6 (ruling §1h.443).** `isDropCap`'s second arm took any capitalised row in the body's face at 1.8 times the body for a drop cap — every large title or heading set in the body's face. **Fix (code):** `lineOf` records on a row headed by a drop cap `PdfLine.cap = { rest }` (it opens with a large mark of one or two characters, every other run is under 1/1.8 of it and not raised or lowered; `rest` is the largest of the other runs' sizes). `isDropCap`: size at least 1.8 × the body and the row is one or two letters alone, **or** it carries `cap`, the words beside the cap are body-sized (`rest` within 1.25 × the body), the face is the body's and it starts with a capital. A row set large as a whole carries no `cap`.
7. **Item 7 (ruling §1h.444).** `openingStart` took a line for prose only when its tallest run was the body's size, so a first line that opens with a 40 pt drop cap failed and the opening began one or two lines late; the cap was also split from its word ("S econdary") because the page leaves the cap's padding between the runs. **Fix (code):** a line is body-sized when its tallest run is, or when `isDropCap` holds and the size most of its characters are set in (C P12-64's `titleSize`) is the body's; `lineOf` joins the cap to the run after it when that run follows within a quarter of the cap's size and continues the word in lower case or in capitals (`CAP_CONTINUES`). A capital beside a capitalised word ("A" + "Results") stays two.
