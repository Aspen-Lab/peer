## 2. Rule 1 — the cause, measured (owner's paper, real upload, light; numbers only)

**It is not `content-visibility`** (the source holds none) **and not the sticky panel of P10-04b.** It is the paper's own figures: `Figure` in `paper-body.tsx` draws a plain `<img loading="lazy" … class="h-auto max-h-[32rem] …">` with no height until the picture arrives. The paper has 10 such pictures; the page is 28,204 px tall before any has loaded and 33,186 px after (+4,982 px). A map row's link is a plain hash link with `html { scroll-behavior: smooth }`: the browser aims at the heading's position at the moment of the click, scrolls to it in ~0.8 s, and the pictures above the heading, requested as the page scrolls past them, arrive between ~0.3 s and 3.5 s after the click (the dev server's figure route is slow on first use) and push the heading down. Chrome's scroll anchoring did not follow it (heading still 2,000–5,000 px below the window's foot after 5 s).

The heading's document top (row 4, "2.3", from scroll 0, 1440 × 1000, head): 12,592 px at 0 / 100 / 300 / 1,000 ms; 13,104 at 2,000 ms; final 15,147 (window y 2,635 after the page stopped at scrollY 12,512). What grew, in the runs above row 13 / 9 / 4: img0 … img9 each 0 → 512 px (481, 507, 409 for four of them), i.e. sections 0, 2, 3, 4, 5, 6 grew by 510–1,020 px each (section 0: 3,183 → 3,695; section 2: 5,170 → 6,194; section 4: 2,318 → 2,830). Measured on a fresh page for every click, which is why A's "from ~800 on it lands" (a page where an earlier click had already loaded the pictures) differs from this.

**Before P10-04b** (`5683a6ae`, port 4035, 1440 × 1000, scrolls 0 / 300 / 700 / 2,000 / 5,000 × rows 4, 9, 13, window 3.5 s): the same growth (the same sections by the same 512 / 1,024 px, the same images 0 → 512) and 13 of 15 clicks ended at y 80 — because on that cold server the pictures mostly had not arrived inside the 3.5 s window (`images changed: none` in those runs); the 2 that missed (592) were the runs where they had. So the mechanism is the same on the base; P10-04b is not the cause. (Not a controlled before / after of picture latency; the head's own 30 runs below are.)

## 3. Rules 2 and 3 — as built

1. **The root cause removed where cheap** — `paper-body.tsx`, `Figure` (a new exported `figureMatClass(waiting)` just above it and the function body, ~lines 563–617): a picture that is not on the page yet keeps the room of the largest picture there can be — the mat gets `min-h-[calc(32rem+1.5rem)] sm:min-h-[calc(32rem+2rem)]` (the img's `max-h-[32rem]` plus the mat's `p-3` / `sm:p-4`) until `onLoad`. The state is set from a stable ref callback on the `<img>` (`!img.complete`), **not in the first render**, so the server markup and the first client render are byte-identical to the head (the two exact-markup tests, `paper-body.test.tsx` and `paper-body.plain.test.tsx`, pass unchanged; the lint rule `react-hooks/set-state-in-effect` rules out the effect form). The page is now 33,324 px tall from the first paint (it was 28,204); a picture shorter than its room (409 / 481 / 507 of 512) shrinks the page by up to ~140 px when it arrives.
2. **The landing settles** — `evidence-quote.tsx`: `settleOnSection(find, env)` and the new `followSectionLink` 5th parameter (`settle`, default `settleOnSection`). After a row's (or a "§Heading" link's) click, on a frame loop: once the heading's top has held still for three frames (and has moved, or 120 ms have passed) it calls `scrollIntoView({ block: "start", behavior: "instant" })` — the heading's own `scroll-mt-20` places it at y 80 — and keeps watching until 1 s after the page first came to rest, scrolling again whenever the layout moved the heading and it rested again. A picture that arrives after that (a slow host) restarts the 1 s watch by frames (`load` / `error` captured on the document), for up to 10 s from the first rest. The reader's own wheel / touch / key / press ends it at once; a second press replaces the first; nothing runs outside a browser (the default env is null in node). Both paths use it: the heading on the page (the browser's hash jump, untouched, then the settle) and the body under the other tab (the `reveal` job's smooth scroll, then the settle).
3. **Nothing else changes**: the rows, tints, the tabs' reveal, the panel, `reading-map.tsx`, `reader-layout.tsx`, `spread.ts` — untouched; `followSectionLink`'s old three-and-four-argument calls and their five tests are unchanged and pass as written.
