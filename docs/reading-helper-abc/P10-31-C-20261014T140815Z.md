Reproduced on the head (`esc-head.out`, 1280 x 800, the explain window open):

- **B** the question bar focused, text typed, its suggestions open: the first Escape closed the WINDOW and left the suggestions open (the box's listener ran on the document in the capture phase, before the field's React handler, and stopped the key; the second Escape closed the suggestions).
- **C** the Keyboard-shortcuts sheet open over the window: the first Escape closed the window and left the sheet open.
- The figure lightbox (not reachable from the invented PDF — it has no figure) is the third: its own listener is also on the document in capture, registered after the box's; `stopPropagation` does not stop another listener of the same node, so one press closed both.

**The order, written down:** (1) a modal dialog over the page (the lightbox, the Keyboard-shortcuts sheet; both `aria-modal="true"`, the explain window never is — P9-20) takes Escape and the window stays; (2) an open control takes it — the question bar's suggestions, a note editor's menu, an export menu, a sticky or the notes window with the focus in it (each a React handler that stops the key) — and the window stays; (3) with none of those open, Escape clears the passage and closes the window and goes no further (P10-08); the next Escape is the page's. A key already handled (`defaultPrevented`) is left alone.

**Fix** (`explain-box.tsx`, the Escape listener only): the listener is on the document in the bubble phase (after every capture listener and every React handler; still before the window's "back"), returns on `event.defaultPrevented`, and returns while `document.querySelector(MODAL_OVER_PAGE)` finds an open modal dialog. `explain-dock.ts` gains `MODAL_OVER_PAGE = '[aria-modal="true"]'` (the selector lives there because a surviving test pins the box's source against the literal `aria-modal=`; no test touched). After the fix (`esc-fixed.out`): A as before; B the first Escape closes the suggestions and the window stays, the second closes the window; C the first closes the sheet and the window stays, the second closes the window.

Tests (`explain-box.escape.flow.test.tsx`, describe "Escape's order when something else is open", 8; 6 red on the head): the lightbox (one Escape: it closes, the window stays, the width stays reserved; the next closes the window), the question bar's suggestions, a sticky's / the notes window's handler, the sheet (through the DOM mark), a handled key, nothing else open (green on the head: pins P10-08), the bubble phase read from the source, the two sources carry the mark and the explain window does not.
