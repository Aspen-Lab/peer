## What changed

### `web/src/store/reading-questions.ts` (§1g.11 a)

- `PaperQuestions` gains an optional `settled?: string[]`, persisted with the rest.
  - An entry saved before it existed has no `settled` and reads as none through the new `settledQuestions(entry)`.
  - `settledQuestions` returns one shared empty list, so the page passes a stable value.
- New store action `settle(paperId)`:
  - copies `cleanQuestions(items)` into `settled`;
  - is a no-op for a paper with no entry, and for an unchanged set (it returns the same state).
- `set` carries `settled` over from the previous entry and never changes it.
- `clear`, and `set` forgetting an emptied paper, remove the entry, `settled` included.
- I made `settled` optional, not required, so the existing store assertions on exact entry shapes stay unchanged. "An old entry without it reads as `[]`" holds through `settledQuestions`.

### `web/src/components/reader/question-field.tsx` (§1g.11 a)

- New pure `settlesQuestions(event)`. It is true for `enter`, `blur` and `remove`, and false for `change`, `gist` and `chip`.
- The field calls `settle(paperId)` after the commit at those three sites: Enter, a line's blur, and a removal.
  - It is not called on typing, on the gist toggle, or on a chip.
  - A chip that leaves the caret in its line settles when the reader leaves that line.
- P1-07's line tracker was renamed from `settle` to `trackLine`, so the two do not read alike. It behaves the same.
- The live tints and the vague hint still read `items`.

### `web/src/components/reader/use-model-report.ts` (§1g.11 b)

- `buildReportKey(paper, depth, project, provider, questions = [])` appends `|q:<djb2(sorted.join("\n"))>` only when at least one question exists.
  - The hash is the same djb2 the key already uses for the project.
  - Without questions the key is byte-identical to before, so every cached report stays valid.
- `useModelReport({ paper, profile, questions })`:
  - The questions are read through a ref, like `paper`.
  - The request effect stays keyed on `reportKey`, so a change in the settled set means a new request; the in-flight one is aborted as before. An earlier set comes back from the client cache.
  - The request body carries `questions` only when non-empty. It is the body of a POST (NDJSON stream or the JSON fallback), never a URL.

### `web/src/app/papers/[id]/page.tsx`

- The `asked` subscription moved above the `useModelReport` call, which now gets `questions: settledQuestions(asked)`.
- That means the settled items only, never the gist (§1f.11): the gist is a flag, not an item.
- The route memo still reads `asked` (the live `items`), as before.

### `web/src/app/api/papers/report/route.ts` (§1g.11 d)

- New non-exported `requestQuestions(value)`. It accepts an array of strings, each trimmed, non-empty, cut to 200 characters, de-duplicated case-insensitively, at most 5.
  - Anything else gives `[]`, never a 400.
  - It is not exported because a Next route file may export only its handlers and config.
- `handlePost` cleans `body.questions` once, right after the paper check, for both transports.
- Both deep calls, the NDJSON stream and the JSON path, pass `questions: body.questions` to `generateDeepReport`.
- The shallow path never reads them: `buildShallowPrompt` builds its prompt from paper, context hint and project only.
- **Log audit:** I read every `console.*` the route reaches with a body present.
  - "dropped N claim(s)" logs the paper id and a count.
  - Shallow refused or failed, figure pool failed, and streaming flow failed log the error or reason, with no body.
  - None prints the body or the questions. `generateDeepReport` logs no question (P2-01/P2-02).
  - `src/proxy.ts` has no logging. The dev server's request line shows method and path only, and the questions are never in a URL.
