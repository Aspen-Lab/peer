### `web/src/lib/papers/reading-map.ts` (new)
Types: `ReadingRole`, `ReadingMapParagraph`, `ReadingMapSection`, `ReadingMap`, following §3c.

`roleOf(canonical)` (§1f.2):
- introduction, related_work → `setup`
- methods → `method`
- results → `evidence`
- discussion, conclusion, limitations → `interpretation`
- references, acknowledgments, supplementary → `apparatus`
- anything else → `body`

Words and minutes (§1f.3):
- `words` is the sum of `paragraph.split(/\s+/).length` over the section's paragraphs.
- `minutes` is `Math.ceil(words / 180)`, at least 1 when words > 0. A section that holds only an equation gets 0 minutes.
- `totalMinutes` is `Math.ceil(totalWords / 180)`.

`openingOf(paragraph)` (§1f.4):
- Takes the first `splitSentences` sentence that is at least 40 characters long and not `isBoilerplate`; otherwise `null`.
- Above 160 characters, the sentence is cut at the last whitespace at index ≤ 160 and trimmed, with nothing appended.
- If a single unbroken run of 160+ characters leaves no such whitespace, it is cut hard at 160. This case is not in the ruling; the result is still a verbatim substring.

`buildReadingMap(doc)` iterates `readableSections`:
- `id` is `section.id`. For a document read before ids existed, it falls back to `s<index in doc.sections>`, which is exactly what `withSectionIds` would have assigned. This fallback is not in the ruling.
- `page` is included only when the section has one.
- Each paragraph line is `{ index, opening }`.

No model, no fetch, no `node:` import. Its imports are only `./reading`, `./skim` and a type from `./html-text`, and `reading.ts` already runs in the browser.
