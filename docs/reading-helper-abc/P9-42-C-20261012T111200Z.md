## 2. The rule as built (§1h.67)

1. **`buildReading(paper, fullText, now = new Date(), options: { figuresFrom?: string } = {})`.** `options.figuresFrom` is the id the figure pictures are drawn from; the call is `placeFigures(…, doc.source === "pdf" ? { paperId: options.figuresFrom || paper.id } : null)`. The default is the paper's own id, so every existing caller (all take two or three arguments) is unchanged. `||`, not `??`: an empty string falls back to the paper's id rather than writing `/api/papers//figure-image`. The reading is still the paper's: `paperId`, the provenance, the abstract and every other field are as they were; only the pictures' URL moved (test: the reading with the option equals the reading without it once the `imageUrl`s are blanked). A body that did not come from a PDF gets no picture URL with the option set, as without it.
2. **The `?upload=` supplement branch** passes `{ figuresFrom: supplement }`. `supplement` is the query value that `bareUploadId` accepted, so it is exactly the canonical `upload:<hash16>`, the same string the branch already hands `getFullText` (the text the captions and pages come from). Every picture URL of that reading is therefore `/api/papers/upload%3A<hash16>/figure-image?page=P&fig=N`; P9-29's route answers it to its owner only, `private, no-store` (a browser with no capability cookie, or another reader, gets a private 404). The reply's own headers (`PRIVATE_UPLOAD_HEADERS`), the 404 for an upload not attached to this paper, and the 410 after a revision change are untouched.
3. **Nothing else changes.** The plain public branch and an upload's own reading (`/reading` of `upload:<hash>`) call `buildReading` as before and write the same bytes (tests below pin both). **`PaperReading.version` is not bumped** (stays 10, the manager's bump of this round).

## 7. For the manager

1. **No version bump, as ordered.** The URL of a supplement reading changes (`openalex%3A…` → `upload%3A…`); the head's reading 10 (your bump) already makes a client refetch a stored reading of an older version (`?v=10`), and a supplement reading is `private, no-store` anyway, so no edge copy holds the old URL.
2. **Cost of the correct source.** An upload's figure picture is `no-store` by P9-29's rule, so each view of a supplement reading re-draws every figure it scrolls past (P9-29 §7.4: a short per-owner cache would remove that; not done, per-user state). Before this item a supplement reading's pictures were public-cacheable but could be the wrong version's.
3. **What this does not change** (not mine, noted while reading the route): the supplement branch waits on `getFullText({ paperId: supplement })` with no `FULL_TEXT_TIMEOUT_MS` race, unlike the other two branches. It is pre-existing and untouched.
4. **One thing it relies on.** `figuresFrom: supplement` is canonical because `bareUploadId` accepted it two lines above (`^upload:[0-9a-f]{16}$`); a change of that rule to accept other spellings would need the route to pass `uploadId(hash)` instead. Said here, not guarded by a test of its own (the `UPLOAD:…` supplement is already pinned 404 by the existing P0-05 test).
