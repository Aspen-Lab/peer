## Upload suppression and account are separate conditions

Home uses `uploadsReady(useUploadsAvailable())` (`web/src/app/page.tsx:95,325`). The hook starts unknown, renders only after a successful response with `enabled: true`, and fails closed for non-2xx, malformed or failed requests (`web/src/lib/papers/use-uploads-available.ts:36-62`). `GET /api/papers/upload-availability` returns only the server predicate (`web/src/app/api/papers/upload-availability/route.ts:18-21`). P12-24 recorded an ordinary local production response 200, enabled false and no control (P12-24 report:158). Thus, assuming the observed build matches this source as its report states, this response establishes the predicate was false at that moment; it does not reveal which subcondition failed. The separate deployed anonymous missing control has no recorded predicate response here and its served revision remains unknown.

In production or Vercel the predicate requires the explicit `PEER_UPLOADS_ENABLED=true` and either configured private Supabase upload storage or an absolute external directory outside the app (`web/src/lib/papers/upload-access.ts:17-27`). Bucket configuration requires bucket, Supabase URL, and service-role configuration (`web/src/lib/papers/upload-backend.ts:110-118`); predicate success is configuration presence, not proof the storage is healthy. No values were inspected. The same control on a public paper is also suppressed for an upload ID (`web/src/app/papers/[id]/page.tsx:683-685,1407`). Availability is not an authentication test: ticket POST first checks same origin, availability (503), then production owner (401), size and storage (`web/src/app/api/papers/upload/ticket/route.ts:26-45`; `upload-access.ts:30-42`). PDF validity, 25 MB limit, rights consent and possible match confirmation apply in the normal UI (`web/src/components/briefing/upload-button.tsx:155-203,295-302`). This investigation was not authorized to accept consent or upload a file.

Browser auth requires public Supabase configuration (`web/src/lib/supabase/client.ts:7-27`). Profile Account is hidden when unconfigured/loading; signed-out users see GitHub and Google buttons (`web/src/components/account/account-section.tsx:153-183`); OAuth redirects to `/auth/callback` (`web/src/components/account/use-auth-user.ts:63-90`). Production ownership requires the actual authenticated user (`upload-access.ts:32-42`). A missing sign-in control could be unconfigured or still loading; a working account, provider, callback and session must be established through normal UI, not inferred from source. Preview's observed SSO is a distinct deployment access restriction, not proof of application auth state.

## 503, retrieval and figures are different failures

The P12-24 local-production feed requests returned 503 (report:158), but the cited summary does not provide their response bodies. `requireAiRequest` returns 503 when deployed auth configuration is absent (`web/src/lib/security/ai-request.ts:11-24,96-112`); feed can also return 503 `ledger_unavailable` for ledger failure (`web/src/app/api/feed/route.ts:74-87,277-281,321-331,389-390,764`). Status alone cannot distinguish these causes. If auth configuration exists but user is signed out, the feed explicitly permits anonymous Tier 0 (`feed/route.ts:667-675`; `ai-request.ts:124-135,190-196`). Missing deployed auth configuration fails earlier even for that anonymous path. Search upstream failure is 502, not the feed 503. No evidence identifies an observed 503 as figure binding.

Public deterministic reading initially renders an abstract-only `buildReading` and fetches a server reading, falling back to cached/client reading if it fails (`web/src/components/reader/use-reading.ts:100-118,142-170`). The server attempts full text for up to eight seconds and falls back to abstract without caching on timeout/throw (`web/src/app/api/papers/[id]/reading/route.ts:17-22,31-50,116-123`). Full text, figures and scientific completeness are not guaranteed by entry. The model report and figure resolver have separate production sign-in/rate gates (`web/src/app/api/papers/report/route.ts:593-610`; `web/src/app/api/figure/route.ts:63-80`); no-provider report uses Tier 0 only after that gate (`report/route.ts:385-395,619-631`). Figure pool and report binding occur separately (`report/route.ts:473-478,509-522`), so feed 503, reader fallback, extraction, binding and click delivery are distinct. P12-24's public B action errors are retained observations, not a proven binding cause.
