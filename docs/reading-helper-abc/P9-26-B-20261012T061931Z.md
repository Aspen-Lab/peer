# P9-26 — B: stopping the jobs and events features — what is left of them, and the smallest change that stops all of it

Role B (investigator, read-only on production code). Source read: `origin/deep-report-reading-helper-enhancement` at `4295f45f` (detached worktree `scratchpad/p9b26/wt`; only this file is added). Nothing under `/home/user/peer` changed. No model call, no network, no key value (environment variable **names** only). Probes — an import graph over all 849 `.ts`/`.tsx` files under `web/src`, a reachability walk from every route / page / layout / `proxy.ts`, a scratch copy with the dead modules deleted that was type-checked and run through the whole suite, and one scoring probe — live under `scratchpad/p9b26/probe*`; none touches the worktree's `src`.

The owner's decision (§1a.18 (f)): "职位和活动的信息不应该被process，这两个功能（职位，活动）需要被停止".

## 0. The answer in one paragraph

**Nothing in the running app fetches, sends to a model, scores, caches or shows a job or event listing today.** The routes (`/api/events/*`, `/api/jobs/feed`, `/api/jobs/report`), the pages (`/events`, `/jobs`, `/jobs/[id]`), the cards, the Adzuna / USAJobs connectors and the Events / Jobs topic lists were removed on 2026-09-05 by `ffa6eded` ("remove events and jobs — Peer is a paper briefing"); its message ends: *"Not yet removed: lib/events, lib/jobs, lib/opportunities … the event/job fields remain on UserProfile, the feed store, /api/profile and the Supabase schema. That extraction is a separate change."* This item is that change. What is left is of two kinds. **(1) 110 dead files, 37,844 lines** (jobs 33, events 18, opportunities 59; 1,879 tests) — 7 job sources + 4 event sources on 10 hosts, two pipelines, the prompts — that no route, page, layout or the proxy can reach (reachability walk: of the 60 non-test files in `lib/jobs`, `lib/events`, `lib/opportunities`, only eight are reachable — the two `types.ts` and six shared files — and none of the eight is a source client or a pipeline). **(2) Live vestiges that still store, sync, copy or advertise job/event information**: the feed store's saved-event / saved-job state and 11 actions, persisted in `localStorage` and pushed to and pulled from Supabase (`saved_items`, `feedback_events`, kind `event` / `job`) at sign-in; two API routes that accept those kinds; the profile's event / job topic lists (mirrored from the paper topics in `/welcome`) and credential fields; the ledger's event / job origin entries; and copy — `/welcome`'s "Turn on Events & Jobs for your field" step and the AI-setup text "Papers, Events, and Jobs" and its cost basis "15 events, and 15 jobs". **The three `app/api/jobs/*` routes are cron jobs; none touches a job or an event; leave all three** (the upload purge is the privacy promise). **Stopping needs nothing in `lib/scoring/`** (one comment-only coupling and two test-only ones, §2). Recommendation (§5): one way — cut the live vestiges and delete the dead modules, no flag — as five Cs: **C1** client store + sync + the two kind routes, **C2** profile + `/welcome`, **C4** delete the dead modules, **C5** docs + an owner-run SQL file run in parallel; **C3** (shared types, ledger, facets, pool-cache) follows because it deletes definitions C1 and C2 stop calling; **C2b** (Profile page + AI-setup copy) waits for P9-24, which owns those files. What the owner must do: nothing to stop it — no cron to turn off, no variable to remove (the build already refuses the job-source names); only, if the manager rules to delete the stored rows, run one SQL file in Supabase.
