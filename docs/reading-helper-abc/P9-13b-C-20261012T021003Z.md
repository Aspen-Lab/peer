## 2. What the page stores, which is not what the brief described

Reading the real runs (a probe over `readPages`, scratch) changed two of the mechanisms; the rules below follow the data.

- **The space in `R3̅ m` is a run the PDF stores, not a gap past the threshold.** Behind the overbar run (U+0305, width 0, in the accents' face) comes a run holding `" "` in the *same face*, 0 to 0.05 pt wide, and the next digit starts 0.08–0.41 pt on, far under the 1.8 pt the gap rule needs. `lineOf` wrote that stored space as text. Both the stored run and (for the brief's 2 pt fixture) the gap rule had to be dealt with.
- **The space in `I0 (hkl)` is inside the subscript's own run.** The page stores `I`, then a lowered run `"0 ("`, a lowered `hkl`, a lowered `)`: the whole `0 (hkl)` is one subscript, typed with a space. There is no "following run that opens with `(`" at the line's size.
- **The `f` labels are raised (+3.9 pt), in six runs** (`0`, `−`, `4`, a stored space, `μ`, `m `), behind a stored 0.15 pt space run after the `f` when there is one; the label starts 1.37–1.52 pt after that run's end. The brief's "gap under 1.5 pt" misses the 1.52 ones (one of the five `8-15` labels) by 0.02; the threshold is 0.2 em (2 pt at 10 pt).

## 3. The rules, as built

**1. Combining marks** (`lineOf`; `COMBINING_RUN`, `COMBINING_TAIL`, `MARK_REACH_EM = 0.5`). A run made only of U+0300–U+036F / U+20D0–U+20FF is a mark.
- No gap space is put before it.
- The space run the PDF stores behind it, in the mark's own face (`fontName` equal), is dropped, wherever the next glyph starts.
- If the mark stands on a digit, a bracket or a sign (the last non-mark character before it is not a letter), the run after it follows with no space when it starts within 0.5 em of where the mark's run ends, whatever the 0.18 em gap rule would say. Beyond half an em it is a word break and keeps its space.
- If the mark stands on a letter (`x̄`, an accent) the gap rule is read as it always was, the stored space of the mark's face apart: `Jose` + acute + a word 2.5 pt on stays two words. Stacked marks (`4` + U+0305 U+0332) and the arrow block work the same way.

**2. A label after a one-letter variable** (`rowsOf` records the scripts under the baseline in `Row.lowered`, beside `raised`, by `SUBSCRIPT_FALL = 1`; `lineOf` takes the set as a fifth parameter; `openLabel`, `SYMBOL_LABEL`, `WORD_LABEL`, `RANGE_LABEL`, `LABEL_TOUCH_EM = 0.2`). The variable is the last run written with text in it, and its trimmed text is exactly one letter, itself neither raised nor lowered. The label is a lowered group (consecutive lowered runs, a stored space among them) or a raised group of the shape number + space + unit (`0−4 μm`, `8-15 μm`). It touches the variable when its first text run starts under 0.2 em after the end of the last run written, a stored space run counted.
- A symbol — letters and digits, one to three of them (`RCT`, `TH`, `Eg`, `Dw`, `I0`, `N2`, `MLi`, `jmax`, `xij`) — stays joined, as today.
- Anything else with a letter in it and no parenthesis is bracketed, with the trailing space of the last run kept after the bracket: `f(area)`, `j/j(limiting)`, `f(0-4 μm)`, `K(alpha)`. The stored space before it is dropped, so the output no longer depends on whether the PDF stored one.
- `on`, `off`, `in`, `out` are bracketed although they are short, as joined they read as a word: `t(on)`, `t(off)`.
- Left as today: a lowered run after a word of two or more letters (`Lix`), after a digit, a label a word space away from its variable, a raised exponent of any kind (`cm²`, `MPa m1/2`, `xn`), a raised group such as `Cod2+` (no space in it), a label with no letter.

**3. The subscript's parenthesis** (`lineOf`). Inside a lowered group no space stands before `(`: the space inside a lowered run's own string (`"0 ("` → `0(`), and the gap or stored space before a lowered run that opens with `(`, are dropped. `I0 (hkl)` → `I0(hkl)`. `RATIO_GROUP` takes one bracketed label inside, so `(j/j(limiting))²` keeps its exponent the way `(i/imax)²` did (P9-08); without that the exponent was dropped as a citation, as `(j/jmax)²` was in the first version of this commit.

**Where I read the brief narrowly or differently, and why**
1. *Letters-only up to three characters joined* against *`t(on)` / `t(off)`*: the brief's rule and its examples disagree (`on` and `off` are two and three letters). I kept the examples and the rule, and added the four short words. `jmax`, `xij`, `Teff` join; the bracketed form for `max` made `(j/jmax)²` into `(j/j(max))` and cost the exponent.
2. *Rule 3 after a raised run, or before a parenthesis at the line's size*: not done. After an exponent it would print `cm⁻²(at C/10)`; after a subscript, `Eg(eV)`, `RCT(Ω)`; both are far commoner in the paper than `I0 (hkl)`. Rule 3 is the lowered group's own.
3. *Marks "on either side, whatever the gap"*: bounded at half an em after a mark on a digit, bracket or sign, and not applied after a letter, where an accent ends a word as often as an index. All twelve places of the paper are 0.1–0.4 pt.
4. *Single-letter variable run*: kept as a run test, not a text-tail test. P9-08's test "a raised run with a letter, a unit, a point or a slash in it stays exactly as the PDF has it" holds a raised `0−4 μm` after a run that merely ends in `f` ("the label f") and pins it plain; it stays green, untouched.
