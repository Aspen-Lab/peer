## Where `notice` / `paywallNotice` render, and why there is no double notice

- There is no `notice` field on `PaperReport`. The field that exists is `paywallNotice`, which the server sets on a report (`report.ts:192`; the route's paywalled, no-full-text and failed-deep-read branches; `buildPaywalledFallback`). **No component and no file under `app/papers` reads it.** I grepped `src` for the word: it appears only in `report.ts`, `deep-report.ts`, the report route and their tests. It renders nowhere on this page today.
- The page's own prose about why a report is abstract-tier is the Decision block's availability sentence (`describeAvailability` in `reading.ts`, fed from the report's provenance and `deepRequested`). It says what Peer read, not why a cap said no.
- A report that carries a `deep_report` / `breaker` quota cannot also carry `paywallNotice`, by construction: a refused decision sends the stream down the tier-1 branch (`aiMode === "tier1"`, straight to `generateShallowReport`) and the JSON branch to `{ ...shallow, quota }`; `paywallNotice` is set only inside the deep branch, which a refused decision never enters. The one report that can carry both is a `company_budget` refusal on the shallow fallback after a failed deep read, and that report is `emptyReport` (`noLlm: true`), which `reportOutcome` never shows (see observation 3).
- So the condition "no other notice for the same report already renders there" holds, and the mount needs no extra gate on it. Rather than leave that as a claim, `quota-notice.test.tsx` pins it: it reads every non-test `.ts`/`.tsx` under `src/components` and `src/app/papers` (more than 50 files; the test asserts the count) and fails if any mentions `paywallNotice`. The day something renders it, that test goes red and the double-notice question has to be answered then. (The mount's own comment avoids the word, since the test would catch it.)

## Observations (noticed, not changed)

1. **The Decision block and the notice can both explain the same shorter report.** For a refused deep read with the full text available and deep requested, `fullTextClause` (`reading.ts`) says "Caveats and a next step need the full text; your model's deep read of it did not finish." and the notice under it says "Deep reports are used up for now. This is the shorter report." They do not contradict each other, but "did not finish" implies it started. `reading.ts` is outside this item; a manager decision whether the availability sentence should know about `report.quota`.
2. **A cached report carries its quota.** `writeCached` stores the whole report, including `quota`, so a revisit within the abstract-tier TTL (6 h) shows the notice from the cache even if the allowance has since come back. The line is still true of that cached report ("this is the shorter report"), but "for now" may be stale. Not changed (the hook is outside this item).
3. **The `companyBudget` line is built and tested but not reachable on today's route.** Every report that carries a `company_budget` quota is `emptyReport("fallback")` with `noLlm: true`, which `reportOutcome` turns into "no model layer" or "failed", never into a shown report; and on the stream, `finish()` sends that quota after `mode`, where the hook's post-mode `quota` branch settles `report: null` and returns before the report arrives. So a reader who hits the shared budget gets no notice today. The `exhausted` and `unavailable` lines are reachable (quota first, then tier 1, the shallow model report, with `quotaFirst` carried onto it; or JSON `{ ...shallow, quota }`). Making the company-budget line reachable needs the hook to carry a quota on a null report, a design question for the manager, in a file outside this item's list.
4. **`mt-6` is a guess.** The brief gave the classes and not the spacing; the answers block below it starts with `mt-12`. Easy to change after the Chromium look.
5. **The quota line sits first in `additions` on the spread, not literally under the Decision block**, which lives in the left panel there; that is the slot the brief and §1g.14 name (and what P2-04's order test pins).
