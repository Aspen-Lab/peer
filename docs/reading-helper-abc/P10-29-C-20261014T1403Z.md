## Rule 1 — one block, two editors, no lost words: built as a merge, by block

A write carries its source: the sticky's writer holds the text it last saw stored (`makeStickyWriter(...).sync`, taken again from the store whenever it changes with no keystroke of its own waiting, and after its own write) and passes it as `base` to `setStickyText(noteId, headerId, text, base)`. When the stored text is no longer that base (the notes window wrote into the same blocks meanwhile), the store merges instead of replacing: `mergeText(base, mine, theirs)` — each side's change is the span of words it touched; spans apart both stay; both only adding words at one place both stay (stored first, a space where words would run together); the same text both arrived at stays once; where both rewrote the same words the later write stands (the writer's own for the sticky, the outside one for the window, as before). Paragraphs are blocks: when base, mine and theirs keep the same paragraphs each is merged on its own, so the later edit wins only for that block and edits to different blocks both stay. The window's `mergeBlocks` (its reconcile when the stored blocks change under an editor holding unsaved typing) merges a block both changed with the same `mergeText` (kind and marks: the side that changed them). **Why a merge and not "show the newer text":** both words survive without the second editor having to restart mid-word in the common case; the fallback (the newer text, the window's editor restarting on the merge at once) is left only to a true rewrite of the same words, where one side must lose. Not built: a per-block revision counter (it would need `Block` in `lib/notes/types.ts`, not mine); the base text is the revision, compared by value.

## Rule 2 — an empty sticky goes

`removeEmptySticky(noteId, headerId)` is a store action (`withoutSticky` moved into the store, re-exported from the sticky module; `closeSticky` uses the action). `removeEmptyStickies(paperId)` writes what is typed in each open sticky (registry `registerStickyWriter`), then removes the ones with no words with their anchors; `StickyNotes` runs it on `pagehide` and when it unmounts (route change), ahead of the effect that closes the cards. A sticky with any words stays. The heading is remembered for the tab, so a stale copy saved afterwards (the notes window's flush as the page is left) cannot bring the empty sticky back (`save` takes a remembered empty heading out of a copy again, never one with words by then). Not a reload-lasting tombstone.
