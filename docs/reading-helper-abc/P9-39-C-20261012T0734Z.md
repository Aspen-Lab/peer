## 2. The rules, as built

**What was wrong.** The test held alpha "in flight" with `net.delayMs = 200` and typed beta and gamma between `sleep(50)`s of wall-clock time. "Alpha is still in flight while beta and gamma settle" was true only while the machine ran the script faster than the delay. On a loaded one alpha finished first, beta was free to go out, and `named` was `[null, "alpha", "beta", "gamma"]` (BACKLOG-47: 1 of 3 alone at a load of ~28; P9-04, P9-19, P9-22, P9-14 each saw it once). The component is not suspected, and nothing in it was changed.

**Rule 1 — a request can be held by hand (the `net` fake).** `net.hold` (default `false`) and `net.gates` (an array). With `hold` off the stream waits `net.delayMs` as before, so every other test is byte-for-byte on its old path. With it on, the request takes no time of its own: it registers `net.gates[n]` (its position in `net.calls`) and stays in flight until something calls the gate. `beforeEach` resets both.

**Rule 2 — the script waits for what it brought about, not for the clock (the `session` helper).** A new step, `until(what, condition)`: the session polls (1 ms timer, one render round per poll) until the condition holds, then runs the next step. Two helpers sit on it: `inFlight(n)` (request n has gone out and is held) and `release(n)` (lets request n's report arrive; it throws "request n is not in flight, so it cannot be released" if the gate is not there). A condition that never holds throws "never reached within 50 rounds: <what>" instead of hanging until the 5 s test timeout. The 50 is a count of render rounds, not a time: what the script waits for is a chain of promises, and one round drains every promise, so the condition holds within a few rounds on any machine. It is a valve that fails loudly, not the fix. `sleep` and its `{ wait }` step are untouched; the six other tests still use `sleep` and the 30 ms delay.

**Rule 3 — the test, re-aimed in how it waits only.** Same name, same three assertions (`named` equals `[null, "alpha", "gamma"]`; no call aborted; three cached keys), same comments on what they mean. The script is now:

`inFlight(0)`, `release(0)`, `until("the open's report cached", 1 key)` — the open goes out, is let go and caches before any question is asked; `type alpha`, `submit`, `inFlight(1)` — alpha is sent and held; `type beta`, `submit`, `type gamma`, `submit` — two more sets settle while alpha is held, so nothing is free to send either; `release(1)`, `inFlight(2)`, `release(2)` — alpha finishes, the one more request goes out for gamma, and finishes. The session then ends when nothing is dirty and nothing pending (the runtime's own rule), not after `sleep(900)`.
