## How the keyboard layer treats a missing handler

I read `components/keyboard.tsx` and wrote a test for it.

- On a paper page, `runReaderKey("x")` resolves to `skip` and finds no registered handler. It returns false without `preventDefault`.
- The paper-page branch is an `else if` after the briefing's card keys, so the briefing's own `x` (dismiss the focused card) does not run there.
- The global `switch` has no `x` case.

Result: `x` on an upload's page does nothing. It is not prevented and not swallowed, and the browser default for a plain letter key on the page body is also nothing.

The new layer test asserts this:
- with only `next` registered, `x` calls nothing and is not prevented;
- with `skip` registered, `x` calls it once and is prevented.
