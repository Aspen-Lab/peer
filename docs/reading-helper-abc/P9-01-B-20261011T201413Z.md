## 2. Cluster A — raised glyphs become a line of their own

### 2.1 The mechanism, with the three suspects the brief named

The fold exists and works: `rowsOf` (l.366–392) sends every run set below 0.75 of the page's usual height (`SCRIPT_RATIO`, l.303) to the nearest row within `-SCRIPT_DROP`…`+SCRIPT_RISE` (−3.5…+7.5 pt, l.306–308) and flags it `raised` when it sits more than 1 pt above (l.387). It is not (a) a missing base glyph, (b) a baseline difference beyond the tolerance, nor (c) the order of rows. It is this, l.375:

```ts
if (text > 0 && item.height < text * SCRIPT_RATIO && item.str.trim()) scripts.push(item);
else place(item);
```

`item.str.trim()` is false for the space the PDF stores after a citation or an exponent — and this PDF stores it as a run of its own, 6.7 pt high, at the script's own baseline. That run is "base": `place` (l.369) finds no row within `LINE_TOLERANCE` (2.2 pt, l.95) because a superscript sits 3.5–4.5 pt above its text row, so it opens a **phantom row at the script's baseline**. The script then asks for its nearest row: the phantom is at distance 0, the real text row at 4.4, so the phantom wins (l.383) and, at distance 0, `raised` is not even set. Subscripts never tear because they drop about 2.0 pt, inside `LINE_TOLERANCE`: their space run joins the text row (the `R`+`CT` of "resistance RCT" is one row).

Then `linesOfRow` makes the phantom row a `PdfLine` of its own (size 6.7, x = the script's x, mid-line), rows sort by y so it stands *above* its text line, and `joinProse` l.789 (`line.x > left + 6`) reads its x as an indent: the paragraph breaks, and the cite is hoisted in front of the line it belongs to ("10−15 disconnections …"). Raised-only lines of only 1–4 digits do not break anything: `isFurniture` (l.667, `FOLIO` l.169) drops them as folios (l.901) — which also silently deletes **three exponents** ("7 mA/cm (Figure" in three places).

It is not about line starts: every torn line's x is mid-line (261.9, 240.4, 99.2 …); the digits stand after the word they cite.

### 2.3 Which direction, and does x-overlap matter?

In page order a superscript's text row is the one *below* it (script y above row y by up to 7.5 pt); a subscript's is the one *above* (script below by up to 3.5 pt) — already what the window does. Do not decide from meaning: in this PDF the labels typeset as subscripts of f (`0−4 μm`) and the "Cod" of D(Co) sit **+3.9 pt above** their line, i.e. geometrically raised. x-overlap is only a tie-break for leading ≤ 11 pt (the two windows overlap by `11 − leading`; this paper's 9 pt pages have leading 9.9); nearest-by-distance already picks the right row, so no x test is needed.

### 2.4 The fix (a dozen lines in `rowsOf`, the old behaviour kept for small print)

A script — a whitespace-only run set small included — joins the nearest **text** row in its window; only a script with no text row near it (a footer, a note, a table in small type) is read as before, so footers, captions and the owner printout are unchanged.

```ts
// rowsOf — first pass: full-size runs only (drop `&& item.str.trim()` from l.375)
const baseRows = rows.slice();
const ownerOf = (s: PdfTextItem, rs: Row[]) => { let best: Row | undefined;
  for (const r of rs) { const rise = s.y - r.y; if (rise < -SCRIPT_DROP || rise > SCRIPT_RISE) continue;
    if (!best || Math.abs(rise) < Math.abs(s.y - best.y)) best = r; } return best; };
const fold = (s: PdfTextItem, r: Row) => { r.items.push(s); if (s.y - r.y > SUPERSCRIPT_RISE) (r.raised ??= new Set()).add(s); };
const loose: PdfTextItem[] = [];
for (const s of scripts) { const r = ownerOf(s, baseRows); if (r) fold(s, r); else loose.push(s); }
for (const s of loose) if (!s.str.trim()) place(s);                       // small print, as before
for (const s of loose) if (s.str.trim()) { const r = ownerOf(s, rows); if (r) fold(s, r); else place(s); }
```
(The simpler form — just drop `&& item.str.trim()` — passes the same checks but changes the footers' row grouping by arrival order; the form above is the conservative one and is what `v1` measures.)

## 3. Cluster B — citation numbers fused into words

### 3.1 Mechanism

`lineOf` (l.406–447) drops a raised run when `CITATION_MARK` fits (l.334) **and** the text before it matches `CITED` (l.340: `[.,;)\]]` or `[A-Za-z]{3,}` at the end). Everything else is "an exponent" and stays glued. The decisions on this paper (185 raised runs, logged with the prototype; `out/raised-log.txt`):

| Output today | Row | Why `CITED` says exponent |
|---|---|---|
| `crystal morphology-2 (crystal size` | text run ends `morphology-`, raised `2 ` (h 6.67, +4.42, x 209.2 = the run's end) | ends in `-`: a suspended hyphen ("morphology- … and interface-dependent") |
| `intra-5,6 and intercrystal` | `intra-` + raised `5,6 ` | same |
| `of Li30 and Zn` | `…of Li` + raised `30`; later `and Zn` + `24` | two letters: read as a unit (`cm`), but Li and Zn are elements |
| `NaCoO235`, `Bi2Te352` | inline `NaCoO2` / `Bi2Te3` (one run, the 2 and 3 have no geometry) + raised `35 ` / `52 ` | the text ends in a digit: read as "10" + exponent |
| `"decrepitation"16` (created by fix A) | `…decrepitation”` + raised `16` | the closing quote is not in the set |
| `basal a-b plane 003` | **not a citation**: one run `plane {003} and the slowest` (the plane family in braces) | `normalizeLatex` strips every brace (`clean.ts` l.145) — outside this item, see §7 |

### 3.2 The rule

A raised run is a **citation** when it is digits joined by comma, dash or space (`/^\d+(?:[\s,–−-]+\d+)*$/`, at most 12 characters) and what precedes it is a letter-bound mark: punctuation or a closing bracket or quote, a suspended hyphen, a word of three letters or more, a capitalised pair (an element symbol), or a formula that already ends in digits. It is an **exponent** otherwise: after a digit, a one-letter variable (`R2`), one or two lower-case letters (a unit: `cm`, `mm`, `s`), or when it carries its own sign (`−13`, `4−`, `2+`).

```ts
const CITATION_MARK = /^\d+(?:[\s,–−-]+\d+)*$/;      // "12", "5,6", "10−15", "89 91"; never "4−" (a charge) or "−13"
const CITED = /(?:[.,;:!?)\]”’"']|\p{L}-|\p{L}{3,}|\p{Lu}\p{Ll}|[\p{L})]\d+)$/u;
//            punctuation, bracket, quote | suspended hyphen | word ≥ 3 letters | element (Li, Zn) | formula ending in digits
```
Cases (all measured): drop — `morphology-`+2, `intra-`+5,6, `”`+16, `Li`+30, `Zn`+24, `NaCoO2`+35, `Bi2Te3`+52, plus every case of the existing P7-11 table. Keep — `cm`+2, `mA/cm`+2, `R`+2, `10`+12, `cm`+`−1`, `Co(OH)6`+`4−`, `[Co`+`2+`, `OH`+`−`, `MPam`+`1/2`, `st`/`th`. On the 185 decisions of the paper the new rule changes exactly these seven and drops 63 instead of 56 (`diff` of `raised-log*.txt`); no exponent is dropped.

The regex has one flaw to keep: the space-separated range (`"89 91"`) must stay valid — `pdf-outline.columns.test.ts` pins it (the `minimalPdf` helper cannot encode the en dash, so the test's `89–91` arrives as `89 91`); my first draft required a separator character and that test caught it.

Known limit (pre-existing, not a regression): an exponent after a closing parenthesis is dropped as a cite — `(j/jmax)2`, the Scharifker–Hills plot axis, in §2.1 and in Figure 2's caption. A rule "single digit after a space-free bracketed group containing `/`" would keep it; I left it to the manager.

## 4. Cluster G — chemistry and variable scripts

What the glyph rows actually carry (all 226 lowered runs and 122 kept raised runs of the paper logged):

- **No geometry at all**: `pH2O` (italic `p` + inline `H2O`), `TC101`, `LiCoO2`, `H2O`, `Co(OH)6`, `NaCoO2`, `A1g` mostly — the PDF sets these digits at the base height in the same run. They cannot be recovered from rows; they stay plain, whatever is chosen.
- **Raised digit/sign runs** (flagged `raised`): exponents `cm2`, `10−13`, `cm−1`, charges `Co2+`, `[OH−]`, `4−` of `Co(OH)6`, `CoO2−`, `2+` of `DCod2+`. About 64 places in 13 paragraphs. These can be written as Unicode superscripts at low risk.
- **Lowered runs**: letters — `area` of f, `limiting` of j, `CT` of R, `H` of T, `on`/`off` of t, `w` of D, `c` of K, x/y/z of `LixCoO2`. Unicode has subscript forms for only a handful of lower-case letters and none for capitals; they stay plain. 13 paragraphs keep them.
- The f labels `0−4 μm` / `4−8 μm` / `8−15 μm` and the "Cod" of D(Co) are typeset **above** the line (+3.9); converting a raised run that holds a letter or a unit would print `f ⁰⁻⁴ μm` — the prototype did exactly that until the rule was made per run.

**One rule**: a *whole* adjacent raised run whose every character is a digit or a sign (`+ − ‐ – -`) is written in Unicode superscripts (`² ³ ¹ ⁴…⁹ ⁰ ⁺ ⁻`); any run with a letter, a unit, `.` or `/` (`1/2` of `MPam1/2`) is left exactly as it is; lowered runs and inline digits are not touched. Failure cases: (1) a raised run that is semantically a subscript but a pure number (a raised label like `f 1` would become `f ¹`); (2) font coverage — the reading face is Newsreader with `subsets: ["latin"]` (`app/layout.tsx` l.51–54), which by Google's latin range holds `² ³ ¹ ⁴` but not `⁺ ⁻ ⁵–⁹ ⁰` — those fall back to the system serif (to be seen at 1440 and 390, light and dark; I could not check the font file offline); (3) find-in-page and copy: "cm2" no longer matches "cm²"; (4) the Tier 0 sentence tools (`splitSentences`, `tokenize`) see a non-ASCII character mid-token — nothing in the 1412 tests failed with it, 7 tests assert the plain form (below).

```ts
// lineOf — in the kept-run branch (after `judged = end - 1`), l.428:
if (mark && [...mark].every((c) => c in SUP)) superUntil = end - 1;            // whole run: digits and signs only
text += raised?.has(item) && i <= superUntil ? toSuper(item.str) : item.str;    // SUP: 0-9 + − - – → ⁰¹²³⁴⁵⁶⁷⁸⁹⁺⁻
```
Prototype `v4` converts 64 places on the paper and none of the f labels (`out/v4-hits.txt`).

**It only works with a PDF-flavoured clean** (§5). If G ships first without it, `normalize()` writes plain digits again and nothing is gained; tests that would then be **re-aimed** (all in `pdf-outline.test.ts`, red on `v4`): "folds an exponent into its line the same way, and keeps it (P7-11)"; "folds a subscript too" (only if lowered digits are converted — the manager may leave subscripts alone, then this stays); "keeps an exponent: a script after a digit, or after a one- or two-letter unit, stays glued"; "keeps a negative exponent after a long unit …"; "keeps a negative exponent the PDF stored as two raised runs …"; "leaves a subscript, an ordinal and a mark that is not a citation number where they are"; "keeps a number at the head of a line …" (the head-of-line raised `1` would become `¹`; guard it: no conversion at the start of a line). Recommendation: **A + B first, G after D's clean option lands**, by itself; letters stay plain.

Spacing of a lowered label is gap-dependent: `f 0-4 μm` (a 0.15 pt space run between f and the label) beside `f4-8 μm` (none). A rule "no space before a script that starts within 2 pt of its base's end" makes it `f4-8 μm` everywhere; optional.

## 5. The shared gate: `cleanDisplayText` in `normalize()` (cross-cluster)

`pdf-text.ts` l.168 `text: cleanDisplayText(section.text)` runs a function written for HTML and titles. On PDF text it (measured, `out/probe5.txt`):

- flattens Unicode scripts: `.normalize("NFKC")` (`clean.ts` l.154) and the two maps (l.173–174);
- folds `° ± × ≤ ≥ µ` to ` degrees`, `+/-`, `x`, `<=`, `>=`, `micro` (l.167–172), and every dash and the minus sign to `-` (l.157) — cluster D, P9-02;
- strips every `{` `}` (l.145) — the paper's plane families `{110} ≫ {101} > {104} ≫ {003}` print as `110 ≫ 101 > 104 ≫ 003` (about 26 lines carry braces);
- joins a capital letter, spaces and a digit (l.196, `([A-Z])\s+(\d)(?=\b|[A-Z),.:;])`) — cluster H below.

**One change serves A/B/G/H and D together**: give `cleanDisplayText` an option (e.g. `{ pdf: true }`, off by default so HTML and the sources are untouched) that keeps symbols, scripts and braces and skips the capital+digit join, and pass it from `normalize()` (l.166–168, 179–180, 189, 193). It belongs to the same C as D; G's Unicode piece lands after it. Existing tests: `lib/text/clean.test.ts` has two (U+2044); none pins any of these rules.

## 6. Cluster H — spaces at line joins

### 6.1 Two sites, opposite errors

`joinProse` (l.794–796):
```ts
if (!current) current = line.text;
else if (/[‐-―-]$/.test(current)) current = `${current.slice(0, -1)}${line.text}`;   // l.795: U+2010–2015 and "-" : the mark is dropped, no space
else current = `${current} ${line.text}`;                                              // l.796: everything else gets a space
```
- A line that ends in `/` ("mA/" | "cm2", "[Li+]/" | "[Co2+]", "C/" | "10", "(mg/" | "cm2/h)", "60°/" | "[0001]", "EC/" | "EMC") gets a space.
- A line that ends in **U+2212** (this PDF's range and compound mark; it is not in the class of l.795) gets one: `20−` | `30` → "20− 30", `4.68−` | `12.50`, `15−` | `25`, and `LiOH−` | `KOH melt`. `cleanDisplayText` then turns the minus into `-` and the space stays: "20- 30".
- The same line-end mark as ASCII `-` or en dash (U+2013, which some PDFs use for ranges) is *removed* by l.795: `20–` | `30` → "2030" (probe: `out/probe13.txt`). It does not occur in this paper, so it has never been seen; it silently corrupts a number.

`A3D` and `A0.25 mm` are not join errors: the line text is `A 3D instantaneous` and `A 0.25 mm diameter` (spaces present, `lines-p5.txt`, `lines-p15.txt`). They are removed by `normalizeChemistryAndOperators` (`clean.ts` l.196) in `normalize()`. It fires twice on this paper, both times wrongly (`Type A 2.5 mm`, `Figure S 1` would be hit the same way). "demonstratea a lower" is in the PDF's own text layer (one 240-pt run, `'demonstratea a lower number …'`) — not an extractor error and not fixable from rows.

### 6.2 The rule

A line ending in `/` (not ` /`), in U+2212, or in a hyphen/en dash/em dash *after a digit* with a digit starting the next line, joins with **no space and the mark kept**; every other line end joins with a space; a line-end hyphen after a letter is cluster C's decision (P9-02).
