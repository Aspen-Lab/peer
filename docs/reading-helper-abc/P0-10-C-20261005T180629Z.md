## Can private text still reach a URL for an upload?

For a standalone upload (`itemId` = `upload:<h>`): no.
- `SectionFigure` (`report-sections.tsx`), the page's plate caption (`page.tsx:726`) and `paper-plate.tsx` all call `useResolvedFigure` with the upload id. That is now a POST to `/api/figure` with no query string.
- The body carries `id`, `v`, `url` (`/api/papers/upload/<hash>/file`, the hash only), `query`, `idx` and `rev`. The title is not sent.
- If a GET for an upload ever carries `query` or `paperTitle`, it gets 400 before anything runs.
- Other upload URLs carry only the id or hash: the reading route path, `/api/papers/upload/<hash>`, and `/file`.

## Open question (not done; needs a contract ruling)

For an attached PDF (a public paper with a private supplement), the figure request still carries Peer's report text about the private PDF in a GET URL:
